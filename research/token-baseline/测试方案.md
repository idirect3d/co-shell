# FEATURE-577 Token 用量测试方案（各阶段基线测量）

- 分支：**FEATURE-577**　版本：**v0.87.0**　BUILD：**1173**（基线采集时）

- 目的：建立**可重复、可对比**的 token 用量测量口径，测量优化前**各阶段**基线用量，供后续 A/B/C/D1 优化实现后做同口径对比。
- 关联：`research/token优化设计方案.md`（方案）、`research/token-baseline/基线方案.md`（上一轮仅覆盖 env 信封一项，本轮取代/扩展之）

## 1. 阶段划分（S0–S6，已确认冻结）

| 阶段 | 名称 | 含义 | 主要测量通道 |
|---|---|---|---|
| **S0** | 系统提示词 | 每个请求固定携带的 system 消息（RULES/身份/CAPABILITIES/SKILLS/模式策略/工具用法说明） | ① 确定性 + ② 运行时 |
| **S1** | 工具声明 | `tool_call_mode=openai` 下每轮全量发送的工具 JSON schema（含重复的 `meta` 参数说明） | ① 确定性 + ② 运行时 |
| **S2** | 单份 env 信封 | `<environment_details>` 单份体积及分项（current_dir / tools / research / board_agents / runtime_info / task_plan / opened_resources / …） | ① 确定性 + ② 运行时 |
| **S3** | 同轮多工具 env 重复 | 同一轮 N 个工具结果各注入一份完整 env 造成的重复量 | ① 确定性 |
| **S4** | N 轮历史累积 | 历史消息中 env 逐条累积形成的上下文增长曲线（斜率 B/轮） | ① 确定性 + ② 运行时 |
| **S5** | 单轮请求合成总量 | 单次 LLM 请求的完整载荷 = S0 + S1 + 历史消息(含各轮 env) + 本轮 tool result | ① 确定性 + ② 运行时 |
| **S6** | 真实会话端到端 | 真实模型的逐轮 `prompt/completion` token、缓存命中、触发上下文重整的轮次 | ② 运行时 |

**口径定义（贯穿全部阶段）**

- 长度单位：**字节（B）**，同时给出**估算 token**（按 3.7 B/token，见 §6 局限）。
- 运行时 token：**以模型返回的 usage 为准**（`prompt_tokens` / `completion_tokens` / `cached_tokens` / `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`）。
- 所有对比必须同一工作区口径、同一 config 快照、同一任务脚本。

## 2. 两条测量通道

### 通道①：确定性测量（0 API 成本、可重复）

- 工具：新增 Go 测试 `agent/token_baseline_test.go` → `TestTokenBaselineStages`，**直调产品代码**：
  - S0：`a.RebuildSystemPrompt()` 后取 `a.systemPrompt`（构件函数 `buildSystemPromptWithMode`）；
  - S1：`a.buildToolsInternal()` → `json.Marshal`（不经网络；与运行时同一构造路径）；
  - S2：`a.buildFullEnvironmentDetails(1, [...] )`（L0），L1/L2 按设计方案定义的字段集重建；
  - S3：模拟一轮 N=1..5 个工具结果，累加 env（现状 N×L0 vs B 方案 L0+(N-1)×L2）；
  - S4：按「每轮新增 1 条带 env 的消息」累加 12/50 轮，输出累积与斜率；
  - S5：S0+S1+历史+S2 求和，输出第 1/10/50 轮合成量与固定开销占比。
- 输出：**固定格式行**（无时间戳/随机值），便于 3 次运行取 md5 校验一致性。
- 复现：
  ```bash
  go test ./agent -run TestTokenBaselineStages -v -count=1 2>&1 | tee research/token-baseline/det-run-1.log
  # 重复 3 次 → det-run-1.log / det-run-2.log / det-run-3.log，三者 md5 必须一致
  ```

### 通道②：运行时测量（真实 LLM，非确定性，按次数重复）

- 数据源：`log/llm-interaction-<date>.log`，逐次调用记录 `[REQ]`（完整 messages + tools）与 `[RES]`（usage）。
  - 实测字段：`prompt_tokens`、`completion_tokens`、`total_tokens`、`cached_tokens`、`prompt_cache_hit_tokens`、`prompt_cache_miss_tokens`、`reasoning_tokens`。
- 运行方式：**非交互** 且**独立工作区/独立会话**，避免污染既有会话与工作区：
  ```bash
  ./work/co-shell-0.87.0.darwin.arm64 run --workdir <固定工作区> --prompt "$(cat research/token-baseline/fixed-task.txt)"
  ```
- 归属方式：记录起止时间戳（`run-N.meta`），按时间窗口从日志切出本次运行的全部调用。
- 解析工具：`research/token-baseline/parse_llm_log.py`
  ```bash
  python3 research/token-baseline/parse_llm_log.py \
      --log log/llm-interaction-2026-10-02.log \
      --from "2026-10-02 02:30:00" --to "2026-10-02 02:45:00" \
      --out research/token-baseline/run-1
  ```
  产出：`run-1.calls.csv`（逐轮：轮次/时间/prompt/completion/cached/hit/miss/tools 字节/system 字节/messages 条数/env 条数）
  与 `run-1.summary.txt`（累计、斜率、缓存命中率、轮数）。
- 固定工作区：`research/token-baseline/s6-workspace/`（脚本一次性生成：12 个文本文件 + 2 个子目录），保证 S2 的目录类块稳定可比。
- 固定任务：`research/token-baseline/fixed-task.txt`，要求**12 步、每步单独一次 `read_file` 调用、最后 `attempt_completion` 汇总**（避免合并调用导致轮数不足）。
- 重复次数：**3 次**（run-1/2/3），比较轮数一致性与每轮 token 曲线。

## 6. 已知局限（必须随报告一并声明）

1. 估算 token 用固定换算（3.7 B/token，英文为主）；中文占比高的文本会低估 token 数，故**字节为准、token 为参考**。
2. 通道①使用测试构造的 Agent，`browser/excel/word/mcp` 等运行时条件组可能未激活，故 S1 的绝对工具数可能少于生产实例（生产实测 62 个工具）；对比时以**同一构造路径的前后差值**为准，另在报告中记录生产工具数（`grep -c 'Callback: ' agent/tools.go`）作为参照。
3. 通道②的 `s6-workspace/` 为合成工作区，其 `current_dir/tools/research` 块与真实仓库不同，故 S6 只用于**前后相对对比**，不作为生产绝对值。
4. LLM 行为非确定：轮数/工具选择可能波动，故要求 3 次重复并记录轮数一致性；若单次轮数 < 10，需重跑该次。
5. 缓存命中率受服务端前缀缓存策略影响，跨时间可能漂移；对比时应记录 `prompt_cache_hit_tokens` 而非仅看 prompt 总量。
