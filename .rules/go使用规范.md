# go使用规范

## 技术栈
- 语言: Go 1.25+
- 存储: bbolt（本地 KV，默认 `db/co-shell.db`）+ 可选 PostgreSQL

## 编码规范

### 通用规则
- 所有错误必须显式处理，不允许使用 `_` 忽略错误
- 函数参数超过 3 个时使用结构体或 Option 模式
- 使用 `context.Context` 作为第一个参数传递超时和取消信号
- 所有导出函数必须有 GoDoc 注释
- 单个程序文件原则上不应超过500行，超过后应想办法将其中的方法分类整理到其他文件中。

### 命名规范
- 包名使用小写单数形式（如 `config`、`store`）
- 接口名使用 `-er` 后缀（如 `Client`、`Handler`）
- 私有方法使用驼峰命名
- 常量使用驼峰命名（Go 风格，非全大写）

### 并发安全
- MCP Manager 使用 `sync.RWMutex` 保护共享状态
- Agent 循环使用 `context.Context` 控制超时
- 所有可关闭资源实现 `Close() error` 方法

### 测试要求
- 测试文件放在同目录下，命名 `*_test.go`
- 使用 table-driven tests 模式
- 关键逻辑（Agent Loop、命令解析）必须有单元测试
- 集成/真实依赖测试用 `testing.Short()` 门控，常规 `go test ./...` 默认跳过
- 收尾必须跑 `go vet ./... && go test ./... && go build -o work/co-shell .`（检查 + 编译可执行码，输出到 work/）

## 依赖管理
- 不要随意修改 go.mod 中的依赖版本
- 新增依赖需评估必要性，优先使用标准库，高度审慎引入第三方库
- 绝对禁止引入个人的、来源不明的或已经过时的第三方库
- 尽全力降低对第三方库的依赖
- 避免引入重量级框架（如 gin、cobra）
- 当前允许的例外：`gorilla/websocket`、`jackc/pgx/v5` / `lib/pq`、`go.etcd.io/bbolt`、`mark3labs/mcp-go`、`larksuite/oapi-sdk-go/v3`、`golang.org/x/crypto`

## 安全约束
- 系统命令执行设置超时应可配置（默认 -1 秒，表示无限等待）
- API Key 等敏感信息显示时需脱敏（显示前 4 位 + **** + 后 4 位）
- 所有文件操作需先确认再执行
- MCP Server 命令执行需验证参数合法性

## 安全编码规范

### 注入防护
- **SQL 注入**：所有数据库访问必须使用参数化查询（pgx 的 `$1`/`$2` 占位符或 `QueryRow`/`Exec` 参数绑定），**严禁**用字符串拼接或 `fmt.Sprintf` 拼 SQL；bbolt 键值访问同样禁止拼接不可信输入作为 key
- **命令注入**：执行系统命令时优先使用 `exec.Command` 的参数数组形式（不经过 shell），避免 `sh -c` + 字符串拼接；对命令参数做合法性校验
- **路径穿越**：所有文件/路径操作必须校验解析后的绝对路径落在允许的根目录（如 workspace）内，禁止直接使用用户提供的相对路径或含 `..` 的路径

### 跨站攻击防护（Web UI）
- **XSS**：所有输出到 HTML 的内容必须转义（`html/template` 自动转义，或手动 `html.EscapeString`），禁止将用户/LLM 输入直接作为 HTML 注入
- **CSRF**：涉及状态变更的请求需校验来源（同源检查 / CSRF Token），WebSocket 连接需校验 Origin
- **CSP**：为 Web UI 设置合理的 Content-Security-Policy，限制脚本/样式来源，降低 XSS 影响面

### 前端信息暴露防护
- **前端 IP 地址暴露**：禁止在前端页面、JS、静态资源中硬编码内网 IP、服务器地址、端口等敏感信息；需要展示时由后端按需下发并脱敏
- **前端源码泄露**：web 静态资源以 embed 单二进制打包，禁止把 API Key、口令、数据库连接串、内部接口地址等敏感信息写入前端代码或静态资源；前端只保留展示所需的最小信息
- **错误信息泄露**：对外（Web/API/桥接）返回错误时只给通用提示，不暴露内部堆栈、文件路径、SQL、依赖版本等实现细节；详细错误仅写日志

### 第三方组件（含开源）审慎引入
- 新增依赖前评估必要性，优先标准库；引入第三方库必须来源可信、维护活跃、无已知高危漏洞
- 锁定版本（go.mod 精确版本），不随意升级；升级前检查变更与漏洞公告
- 定期用 `govulncheck ./...` 扫描依赖漏洞，发现高危漏洞及时升级或替换
- 禁止引入个人、来源不明、已过时或维护停滞的第三方库

### 敏感信息与日志安全
- API Key、口令、Token 等敏感信息：显示时脱敏（前 4 位 + **** + 后 4 位），存储时加密/哈希（口令用 bcrypt）
- 日志中禁止记录明文 API Key、口令、Token、完整数据库连接串；确需记录时脱敏
- 敏感配置（config.json 等）注意文件权限，避免被其他用户读取

### 权限与最小暴露
- 遵循最小权限原则：服务只监听必要端口（Web 默认 loopback），不暴露不必要的接口
- 所有外部输入（用户输入、HTTP 参数、WebSocket 消息、桥接请求）必须做校验与边界检查
- 可关闭资源（DB、WebSocket、文件句柄）必须实现 `Close()` 并确保释放，防止资源耗尽

## 语言偏好
- 代码注释使用英文
- 变量命名使用英文
- 所有提示信息和给LLM的提示词**必须支持多语言**
