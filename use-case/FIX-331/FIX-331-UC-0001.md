# FIX-331: XML 工具调用流式解析跨 chunk 边界前缀破坏修复

## 背景

用户实际运行 co-shell（对话 co-flow 项目）时观察到 LLM 工具调用流式渲染输出异常：

```
...图标颜色的定义。⚙️ read_file
   end_line:    intent: :    , :    : :    , : start_line1

⚙️ search_files
   path: /Users/direct3d/projects/co-flow/web/static/css
   regex: 
[⚙️ ]< read_file
```

症状：
1. 工具名 `⚙️ read_file` 没有正常换行，直接粘在普通文本句末
2. read_file 参数完全错乱：`end_line:` / `intent:` 后无值、键值交叉、`,` 与 `:` 被当文本输出、`start_line1` 键值粘连
3. search_files 只渲染出 `path`，`regex:` 值为空
4. 末尾出现 `[⚙️ ]< read_file` 残渣——工具调用文本被当普通内容渲染

## 根因

`agent/toolcall_parser_xml.go` 的 `XMLToolCallParser.Feed` 在 `xmlStateOutside` 状态处理 `<` 时存在 chunk 边界缺陷：

当 LLM 流式输出把工具标签 `<cs:read_file>` 拆分到两个 chunk（例如第一个 chunk 以 `<` 或 `<c` 或 `<cs:` 结尾）时：

- `i+1 < len(content) && strings.HasPrefix(content[i+1:], p.prefix)` 检查失败（前缀不完整）
- `i+2 < len(content)` 检查失败（close-tag 也不完整）
- `<` 被当作**普通文本**输出（`OpPlainText`），且**不会**缓存到 `p.partial`

下一 chunk 的 `cs:read_file>` 因不以 `<` 开头而完全不匹配标签识别逻辑，整个片段被当作普通文本输出。工具调用 XML 结构被跨 chunk 边界破坏：
- 工具名识别失败 → 参数被误认为工具级标签 → 触发 `unknown tool tag <path>` 类错误或参数渲染错乱
- 一部分工具调用文本泄漏到普通内容渲染（`[⚙️ ]< read_file` 残渣）
- 参数渲染混乱（键值交叉、符号残留）

## 修复方案

`agent/toolcall_parser_xml.go` 的 `xmlStateOutside` 分支，在 `<` 认定为字面文本之前增加两个缓存判断：

1. **开标签前缀部分匹配**：`strings.HasPrefix(p.prefix, content[i+1:])`——当 `<` 之后的剩余内容是标签前缀的前缀（含空串：`"<"`、`"<c"`、`"<cs"`、`"<cs:"`）时，把整段 `content[i:]` 缓存到 `p.partial`，留待下一 chunk 续上后再重新扫描
2. **闭标签前缀部分匹配**：`content[i+1] == '/' && strings.HasPrefix(p.prefix, content[i+2:])`——当 `</` 之后是前缀的部分前缀（`"</"`、`"</c"`、`"</cs"`）时同样缓存

普通文本（如 `a < b`、`</div>` 等不以前缀开头的 `<`）不匹配前缀，保持原有字面输出路径，不受影响。

## 用例列表

### UC-0001 `<` 单独成 chunk 边界（单测）
**前置条件**：`NewXMLToolCallParser(toolcallTestTools())`。
**步骤**：chunks = `["<", "cs:write_to_file>", "<cs:path>a.go</cs:path>", "</cs:write_to_file>"]`。
**预期**：渲染 `⚙️ write_to_file` 工具头 + `   path: a.go` 参数，无 `<` 泄漏。

### UC-0002 前缀片段跨 chunk 边界（单测）
**前置条件**：同 UC-0001。
**步骤**：chunks = `["<c", "s:write_to_file>", "<cs:path>a.go</cs:path>", "</cs:write_to_file>"]`。
**预期**：工具头与 path 参数正常渲染。

### UC-0003 普通文本 `<` 不受影响（回归）
**前置条件**：同 UC-0001。
**步骤**：Feed `"a < b"` / `"</div>"` 等非前缀 `<`。
**预期**：按普通文本输出（OpPlainText），不缓存 partial。
