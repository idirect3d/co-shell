# FIX-330: 系统命令交互卡死修复与 OpenAI 模式工具示例清理

## 背景

### 问题 1：系统命令需要用户输入时卡死、无回显

enhanced（raw terminal）输入模式下，`REPL.handleAgentInput` 启动时 `EnhancedIO.startRaw()` 将终端置于 raw mode（关闭 `ECHO`/`ICRNL`/`ICANON`/`ISIG`），且整个 `RunStream` 期间持续保持。当 agent 执行需要用户输入的系统命令（如 `sudo`、`passwd`）时，子进程通过 `cmd.Stdin = os.Stdin` 读输入，但此时：
- `ECHO` 关闭 → 输入无回显
- `ICRNL` 关闭 → 回车产生 `\r` 而非 `\n`，行读取程序等不到换行
- `ICANON` 关闭 → 无行缓冲
- `ISIG` 关闭 → Ctrl+C 失效

表现为"卡死、输入无效、无回显"。既有 FIX-209 仅解决 ESC monitor 与子进程竞争 stdin 的问题，未解决 raw mode 本身。

### 问题 2：OpenAI 模式系统提示词包含工具调用示例

`KeySystemPromptToolUsageExamples` 资源在 `en_system.go` 中包含 5 个 JSON 格式工具调用示例。OpenAI 模式下工具定义已通过 API `tools` 参数提供，无需在系统提示词中重复举例，示例内容占用上下文且无必要。zh_system.go 中该 key 原本为空。

## 修复方案

### 改动 1：Agent 新增 CommandHooks 机制（agent/loop.go）
- 新增 `CommandHooks` 结构体：`BeforeCommand func()` / `AfterCommand func()`。
- `Agent` 新增 `commandHooks CommandHooks` 字段。
- 新增 `SetCommandHooks(hooks CommandHooks)` / `onCommandStart()` / `onCommandEnd()` 方法。
- 钩子在线程安全保护下取用（持锁复制函数指针后解锁调用），允许钩子内部安全回调 agent。

### 改动 2：命令执行点触发钩子（agent/command_tools.go）
- `executeSystemCommand`（LLM 工具路径）与 `ExecuteCommandDirectly`（REPL 直接命令路径）：
  - 命令启动前调用 `onCommandStart()`（恢复 cooked mode）
  - `cmd.Start()` 失败分支调用 `onCommandEnd()`
  - `cmd.Wait()` 返回后、释放进程资源前调用 `onCommandEnd()`（重进 raw mode）

### 改动 3：REPL 注册钩子（repl/repl.go）
- `handleAgentInput` enhanced 模式 `startRaw()` 成功后注册钩子：
  - `BeforeCommand` → `eio.stopRaw()`（恢复 cooked mode）
  - `AfterCommand` → `eio.startRaw()`（重进 raw mode，失败记录 warn）
- `RunStream` 返回后先 `SetCommandHooks(agent.CommandHooks{})` 清除钩子再 `stopRaw()`，避免残留钩子误触发。
- stdio 模式不注册（终端本就在 cooked mode，不受影响）。

### 改动 4：清空 OpenAI 模式工具示例（i18n/zh_system.go + i18n/en_system.go）
- `KeySystemPromptToolUsageExamples` 在 zh/en 中均赋值为空字符串 `""`。
- `i18n.T()` 对"key 存在但值为空"返回 `""`（合法的"无内容"值，`i18n.go` T() 注释中已明确此设计），OpenAI 模式 ToolExamples 节将输出为空，不污染系统提示词。

## 用例列表

### UC-0001 CommandHooks BeforeCommand/AfterCommand 被调用（单测）
**前置条件**：构造 Agent，注册 CommandHooks（before/after 各置计数标志）。
**步骤**：调用 `onCommandStart()` 再调用 `onCommandEnd()`。
**预期**：before 与 after 计数均为 1。

### UC-0002 未注册钩子时 onCommandStart/onCommandEnd 不 panic（单测）
**前置条件**：Agent 未注册任何 CommandHooks。
**步骤**：调用 `onCommandStart()` / `onCommandEnd()`。
**预期**：无 panic、无副作用。

### UC-0003 钩子内部可安全回调 agent（单测）
**前置条件**：构造 Agent，BeforeCommand 钩子内部调用 `a.IsCommandRunning()`。
**步骤**：`a.SetCommandRunning(true)` 后调用 `onCommandStart()`。
**预期**：钩子执行成功无死锁（锁内取函数指针、锁外调用设计）。

### UC-0004 i18n 空资源行为（断言测试）
**前置条件**：i18n 已初始化。
**步骤**：断言 `i18n.T(i18n.KeySystemPromptToolUsageExamples) == ""`（zh 与 en 语言下均成立）。
**预期**：返回空字符串，而非 key 名字符串。

### UC-0005 运行时交互命令可用（运行时）
**前置条件**：enhanced 输入模式，shell-session-enabled=off。
**步骤**：在 REPL 中执行需要用户输入的交互命令（如 `sudo -v` 或 `read -p "input: " x; echo $x`）。
**预期**：输入有回显、回车正常提交、Ctrl+C 可中断，命令完成后 REPL 恢复正常 raw mode 交互。

### UC-0006 编译三平台（构建）
**前置条件**：源码修改完成，`go build ./...` 通过。
**步骤**：执行 cc 规则参数 `3` 编译 darwin/arm64、windows/amd64、linux/arm64。
**预期**：三个平台产物输出到 work/ 目录（co-shell-darwin-arm64 / co-shell-windows-amd64.exe / co-shell-linux-arm64）。
