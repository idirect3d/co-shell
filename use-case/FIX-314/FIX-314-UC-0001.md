# FIX-314: OpenAI 模式 parse-error-action=retry 时方法调用及错误结果不应进入上下文

## 现象

OpenAI 模式下，LLM 返回的 tool_call 参数 JSON 解析错误或缺少必填参数时，`executeToolCall` 返回错误。当 `parse-error-action=retry` 时，错误的 tool 结果消息仍被 append 进 `a.messages`，导致：
- assistant 消息（带 tool_calls）进上下文
- tool 错误结果进上下文
- 下一轮 LLM 看到错误结果，可能重复错误调用而非干净重发

## 排查结论（根因）

| 事实 | 证据 |
|---|---|
| `executeToolCall` JSON 解析失败返回 `execErr` | agent/tools.go：`json.Unmarshal` 失败 → `"cannot parse tool arguments: ..."` |
| retry 分支仅改 `result` 为错误文本 | agent/run_stream.go:1033-1035 |
| tool 错误结果无条件 append 进上下文 | agent/run_stream.go:1062-1068（OpenAI 模式 Role="tool"） |
| assistant 消息在 :967 已进上下文 | agent/run_stream.go:967 |
| `assistantMsgIdx` 已记录，取消路径已示范回滚 | agent/run_stream.go:953、:1017-1019 `a.messages = a.messages[:assistantMsgIdx]` |

**根因定论**：OpenAI 模式 `parse-error-action=retry` 时，工具执行失败的 assistant 消息和 tool 错误结果都应从上下文回滚，然后 continue 让 LLM 干净重发。当前实现未回滚。

## 修复内容

### `agent/run_stream.go`（Step 4 工具执行循环）

在 `execErr != nil` 分支的 parse-action 处理中，新增：`retry` 且 `!isXMLMode` 时——
1. 回滚 assistant 消息：`a.messages = a.messages[:assistantMsgIdx]`
2. 回滚 memory 记录（assistant 消息曾写入 memoryManager）
3. `continue` 到下一次迭代（LLM 干净重发）

XML 模式保持现状（XML 工具结果以 user 消息进入，不能整体回滚）；`exit`/`prompt` 行为不变。

## 修复效果

- OpenAI 模式 + `parse-error-action=retry`：JSON 解析错误/缺参数 → assistant(tool_calls) + tool 结果**都不进上下文** → LLM 干净重发
- `exit`/`prompt` 行为不变；XML 模式行为不变

## 用例（循环模式）

| # | 场景 | 步骤 | 预期结果 |
|---|---|---|---|
| 1 | OpenAI + retry + JSON 解析错误 | `executeToolCall` 返回 `cannot parse tool arguments`，`parseAction=retry`，`isXMLMode=false` | `a.messages` 不包含该 assistant 消息（tool_calls）+ 不包含 tool 错误结果；循环 continue 重发 |
| 2 | OpenAI + retry + 缺参数错误 | `executeToolCall` 返回缺少必填参数错误，同上 | 同上，上下文干净 |
| 3 | OpenAI + prompt | `parseAction=prompt`，`isXMLMode=false` | 保持现状：tool 错误结果进上下文（结构化反馈 formatToolError） |
| 4 | OpenAI + exit | `parseAction=exit` | 保持现状：返回错误退出循环 |
| 5 | XML + retry | `parseAction=retry`，`isXMLMode=true` | 保持现状：错误结果以 user 消息进入（不整体回滚） |
| 6 | OpenAI + retry 成功后消息完整 | 重发后工具执行成功 | assistant + tool 成功结果正常进入上下文（无丢失） |
