# FEATURE-612 UC-0001：动态感知暴露面板（任务进展栏滑动开关）

> 分支：**FEATURE-612**　版本：**v0.100.1**　BUILD：**1232**
> 现象：任务进展面板 `#plan-panel` 头部只有一条静态文案「任务进展」；Agent 这一轮到底感知到了什么（`<user_dynamic_events>`、`<user_presence>`、`<context_window>`、`<runtime_info>`、`<tools>`、`<opened_resources>` …）只注入 LLM 上下文，用户在界面上完全看不到、也无从排查。
> 判定口径：面板头部改为**内凹边框的滑动开关**（文字右侧带纵向细长扳手），默认「任务进展」；点击文字或将扳手**向左拖动**即「任务进展」左滑出、「动态信息」右滑入；动态信息视图为**严格单时间线（最新在上、不分区）**，每行左侧用彩色类型标签区分类别，时间线之下列出环境块（排除内容过多的 `current_dir`/`research`），整块共用**一根**上下滚动条；切到「动态信息」时下方面板区的「子代理」「已加载技能」隐藏。

## 背景（现状与缺口）

- 现状：`web/static/index.html` 的 `#plan-panel` 头部为 `<div class="panel-head"><span data-i18n="taskPlan">任务进展</span></div>`；`app.js` 的 `renderPlan()` 只渲染任务计划（标题/描述/验收标准/步骤），`renderSubAgents()` 与 `renderSkills()` 渲染同面板的另外两区。
- 现状：动态感知数据分布在后端 `agent/dynamic_events.go` 的 `dynamicEventQueue`（pending + retained）、`agent/envelope.go` 组装的 `<environment_details>` 各块，以及 `web/session.go` 的会话状态中；除 `dynamic_backfill`（未消费 user_message 回填）外，**没有任何**「后端 → 前端」的动态感知通道。
- 缺口：用户无法直观看到「LLM 这一轮感知到了什么」；FEATURE-611 引入的 `[unacked]` 未确认重放机制在界面上没有任何可视化，出了「事件丢了没？」「LLM 确认了没？」的问题只能翻日志。
- 本次：新增动态感知快照的 WebSocket 推送（`dyninfo`）+ 面板头部滑动开关 + 动态信息视图。

## 用例与结果

> 状态列在实施完成前为 `待验证`；`(R)` = 可自动化（单元测试/命令行复现），`(M)` = 需人工在 Web UI 验收。

### A. 面板头部滑动开关

- **UC-01（M）** 默认态：面板头部显示一枚内凹边框的开关，文字为「任务进展」，文字右侧有一根纵向细长的扳手（把手）；排版不错位、不溢出面板宽度。
- **UC-02（M）** 内凹观感：开关边框使用内阴影/凹槽效果（视觉上低于面板表面），与面板背景形成明暗对比；深色、浅色主题下均可辨认。
- **UC-03（M）** 点击文字切换：点击「任务进展」文字本体，视图切换为「动态信息」，下方面板内容同步切换。
- **UC-04（M）** 拖动扳手切换：按住扳手向左拖动并越过阈值（约半个开关宽度）后松手 → 切换为「动态信息」；未达阈值松手 → 回弹到原态、不切换。
- **UC-05（M）** 滑动动画：切换过程中「任务进展」向左滑出、「动态信息」从右侧滑入，运动连贯、无闪烁与跳变；拖动过程中扳手实时跟随指针位置。
- **UC-06（M）** 反向切回：在「动态信息」态下点击文字或将扳手向右拖 → 回到「任务进展」，动画反向且对称。
- **UC-07（M）** 点击与拖动不冲突：一次完整拖拽（越过阈值）只触发一次切换，松手后不因冒泡的 click 事件再切一次。
- **UC-08（M）** 状态持久化：切换后用同一浏览器刷新页面，开关保持上次所选视图（localStorage 记忆）。
- **UC-09（M）** 键盘可达：开关可 Tab 聚焦，Enter/空格可切换；具备 `role="switch"` / `aria-checked` 语义。
- **UC-10（M）** 窄屏抽屉：`body.narrow` 抽屉模式下开关仍正常显示与切换，且不遮挡抽屉关闭按钮。

### B. 动态信息视图 —— 时间线

- **UC-11（M）** 视图构成：切到「动态信息」后，面板主体为单一滚动容器——上部是事件时间线，下部是环境块区。
- **UC-12（M）** 严格时间倒序：时间线条目按时间严格倒序（最新在最上），不做分类分组。
- **UC-13（M）** 彩色类型标签：每行左侧有一个醒目的类型标签，不同类型颜色不同（用户动作 / 用户消息 / 公告板 / 子代理 / UI 交互 / 待确认 / 系统）。
- **UC-14（M）** 用户动作事件：上传/粘贴/预览/打开文件后，时间线出现对应条目，类型标签为「用户动作」，正文含文件名与工作区相对路径。
- **UC-15（M）** 补充消息事件：任务执行期间用户补充的消息在时间线中出现，标签为「用户消息」，正文显示消息内容。
- **UC-16（M）** 公告板事件：收到 `board_message` / `board_timeout` 时，时间线出现「公告板」标签条目。
- **UC-17（M）** 子代理事件：子代理进入完成/失败态时，时间线出现「子代理」标签条目。
- **UC-18（M）** UI 交互事件：`render_ui` 组件交互（表单提交/按钮/图表下钻）在时间线中出现，标签为「UI 交互」。
- **UC-19（M）** 待确认/未确认条目：尚未注入的事件（pending）标为「待确认」；已注入但 LLM 未 `meta.ack` 的 retained 事件标为「未确认」，两者均有醒目角标（色块/描边）。
- **UC-20（M）** 待确认计数：开关「动态信息」文字旁有计数胶囊，显示待确认 + 未确认条目数；为 0 时不显示胶囊。
- **UC-21（M）** 时间显示：每行显示可读时间（相对时间或时间戳），且与事件真实发生时间一致（重放事件保留原始时间戳）。
- **UC-22（M）** 空态：会话尚无任何动态事件时，时间线区域显示占位提示（如「暂无动态事件」），不出现空白塌陷。
- **UC-23（M）** 长文本：单条事件文本过长时自动换行/截断，不撑破面板宽度、不产生横向滚动条。
- **UC-24（M）** 单一滚动条：整个面板（时间线 + 环境块）共用一根纵向滚动条，内部不出现第二根独立滚动条。

### C. 环境块区

- **UC-25（M）** 环境块区位于时间线下方，逐块展示，块标题即标签名（如 `<runtime_info>`、`<tools>`）。
- **UC-26（M）** 环境块区**完全对齐最近一次 `<environment_details>`**：该次 envelope 里省略了的块就不显示（如 `env_runtime_info_once` 省略了 `<runtime_info>` 时不显示）；面板不自行补渲染。
- **UC-27（M）** `<current_dir>`、`<research>`、`<task_plan>` 三块**不显示**（前两者内容过多，第三者与「任务进展」视图重复）。
- **UC-28（M）** `<user_presence>` / `<context_window>` / `<current_mode>` / `<result_mode>` / `<no_tool_action>` 等小体量块正常显示当前值。
- **UC-29（M）** 体量较大的块（如 `<tools>`、`<skills>`、`<opened_resources>`）默认折叠，点击标题可展开/收起；`<tools>` 排在环境块区最下方。
- **UC-30（M）** 无 `<environment_details>` 缓存时（会话刚开始、LLM 尚未被调用），环境块区显示占位提示而不报错、不影响时间线渲染。

### D. 刷新与推送

- **UC-31（R）** 后端新增 `dyninfo` 帧：`serverMessage.Dyn` 承载 `{events:[…], env:[…], counts:{pending,unacked}}`，JSON 字段名与前端读取一致。
- **UC-32（R）** 动态事件入队后立即推送一次 `dyninfo`（时间线随之出现新条目）。
- **UC-33（R）** 工具调用完成（既有 `state`/任务进展推送处）时同步推送 `dyninfo`，保证面板与会话状态一致。
- **UC-34（R）** 浏览器连接/重连、切换会话后主动推送一次 `dyninfo`，前端不显示上一会话的陈旧数据。
- **UC-35（R）** `dyninfo` 载荷字段缺失/为空时前端按空数据渲染，不抛异常、不阻断其他消息处理。
- **UC-36（R）** 事件量超过上限（队列容量 / retained 上限）时快照只含上限内条目，不无限增长；`unacked` 标记与 `meta.ack` 后消失的行为一致。

### E. 与既有面板的关系

- **UC-37（M）** 切到「动态信息」时，面板下方的「子代理」「已加载技能」区块隐藏；切回「任务进展」后按各自原有条件恢复显示。
- **UC-38（M）** 「任务进展」视图行为与改动前完全一致（标题/描述/验收标准/步骤列表渲染不变）。
- **UC-39（M）** 顶部菜单的「任务进展」开关（`miPlan`）仍控制整个右面板的显隐，与头部视图开关互不干扰。
- **UC-40（M）** 无任务计划（plan 为 null）时切到「动态信息」仍能正常显示（不因 `planBody` 为空而隐藏整个面板或空白）。

### F. i18n 与主题

- **UC-41（M）** 中英文案完整：「任务进展」「动态信息」及各类别标签在中英两种语言下均正确显示，无缺失键。
- **UC-42（M）** 浅色主题下开关、时间线标签、环境块标题的文字对比度满足可读性要求。
