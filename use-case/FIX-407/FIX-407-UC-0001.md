# FIX-407 测试用例 — Web UI 会话切换不切换上下文

> 版本 v0.9.1 | 分支 FIX-407
> 功能：修复通过 Web UI 状态栏会话图标弹出的会话列表进行会话切换时，只切换了任务进展中的任务计划，但 `:context` 显示的上下文没有切换的问题。

## 需求规格

1. `web/session.go` 的 `WebSession.switchSession(id)` 在切换会话时，必须像 REPL `:session switch` 命令（`cmd/session.go handleSwitch`）一样，真正替换 agent 内存中的上下文（`a.messages`）。
2. 切换流程必须包含：
   - `FlushCurrentSession()`：将当前会话消息写回 DB
   - `LoadNamedSession(id)`：加载目标会话
   - `json.Unmarshal` 目标会话 Messages
   - 用当前 system prompt + 目标消息构建新 history 并 `SetHistory`
   - `SetCurrentSessionID` + `SaveCurrentSessionID`
3. 切换后 `:context` 显示目标会话的上下文，而非旧会话的上下文。

## 测试用例

### UC-0001 会话切换后上下文被替换（Go 单测）
- 准备：创建两个会话 sess-A（含消息"会话A的消息"）和 sess-B（含消息"会话B的消息"），当前在 sess-A
- 操作：发送 `session_switch` 消息切换到 sess-B
- 断言：`ag.CurrentSessionID()` 为 sess-B；`ag.Messages()` 包含"会话B的消息"且不包含"会话A的消息"
- 通过标准：`TestSessionSwitchSwitchesContext` 通过

### UC-0002 切换前当前会话消息被刷新到 DB（Go 单测）
- 准备：当前会话 sess-A 有消息，目标会话 sess-B 有消息
- 操作：发送 `session_switch` 切换到 sess-B
- 断言：sess-A 的 DB 记录包含切换前的消息（`FlushCurrentSession` 生效）
- 通过标准：`TestSessionSwitchSwitchesContext` 中验证 sess-A 已持久化

### UC-0003 切换后任务计划仍正确切换（Go 单测，回归）
- 准备：sess-A 绑定任务计划 Plan A，sess-B 绑定任务计划 Plan B
- 操作：发送 `session_switch` 切换到 sess-B
- 断言：切换后推送 task_plan 事件，任务计划为 Plan B
- 通过标准：`TestSessionSwitch` 回归通过

### UC-0004 回归：会话列表/删除/新建全量测试
- 操作：`go test ./web/ -run 'TestSession'`
- 通过标准：全部通过，无回归

## 执行方式

- UC-0001~0002：`web/session_test.go` 新增 `TestSessionSwitchSwitchesContext`，运行 `go test ./web/ -run 'TestSessionSwitch'`
- UC-0003~0004：运行 `go test ./web/ -run 'TestSession'`
- 收尾：`go build ./... && go vet ./... && go build -o work/co-shell .`
