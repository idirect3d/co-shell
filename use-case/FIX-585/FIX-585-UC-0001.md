# FIX-585-UC-0001 工具超时不再误报为“用户中断” · 代码层用例

> 分支：`FIX-585` ｜ 版本：`v0.91.1` ｜ 编号：FIX-585
> 缺陷实证（2026-10-02 本次会话）：19:01:06.513 发起 `grep -ril "splash" --include=* .`（`timeout_seconds=60`），19:02:06.514（整 60s）被杀；
> 日志依次为 `Interrupt: killing process group of PID 38070` → `tool execute_command interrupted (user)` → `Agent.RunStream: tool execute_command interrupted by user (reason=); discarded unclosed assistant message and tool results (idx=44)`。
> 关键反证：`reason=` **为空**——真实用户中断必带 `reason=web-interrupt` 等；同日 18:08:05→18:09:05 有同构记录。
> 本文覆盖**代码层（单元 / 集成）**；运行时端到端条目见 `FIX-585-UC-0002.md`，移动端条目见 `FIX-585-UC-0003.md`。

---

## 一、根因与修复判据

| # | 位置 | 现状（缺陷） | 修复后期望 |
|---|---|---|---|
| 1 | `agent/tools.go:2445-2455` | 工具超时用 `context.WithTimeout` 取消**同一个**工具 ctx（`effectiveTimeout = max(userMin, llmSuggested)`），与用户中断共用取消信号 | 不变（保留该超时模型），但下游须能区分取消原因 |
| 2 | `agent/command_tools.go:331-338`（非 detach）、`480-488`（direct） | `select { case <-ctx.Done(): }` 不分原因，统一打 `Interrupt: killing process group ...` 并返回 `newToolInterruptedError(..., "user")` | 仅当 `a.IsInterrupted()` 为真才走中断分支；否则视为**工具超时**：打 `Timeout kill: ...`、置 `timedOut`、kill 进程组，落回既有超时错误（`command timed out after Ns`），**不返回** `ErrToolInterrupted` |
| 3 | `agent/run_stream.go:1579-1596` | 见 `ErrToolInterrupted`（或工具 ctx 被取消）即按“用户中断”处理：丢弃整轮 assistant 消息与工具结果 + 发 `KeyInterruptToolNotice` + 结束本轮 | 仅当 `a.IsInterrupted()` 为真才丢弃整轮；否则按普通工具失败把错误交回 LLM（本轮上下文保留，LLM 可自行调整/重试） |

**统一判据**：`timeout`（DeadlineExceeded / 无中断标记）→ 普通工具失败，**不丢轮**；`user interrupt`（`Agent.InterruptTool` 置位）→ 保持 FEATURE-582 行为，**丢弃整轮**。

## 二、用例（A 组：代码层）

| 编号 | 名称 | 步骤 | 期望 |
|---|---|---|---|
| A-01 | 超时非中断（非 detach） | 单测：以带 deadline 的 ctx（`context.WithTimeout(..., 1s)`）调用 `execute_command` 执行 `sleep 5` | ① 返回 err ≠ nil；② `errors.Is(err, ErrToolInterrupted) == false`；③ `err.Error()` 含 `timed out`；④ `a.IsInterrupted() == false` |
| A-02 | 用户中断仍为中断（非 detach） | 单测：执行 `sleep 30`，100ms 后调用 `a.InterruptTool("web-interrupt")` | ① `errors.Is(err, ErrToolInterrupted) == true`；② `a.InterruptReason() == "web-interrupt"`；③ 进程组被终止（命令不再占用 PID） |
| A-03 | 超时非中断（direct 模式） | 单测：`ExecuteCommandDirectly` 路径 + 带 deadline 的 ctx 执行 `sleep 5` | 同 A-01（该路径同样不得返回 `ErrToolInterrupted`） |
| A-04 | ctx 取消但无中断标记 → 不丢弃整轮 | 集成：复用 `agent/interrupt_test.go` 中 `TestRunStreamInterruptDiscardsUnclosedToolCalls` 的 RunStream 夹具，令工具返回中断型错误/ctx 取消，但**不调用** `InterruptTool` | ① `a.messages` 长度不因该工具轮而减少（assistant 消息与 tool 结果保留）；② 不产生 `KeyInterruptToolNotice` 事件；③ 错误进入下一轮上下文（LLM 可见工具失败） |
| A-05 | 真实中断 → 丢弃整轮（回归 FEATURE-582） | 集成：同一夹具，工具执行中调用 `InterruptTool("web-interrupt")` | ① 未闭合的 assistant 消息与本轮 tool 结果被丢弃（与既有用例一致）；② 发出 `KeyInterruptToolNotice`；③ 本轮结束回输入态 |
| A-06 | 既有中断机制回归 | `go test ./agent/ -run 'Interrupt\|ProcRegistry' -v` | `TestErrToolInterruptedMatches`、`TestInterruptToolIdempotent`、`TestInterruptToolClearsAtTurnReset`、`TestProcRegistry*` 全绿 |
| A-07 | 编译与静态检查 | `go build ./... && go vet ./...`（一次完整执行，禁止分开） | 全绿、无新增告警 |

**日志文案的校验方式**：日志为文件输出（`log/co-shell-YYYY-MM-DD.log`），不在单测中断言；`Timeout kill: ...` / `Interrupt: ...` 的文案区分由 `FIX-585-UC-0002.md` 的运行时条目（RT-A1/RT-A2）用 `grep` 实测。

## 三、边界与不做的事（防止过度设计）

- **不改** 工具超时的取值语义（`max(userMin, llmSuggested)`）与配置项，不新增开关。
- **不改** Web 端中断按钮/ESC 的分流逻辑（`agent.IsToolRunning()`），不改前端提示文案。
- **不改** detach 模式的既有分支（`Timeout detach:` 与 Q4-B 的中断清理）。
- 工具超时仍会 kill 进程组（这是防泄漏的既有设计），只是**不再**丢弃整轮上下文。
