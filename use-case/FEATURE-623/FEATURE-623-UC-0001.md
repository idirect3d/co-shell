# FEATURE-623 UC-0001：可用工具拆分「全局 / 空间」两段并精简展示

> 分支：**FEATURE-623**　版本：**v0.106.0**　BUILD：**待定（编码后回填）**
> 需求（用户 2026-10-08 22:30~22:31 确认）：
> ① `<environment_details>` 的可用工具拆成**全局**（`~/.co-shell/bin/`）与**空间**（`{workspace}/bin/`）两部分；
> ② Web UI「动态信息 → 可用工具」同步调整，**先显示全局、再显示当前空间**；
> ③ 两处都**只分别显示一次**工具所在文件夹的**绝对路径**，工具行只显示**文件名**（不再带路径前缀），**保留时间与大小**；
> ④ 目录**不存在或为空**时仍输出该段的绝对路径行（便于看出「此目录为空」）。
>
> 现状（问题）：`<tools>` 只列工作区 `{workspace}/bin/`，每行都带 `bin/` 前缀（`agent/envelope.go:144` + `agent/file_tools.go:489`）；`~/.co-shell/bin/` 在全部代码中**无任何引用**，全局工具对 LLM 与面板都不可见。本机 `~/.co-shell/bin/` 当前不存在，故本任务完成后全局段应为「只有路径行」的空段。

## 术语

- **全局段** = `~/.co-shell/bin/` 下的工具清单（绝对路径 `$HOME/.co-shell/bin`）。
- **空间段** = 当前工作区 `{workspace}/bin/` 下的工具清单（绝对路径 `{workspace}/bin`）。
- **路径行** = 每段开头唯一的一行，内容为该目录的**绝对路径**（每段恰好一次）。
- **工具行** = `文件名 时间 大小`（如 `add_cs_prefix.py 2026-07-30 05:43:15 1.4KB`），**不再带目录前缀**。
- **裁剪开 / 关** = 配置 `env_history_prune` 为 true / false（FEATURE-622）。
- `(R)` = 离线可断言（Go 单测）；`(M)` = 需 `--serve` 隔离实例或真实会话实测。
> 运行时循环：先跑 `(R)` 全绿，再对每个 `(M)` 逐项实测并汇总，最后回填 BUILD。

## 输出格式定义（需确认）

**方案 A（本用例基准，推荐）** —— `<tools>` 内分两个子块，子块首行即绝对路径：

```xml
<tools>
<global_tools>
/Users/direct3d/.co-shell/bin
</global_tools>
<workspace_tools>
/Users/direct3d/github/co-shell/bin
add_cs_prefix.py 2026-07-30 05:43:15 1.4KB
bin/… （其余 33 项同理，均只写文件名）
</workspace_tools>
</tools>
```

**方案 B（备选）** —— 不加子标签，靠固定顺序区分：第 1 行 = 全局路径；其后 = 全局工具行；再 1 行 = 空间路径；其余 = 空间工具行。缺点：解析依赖「以 `/` 开头即路径行」的启发式，鲁棒性差。

> 若你更偏好方案 B（纯行式、无标签），请在确认用例时说明；否则按方案 A 实施。

## 用例与结果

### A. env_details 段结构（全局 → 空间）

- **UC-01（R）** `<tools>` 内先出现 `<global_tools>` 段、后出现 `<workspace_tools>` 段（顺序固定）。
- **UC-02（R）** 全局段首行是该目录的**绝对路径**（`$HOME/.co-shell/bin`），且该段内**只出现这一次**路径。
- **UC-03（R）** 空间段首行是 `{workspace}/bin` 的绝对路径，且该段内只出现一次路径。
- **UC-04（R）** 工具行格式为 `文件名 时间 大小`：不含 `bin/` 前缀、不含目录路径、不含绝对路径；时间格式 `2006-01-02 15:04:05`，大小沿用 `humanSize`。
- **UC-05（R）** 工具行数量 = 该目录实际条目数（受 `maxEntries=64` 上限约束）；顺序与 `os.ReadDir` 一致。
- **UC-06（R）** 全局目录存在且有内容时：全局段 = 路径行 + 若干工具行；空间段同理（构造两个临时目录做断言）。

### B. 空目录 / 缺失目录

- **UC-07（R）** 全局目录**不存在**：仍输出 `<global_tools>` 段与路径行，段内无工具行（当前本机即为该情形）。
- **UC-08（R）** 全局目录存在但**为空**：同 UC-07（路径行 + 无工具行）。
- **UC-09（R）** 空间目录不存在或为空：仍输出 `<workspace_tools>` 段与路径行，无工具行。
- **UC-10（R）** `env_include_tools=false`：整个 `<tools>` 段不输出（两段都不出现），行为与改动前一致。

### C. 裁剪与变化检测（与 FEATURE-622 协同）

- **UC-11（R）** 裁剪开（`env_history_prune=true`）：连续两次构建信封，两次都**实发**两段全量，全文不含 `<unchanged since msg#`。
- **UC-12（R）** 裁剪关且 `env_dir_change_detect=true`：两目录内容均未变化时，第二次输出 `<tools><unchanged since msg#N/></tools>`（整段占位，语义不变）。
- **UC-13（R）** 裁剪关时**全局目录内容变化**（新增/删除一个文件）也触发重新实发——变化检测哈希必须覆盖全局段，不能只看工作区。
- **UC-14（R）** 每 20 个信封强制全量（`envDirForceFullEvery`）行为不变：`dirMisses` 累加与复位逻辑对两段同时生效。

### D. Web UI「动态信息 → 可用工具」

- **UC-15（M）** 面板「可用工具」区块按「全局 → 空间」两段渲染：第一段为全局目录绝对路径标题，第二段为空间目录绝对路径标题；两段内路径各自只出现一次。
- **UC-16（M）** 面板里的工具行只显示 `文件名 时间 大小`，不再出现 `bin/` 前缀，也不重复出现目录路径。
- **UC-17（R）** 后端推送给面板的 `env` 数组中，`tools` 块内容包含两个子段且**全局在前、空间在后**；`dynEnvSkip` 仍不跳过 `tools`（`web/dyninfo.go:77-81`）→ 面板始终可见该块。
- **UC-18（R）** 面板 JSON 中 `tools` 块的文本与同一轮 `<environment_details>` 的 `<tools>` 段逐字节一致（面板继续镜像「LLM 所见」，FEATURE-612 语义不变）。

### E. 回归（其它机制不受影响）

- **UC-19（R）** `<current_dir>` 与 `<research>` 块格式**不变**（仍是 `前缀+名字 时间 大小`），本次只改 `<tools>`。
- **UC-20（R）** 持久历史不被改写：格式变化只发生在生成时；`:context full` 与 Web UI 回放显示生成当时冻结的信封（新格式），不影响历史可比性。
- **UC-21（M）** `--serve` 隔离实例实测：≥3 轮会话后，请求体里 `<tools>` 结构符合方案 A，且「唯一全量信封」（FEATURE-622）行为不回归（历史信封仍只有 `<time>`+`<message_no>`）。
- **UC-22（R/M）** 体积记账：记录改动前后 `<tools>` 段的字节数（预期：省去 34 个 `bin/` 前缀 ≈136B，新增全局段路径行 + 子段标签 ≈60B），给出实测数字，确认未显著增加 prompt。

### F. 边界

- **UC-23（R）** `$HOME` 无法解析（如 `os.UserHomeDir` 报错）时：全局段退化为「只有路径行」或整段省略——**必须明确其一并在用例中固定**（实现时选定，避免 panic）。
- **UC-24（R）** `bin/` 目录是符号链接或含子目录时：子目录沿用现有「`名字/ 时间`」形式（无大小），行为与原实现一致。
