# FIX-586 UC-0001：历史 env 三级降级接线恢复——代码层用例

> 分支：**FIX-586**　版本：**v0.91.2**　缺陷来源：FEATURE-579 plan A 接线在 FEATURE-583 中被误删
> 判定口径：`buildContextMessages()`（发给模型的这份拷贝）必须实际执行三级降级；开关关闭时零改动；持久历史零改动。
> 说明：**会话持久化历史 / Web 回放 / `:context full` 保留完整 env 属设计使然**，降级只作用于“发给模型的这一份拷贝”，本用例不要求它们变化。

## 目的

锁定“降级调用确实接在请求组装路径上”这一事实。本缺陷之所以长期未被发现，正是因为既有单测只直接调用 `pruneEnvContext`，从未覆盖接线。

## 修复要点

| 项 | 内容 |
|---|---|
| 代码 | `agent/loop.go` `buildContextMessages()` 末尾恢复 `msgs = a.pruneEnvContext(msgs)` |
| 顺序 | 先降级、后 `injectSkillsEnvToLast`（保证 `<skills>` 落在最新一条不降级的 envelope 上） |
| 开关 | 沿用 `env_history_prune`（默认 on）/ `env_history_full_keep=1` / `env_history_lite_keep=1`（本次不调整） |
| 守护 | 新增 `TestFIX586BuildContextMessagesPrunesEnv`、`TestFIX586BuildContextMessagesKeepsFullEnvWhenSwitchedOff` |

## 用例 A：真实请求路径发生降级（开关 on）

```bash
go test ./agent -run TestFIX586BuildContextMessagesPrunesEnv -v -count=1
```

**期望**：`PASS`，日志含 `FIX586_WIRING|levels=L2,L2,L1,L0|newest_bytes=<N>|history_unchanged=true`；
即 4 条历史消息从旧到新降级为 **L2 / L2 / L1 / L0**，最新一条保留 `<current_dir>`，次新一条保留 `<cwd>` 但已无 `<current_dir>/<tools>/<research>`，更早两条仅剩 `<time>` + `<message_no>`。

## 用例 B：开关关闭时零降级（向后兼容）

```bash
go test ./agent -run TestFIX586BuildContextMessagesKeepsFullEnvWhenSwitchedOff -v -count=1
```

**期望**：`PASS`，日志含 `FIX586_WIRING_OFF|levels=L0,L0,L0,L0`；每一条历史 envelope 都仍含 `<current_dir>`。
