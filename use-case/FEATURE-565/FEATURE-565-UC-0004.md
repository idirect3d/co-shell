# FEATURE-565 运行时用例 UC-0004：槽位复用、run+1 与清单行数上限

## 目标

验证 ID 在**非运行状态**下可被再次指定复用；复用后同一 ID 仍只占清单中的**一行**，`run` 计数 +1、
指令替换为本次的新指令；无论复用多少次，清单行数都不超过上限 N。

## 前置条件

- 工作区为 co-shell 仓库，`work/` 下已构建本分支可执行码（v0.79.0）。
- 上限 N = 5（默认）；Web UI 已打开（`--serve`）。
- 会话为全新会话（无历史子代理）。

## 步骤

1. 启动 `A1`：`launch_sub_agent(tasks=[{id:"A1", instruction:"第一个任务：ls -la"}], timeout_seconds=60)`，等待其**正常结束**（completed）。
   - 观察清单：出现 1 行 `A1`。结束后该行应消失（仅运行中上墙，见 UC-0005）。
2. 再次以同一 `A1` 启动不同指令：`instruction:"第二个任务：pwd"`。
   - 预期：**成功**（上一个 A1 已结束，槽位空闲）。
   - 检查该子代理的 `run` 值：应为 **2**（`sub_agent_status` 或清单/状态信息中可见）。
   - 检查工作目录仍是 `sub-agents/A1/`（同一 ID 复用同一工作目录），历史日志保留（不覆盖 run-1 日志）。
3. 让 `A1` 被 kill：在运行中调用 `kill_sub_agent(ids=["A1"])`，确认状态变为 killed。
4. 再次启动 `A1`（第三个任务）。
   - 预期：**成功**；`run` 变为 **3**；清单中仍只有 **1 行** A1，且指令为新指令（旧指令不再显示）。
5. 让 `A1` 处于失败状态（例如让子代理执行注定失败的命令），结束后再次用 A1 启动。
   - 预期：同样可以复用（completed / failed / killed 均视为槽位空闲）。
6. 反复复用 A1 共 10 次（每次等其结束再启动）。
   - 预期：清单**始终最多 1 行** A1；不会因为复用而堆积历史行。
7. 同时运行 A1、A2、A3、A4、A5（各保持 running），观察清单。
   - 预期：**恰好 5 行**（A1..A5），即行数 = min(运行中数量, N)；不存在第 6 行。

## 预期结果

- 占用判定只看「**当前会话中该 ID 是否正在运行**」，与历史完成/失败/被杀记录无关。
- 同一 ID 复用：同一行、`run` 递增、指令替换；历史 run 日志文件保留在 `sub-agents/<id>/` 下。
- 清单行数上限 = N，且不随复用次数增长。

## 验证方式

- `sub_agent_status` 查看 run 值与状态；`ls sub-agents/A1/` 确认历史 run 日志仍在。
- Web UI 清单行数统计（`browser_evaluate` 读取 `#subAgentBody` 子项数量）。
- 单元测试：同一会话内 completed → 复用 → `run+1`；killed/failed → 可复用；`Rows()` 行数 ≤ N。
