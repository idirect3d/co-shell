# FEATURE-565 运行时用例 UC-0003：每会话独立 ID 池

## 目标

验证 ID 池的作用域是**会话**：会话 A 的 A1..An 与会话 B 的 A1..An 互不影响；
一个会话把槽位用满或让 A1 正在运行，不会影响另一个会话使用 A1。

## 前置条件

- 工作区为 co-shell 仓库，`work/` 下已构建本分支可执行码（v0.79.0）。
- 上限 N = 5（默认）。
- 可开启两个会话（Web UI 两个会话页签，或一个 Web 会话 + 一个 CLI `run --session <id>` 会话）。

## 步骤

1. 在**会话 A** 中启动 `A1`（长任务，保持 running）。
2. 切到**会话 B**，启动 `A1`（同样长任务）。
   - 预期：**成功**。会话 B 的 A1 与会话 A 的 A1 是两个独立进程，各自有独立工作目录/日志。
3. 在会话 A 中把 A1..A5 全部用满（5 个 running），随后尝试 A6。
   - 预期：拒绝（会话 A 槽位已满，上限 5）。
4. 在会话 B（此时只有 A1 running）中尝试 `A2`、`A3`。
   - 预期：**成功** —— 会话 A 的满载不影响会话 B。
5. 观察两个会话的右侧清单。
   - 预期：每个会话的清单只显示**本会话**正在运行的子代理（会话 A 显示 5 行 A1..A5；会话 B 显示自己的 A1、A2、A3），互不串味。
6. 在会话 A 中检查 `<environment_details>` 的 `<sub_agents>`。
   - 预期：只列会话 A 的运行中子代理（不含会话 B 的），并标注当前最多可用子代理数为 5。
7. 关闭/结束会话 A 的所有子代理后，回到会话 B 再次启动 A4。
   - 预期：成功；会话 B 的池状态与 A 的历史状态无关。

## 预期结果

- 池与占用判定都带会话维度（`SessionID`），不存在跨会话争抢或互相阻塞。
- 同一 id（如 `A1`）在不同会话中可同时存在，且各自独立工作目录、独立 run 计数。
- 会话切换后清单与 `<sub_agents>` 都只反映当前会话。

## 验证方式

- 两个会话中分别 `sub_agent_status` 查看进程表（带会话过滤后的视图）。
- Web UI 会话切换时观察清单是否刷新为当前会话内容（FEATURE-564 的会话切换推送机制）。
- 单元测试：构造两个 `SessionID` 的进程表，断言 `Rows(sessA)` / 占用判定只统计本会话。
