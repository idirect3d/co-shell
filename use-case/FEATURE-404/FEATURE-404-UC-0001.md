# FEATURE-404 改进主消息录入框滚动条

## 背景

主消息录入框（`#input` textarea）在没有内容、有单行内容或有多行内容但没有超过最大显示行数时，都会自动出现滚动条。怀疑是输入框默认高度、内容上下间距（padding）设置稍大导致。

## 验收标准

1. 主消息录入框在没有内容、有单行内容或有多行内容但没有超过最大显示行数时，不出现滚动条。
2. 内容超过最大显示行数时，出现滚动条。
3. 编译通过：`go build ./... && go vet ./... && go build -o work/co-shell .`

## 测试用例

### UC-001 无内容时不出现滚动条
- 前置：Web UI 已加载，主消息录入框为空
- 步骤：观察录入框
- 期望：不出现滚动条

### UC-002 单行内容时不出现滚动条
- 前置：Web UI 已加载，主消息录入框输入单行内容
- 步骤：观察录入框
- 期望：不出现滚动条

### UC-003 多行但未超限时不出现滚动条
- 前置：Web UI 已加载，主消息录入框输入多行内容但未超过最大显示行数
- 步骤：观察录入框
- 期望：不出现滚动条

### UC-004 超过最大显示行数时出现滚动条
- 前置：Web UI 已加载，主消息录入框输入超过最大显示行数的内容
- 步骤：观察录入框
- 期望：出现滚动条

### UC-005 编译验证
- 前置：无
- 步骤：运行 `go build ./... && go vet ./... && go build -o work/co-shell .`
- 期望：全部通过，无编译错误、无 vet 告警
