# FIX-614 验收测试用例（UC-0001）：工具调用失败在实时消息指示器中未变红

> 分支 **FIX-614**，版本 **v0.101.1**（FIX 走 patch 递增）。
> 相关代码：`web/static/app.js`（消息可视化指示器 `#msgVizTrack`）。

## 一、根因（已实证）

`msgVizColor()`（app.js:3253）决定指示线颜色，**只在 `msgVizFlush()`（app.js:3299，由 `token_iter` 事件触发）时计算一次**。
而工具失败的 `level-error` class 是在**随后的 tool result 事件**里才加到 `.ev` 上的（app.js:2795）。线已绘制完毕，颜色与 tooltip 都不会更新。

实证（隔离实例 `--serve :28290`，函数级复现）：

```
tool block 创建 → msgVizFlush() 画线      → --line-color = #facc15（黄）
box.classList.add("level-error")          → --line-color = #facc15（仍黄）  ← BUG
box.className = "ev tool level-error"     → tooltip 仍为「工具 · TOOL · …」
```

历史回放之所以正确：回放时 tool block 及其 `level-error` 在同一次渲染中完成，`msgVizFlush()` 读到的 box 已带该 class。

## 二、修复方案（预期）

- 新增 `msgVizRecolor(box)`：在 `#msgVizTrack` 中按 `line._box === box` 找到对应的线，用 `msgVizColor(line._cls, box)` 重算 `--line-color`，并用 `msgVizTip(line._cls, box, line._ratio)` 重算 tooltip。
- `msgVizFlush()` 在线上保存 `line._ratio`（tooltip 的上下文百分比需要它，flush 时是唯一可得的时机）。
- 在工具失败标记处（app.js:2795）添加 `level-error` 后调用 `msgVizRecolor(box)`。
- 不改动 `msgVizColor` 的既有优先级（level-error 优先于 tool）。

## 四、关键断言点

- **B-001** 是本次 bug 的直接判据：修复前 `colorAfter === colorBefore === "#facc15"`；修复后 `colorAfter === "#FF0000"`。
- **B-004** 保证修复不会在"线还没画"的路径上引入异常（历史回放/早期事件）。
- **C-002/C-003** 保证 recolor 不误改其他线（只更新 `_box` 命中的那一根）。
