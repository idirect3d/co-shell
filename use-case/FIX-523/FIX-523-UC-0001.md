# FIX-523 测试用例：「身份与个性」弹窗高度自适应（矮窗口不再裁切）

## 背景

点击左下角 logo 图标 → 弹出菜单 → 点击「身份与个性」，打开身份与个性配置弹窗（`#identity`）。

现有实现：

| 位置 | 规则 | 问题 |
|---|---|---|
| `web/static/style.css:588` | `.identity-box { width: 560px; max-width: 92vw; }` | **无高度上限**，高度完全由表单内容撑开 |
| `web/static/style.css:2295` | `.modal-body { padding: 14px; }` | **无滚动容器** |
| `web/static/style.css:2267` | `.modal { position: fixed; inset: 0; display: flex; align-items: center; }` | 弹窗居中，超出的内容向视口上下溢出 |

因此窗口高度较矮时，弹窗上下溢出视口、且**没有滚动条**，底部字段与「保存」按钮无法访问。

对照既有同类实现（`style.css:2331-2347`）：`.settings-box { height: 800px; max-height: 90vh; }` + `.settings-body { height: calc(100% - 41px); overflow-y: auto; }`。

## 需求（用户确认）

1. 点击左下角 logo 图标弹出的菜单中，「身份与个性」配置界面在页面（窗口）较矮时**显示完整**。
2. 弹窗**最大高度不超过页面高度**，内容超出时**自动出现滚动条**。
3. 归属版本 **v0.58.1**（FIX，patch+1）；任务号 **FIX-523**。
4. 最大高度取 **90vh**（与现有系统设置 / 模型管理弹窗一致）。

## 实现契约

| 项 | 约定 |
|---|---|
| 改动文件 | 仅 `web/static/style.css` |
| `.identity-box` | 增加 `max-height: 90vh`、`display: flex`、`flex-direction: column` |
| `.identity-box .modal-body` | 增加 `flex: 1`、`min-height: 0`、`overflow-y: auto` |
| 关键点 | `min-height: 0` 是滚动生效的前提——flex 子项默认 `min-height: auto` 不会收缩到内容高度以下 |
| 标题栏 | `.modal-head` 保持固定高度、不参与滚动 |
| 非目标（明确不做） | ① 不改 `.modal` / `.modal-box` / `.modal-body` 的**公共**规则（避免影响其他弹窗）；② 不改窄屏全屏规则（`#identity` 本就未被 FEATURE-487 的全屏规则覆盖）；③ 不改任何 JS；④ 不改身份表单 DOM 结构、字段顺序、按钮文案；⑤ 不改其他弹窗（系统设置 / 模型管理 / 模型向导 / 图片预览）任何样式 |

## 用例

### UC-01 弹窗可正常打开（前置用例）

- **步骤**：点击 `#logoWrap` → 点击 `#miIdentity`。
- **期望**：`#identity` 不含 `hidden` 类；`.modal-head` 文本为「身份与个性」；`#identityBody` 渲染出 ≥1 个 `.identity-row`。

### UC-02 矮窗口（800×500）弹窗不溢出视口

- **步骤**：视口设为 800×500，打开弹窗。
- **期望**：`box.getBoundingClientRect().top >= 0` 且 `bottom <= innerHeight`（上下均不溢出）。

### UC-03 矮窗口弹窗高度 ≤ 90vh

- **步骤**：同 UC-02。
- **期望**：`box.getBoundingClientRect().height <= innerHeight * 0.9 + 1`（容差 1px）。

### UC-04 矮窗口出现内部滚动条

- **步骤**：同 UC-02。
- **期望**：`.identity-box > .modal-body` 的 `getComputedStyle().overflowY === "auto"`，且 `scrollHeight > clientHeight`（内容确实溢出并可滚动）。

### UC-05 矮窗口可滚动到最后一个字段的保存按钮

- **步骤**：同 UC-02，把 `.modal-body` 的 `scrollTop` 设为 `scrollHeight`。
- **期望**：`scrollTop > 0`；滚动后最后一个 `.identity-save` 按钮的 `rect.bottom <= innerHeight` 且 `rect.top >= 0`（完全可见、可点击）。
- **反向校验**：修复前该按钮 `rect.bottom > innerHeight`（此用例即为缺陷复现）。

### UC-06 标题栏固定不随内容滚动

- **步骤**：同 UC-02，记录滚动前 `.modal-head` 的 `rect.top`；滚动 `.modal-body` 到底部后再记录。
- **期望**：两次 `rect.top` 差的绝对值 < 1px（标题栏不移动）；且 `.modal-head` 始终为弹窗顶部区域。

### UC-07 高窗口（800×1400）弹窗高度内容自适应

- **步骤**：视口设为 800×1400，打开弹窗。
- **期望**：`box.height < innerHeight * 0.9`（未被 90vh 上限截断，仍随内容自适应）；`.identity-box > .modal-body` 的 `scrollHeight <= clientHeight + 1`（无多余滚动条）。

### UC-08 极矮窗口（800×360）不溢出

- **步骤**：视口设为 800×360，打开弹窗。
- **期望**：`top >= 0 && bottom <= innerHeight`；`height <= innerHeight * 0.9 + 1`；滚动条存在（`scrollHeight > clientHeight`）。

### UC-09 窗口高度动态变化时实时自适应

- **步骤**：视口 800×1200 打开弹窗 → 调整为 800×520（不重载页面）。
- **期望**：调整后 `top >= 0 && bottom <= innerHeight`，且 `height <= innerHeight * 0.9 + 1`（无需刷新即自适应）。

### UC-10 弹窗宽度无回归

- **步骤**：视口 1280×800，打开弹窗。
- **期望**：`box.getBoundingClientRect().width === 560`（桌面宽度未受影响）。

### UC-11 窄屏（body.narrow）不溢出

- **步骤**：视口 390×640（触发 `body.narrow`，确认 `document.body.classList.contains("narrow")` 为真）打开弹窗。
- **期望**：`box.width <= 0.92 * innerWidth + 1`（`max-width: 92vw` 生效）；`top >= 0 && bottom <= innerHeight`。

### UC-12 回归：系统设置弹窗不受影响

- **步骤**：视口 1280×800，打开系统设置弹窗（`#settings`）。
- **期望**：`.settings-box` 的 `max-height` 计算值仍为 `90vh`（`648px` @800 高）；其 `height` 仍为 `800px` 上限内取值（约 `min(800, 720)` = 720px）；弹窗不溢出视口。与修复前逐项相同。

### UC-13 回归：模型管理 / 图片预览弹窗不受影响

- **步骤**：打开 `#models` 弹窗；再打开 `#preview`（无图片时可跳过）。
- **期望**：`.models-box` 的计算样式（`max-width: 720px`、`min-width: 560px`）与 `.models-body { max-height: 60vh; overflow-y: auto }` 与修复前逐项相同。

### UC-14 功能回归：字段仍可保存

- **步骤**：在弹窗内修改任一 textarea（如「个性」字段）→ 点击该行「保存」按钮。
- **期望**：收到 `identity_result` 且 `ok === true`，`#identityBody` 顶部的 `.set-result.ok` 提示出现并在约 3s 后消失；弹窗保持打开、滚动位置不受影响。

### UC-15 无 JS 改动 / 无控制台报错

- **步骤**：`node --check web/static/app.js`；打开弹窗过程中监听 `console` 错误与 `window.onerror`。
- **期望**：语法检查通过；无 JS 报错。

### UC-16 编译与静态检查

- **步骤**：`go build ./... && go vet ./...`（根模块）；`cd cmd/co-shell-hub && go build ./... && go vet ./...`。
- **期望**：全绿，无新增告警。
