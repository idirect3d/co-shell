# FEATURE-548 测试用例（UC-0001 ~ UC-0016）

> 主题：会话记录按会话隔离 + 完整有序（每个会话维护自己的 UI 会话记录；切换会话回放该会话记录；记录严格按时间顺序完整落盘）
> 版本：v0.71.0　分支：FEATURE-548（基于 main，v0.70.0 已合并并打 tag）
> 验收口径（三条硬指标）：
> 1. **按会话隔离可见**：切换会话后消息区**只显示目标会话的记录**（旧会话内容必须消失），目标会话记录被完整回放。
> 2. **完整且有序**：记录包含用户消息（YOU 块）+ LLM 内容/思考 + 工具调用/结果块，严格按发生顺序排列；分页**绝不切半**、裁剪**绝不留半条消息**。
> 3. **运行中不可切换**：任务运行中点其他会话被拒绝并给出提示，当前任务不受影响。

## 一、编码前调研结论（用例设计依据，全部为硬事实）

| 项 | 现状 | 位置 |
|---|---|---|
| 记录存储 | 按 `sessionID\x00<8位seq>` 存 bbolt，**存储层本身已按会话隔离** | `store/eventstream.go:58-65,73,153` |
| 记录写入 | 全项目唯一写入点，写「事件到达时刻」的 `CurrentSessionID()` | `web/session.go:1345` |
| 事件合并 | `eventCoalescer` 把流式碎片合并为完整块后落盘 | `web/session.go:1327-1348`、`web/eventcoalesce.go` |
| 记录读取 | `pushHistory` → `loadHistoryPage`，按 `meta.msg_index` 分组分页 | `web/session.go:746,765` |
| 历史拉取时机 | **仅** WebSocket `onopen` 时一次，且**不带 session**（后端回退 `CurrentSessionID()`） | `web/static/app.js:560`；`web/session.go:747-749` |
| 缺陷 1 切会话不换记录 | 点击会话项只发 `session_switch`，**不清空消息区、不重拉历史**；后端 `switchSession` 也没有回放信号 | `app.js:2839-2845`、`web/session.go:869-908` |
| 缺陷 2 用户消息未落盘 | YOU 块只由前端本地 `renderUserEcho` 生成，后端无对应事件；`dynamic_event/user_message` 只进 agent 动态队列 | `app.js:3123,4165,4397,4447,4458`；`web/session.go:208` |

| 缺陷 4 裁剪丢半条 | 上限 5000 条按**事件条数**从最旧删，会把一条消息切成两半 | `store/eventstream.go:43,130-145` |
| 缺陷 5 切会话竞态 | coalescer 的 pending 块为 WebSession 级共享，运行中切会话会把旧会话未落盘内容写进新会话 | `web/session.go:1292,1337` |
| 运行态判定 | `ag.IsBusy()` 可用（已用于 `SetBusyProvider`、`ui_action` 分支） | `web/session.go:145,183` |
| YOU 块索引来源 | 首事件回填：`renderEvent` 用首事件 `meta.msg_index` 回填 pending YOU 块 | `app.js:1704-1712`、`2274-2295` |

## 二、实现约定（经 ask_user 确认 + 编码口径）

1. 版本 **v0.71.0**、任务号 **FEATURE-548**（用户确认）。
2. 切换会话：**清空消息区 + 从 bbolt 回放目标会话完整记录**（用户确认）。
3. **任务运行中禁止切换会话**，给出提示（用户确认）。
4. 分页**按消息组整组取数，绝不切半**；事件流上限**改为按消息组裁剪**（用户确认）。
5. 新增用户消息事件类型（`user_echo`）：**仅落盘、不实时推送**——实时 YOU 块仍由前端本地 `renderUserEcho` 渲染（避免重复块），回放时由 `renderEvent` 渲染为 YOU 块。
6. 回放请求携带目标会话 id（复用 `history_get` 的 `value` 字段），不再依赖 `CurrentSessionID` 的读写时序。
7. 切换会话后必须刷新：会话列表当前项、任务进展（PROJECT STANDARDS「切换 session 必须主动推送任务进展刷新」）。

## 三、用例清单

### A 组：结构 / 单测（Go 单测，可自动执行）

#### UC-0001 分页按消息组整组返回，绝不切半
- **前置**：`newTestStore(t)`；构造 3 条消息（`msg_index` = 0/1/2），每组事件数分别 5 / 5 / 5。
- **步骤**：调用新增的按组读取接口 `LoadEventsByGroups(sessionID, 2, 0)`。
- **预期**：返回 2 组、共 10 条事件；返回集合中每个 `msg_index` 的事件数与其写入数**完全相等**（无缺失）；`hasMore == true`；游标指向最旧返回组的首个事件。
- **失败判据**：返回任一组的条数少于写入条数（切半），或返回了 3 组（未按 groups 截断）。

#### UC-0002 单组事件数超过单页事件预算时仍整组返回
- **前置**：构造第 1 组 `msg_index=0` 含 **120** 条事件（> `maxEventsPerMessage`=50），第 2 组 `msg_index=1` 含 3 条事件。
- **步骤**：`LoadEventsByGroups(sessionID, 1, 0)`（只要最新 1 组）。
- **预期**：只返回 `msg_index=1` 的 3 条事件（整组）；`hasMore == true`。再次以返回游标请求，得到 `msg_index=0` 的**全部 120 条**事件（不因 50 条预算而截断）。
- **失败判据**：任一次返回的组内事件数少于写入数。

#### UC-0003 反复分页无重无漏，全局时序单调
- **前置**：构造 25 组 × 每组 7 条事件，`msg_index` 0..24。
- **步骤**：反复调用按组读取（每次 5 组）直到 `hasMore == false`，把各页事件按调用顺序拼接。
- **预期**：拼接结果共 175 条事件；`msg_index` 序列严格递增（0→24）且不重复；每组的条数均为 7。
- **失败判据**：出现重复 `msg_index`、条数不为 7、或顺序非单调。

#### UC-0004 裁剪按消息组进行，不产生半条消息
- **前置**：`newTestStore(t)`；构造若干组事件使总数超过上限（沿用 `maxEventStreamEntries` 预算），每组 3 条事件、`msg_index` 递增。
- **步骤**：逐条 `AppendEvent` 直到总数超限；再 `LoadEvents` 读回全部。
- **预期**：保留事件总数 ≥ 上限预算的「整组」数；**每个保留的 `msg_index` 的事件数都等于 3**（边界组被整组保留或被整组丢弃，不存在 1 或 2 条的组）；最新一组完整保留。
- **失败判据**：存在任一 `msg_index` 的事件数 < 3（被切半）。

#### UC-0005 用户消息事件在首事件时落盘且索引正确
- **前置**：`newSessionFixture(t)` 风格脚手架；拿到 `WebSession` 与其 renderer。
- **步骤**：模拟 `ReadLine` 收到用户输入「你好」→ 触发该轮的首个 stream 事件 → 读回该会话事件流。
- **预期**：事件流中存在一条 `type == "user_echo"`、`text == "你好"` 的事件；其 `meta.msg_index` 等于该用户消息在 agent 消息数组中的下标（即首事件时 `len(Messages())-1`）；该事件在事件流中的顺序**先于**该轮首个业务事件。
- **失败判据**：无 `user_echo` 事件，或索引不等于该用户消息下标，或顺序出现在首业务事件之后。

#### UC-0006 用户消息事件只落盘、不实时推送
- **前置**：同 UC-0005 的脚手架（带可捕获推送的假 server）。
- **步骤**：触发用户输入 + 首事件，检查推送给浏览器的消息。
- **预期**：推送给浏览器的帧中**不包含** `user_echo` 事件（实时 YOU 块由前端本地渲染）；但事件流中存在该事件。
- **失败判据**：浏览器收到 `user_echo`（会造成 YOU 块重复）。

#### UC-0007 任务运行中禁止切换会话（后端）
- **前置**：脚手架中令 `ag.IsBusy()` 为真（模拟运行中）。
- **步骤**：发送 `clientMessage{Type:"session_switch", Value:"sess-B"}`。
- **预期**：`ag.CurrentSessionID()` **保持原值不变**；agent 上下文消息未被替换；服务器推送一条失败/提示消息（`kind` 为切换结果且 `ok == false`）。
- **失败判据**：会话被切走，或没有任何提示帧。

#### UC-0008 切会话成功后推送重载信号且保持会话隔离
- **前置**：存在会话 A、B（各含不同事件流），当前为 A 且空闲。
- **步骤**：发送 `session_switch` → B。
- **预期**：`CurrentSessionID() == "B"`；向浏览器推送的帧中存在一条「已切换」信号且携带目标 id；B 的事件流不含 A 的事件（`LoadEvents("B")` 只返回 B 的）。
- **失败判据**：无重载信号，或事件流串会话。

#### UC-0009 回放请求按显式 session 取历史，不依赖 CurrentSessionID
- **前置**：会话 A、B 各有独立事件流；当前会话为 B。
- **步骤**：`pushHistory("A", count, 0)`（显式传入 A）。
- **预期**：返回的历史事件全部来自 A（事件条数与 A 一致）；与 `CurrentSessionID()==B` 无关。
- **失败判据**：返回 B 的事件（回退到了 CurrentSessionID）。

#### UC-0010 前端切会话清空消息区并重拉历史（静态校验）
- **步骤**：读取 `web/static/app.js`。
- **预期**：存在对后端「已切换」信号的处理器，其函数体内**同时**出现清空消息区（`resetStreamView(`）与历史重拉（`history_get`）调用；且 `history_get` 帧携带目标会话 id。
- **失败判据**：`session_switch` 点击处仍只 `wsSend` 而没有任何重载链路。

#### UC-0011 前端支持 user_echo 回放为 YOU 块（静态校验）
- **步骤**：读取 `web/static/app.js`，定位 `renderEvent`。
- **预期**：`renderEvent` 中存在 `user_echo`（或等效常量）分支，调用 `renderUserEcho(` 渲染 YOU 块。
- **失败判据**：回放时 `user_echo` 落入无法识别的分支（YOU 块丢失）。

### B 组：浏览器实测（隔离实例，`--serve` 启动）

#### UC-0012 切换会话显示目标会话的记录
- **前置**：`work/co-shell-0.71.0.darwin.arm64 --serve --port <p>` 启动，浏览器进入工作区；会话 A 已有若干轮对话，新建会话 B 并发一条消息。
- **步骤**：点击会话列表中的 A。
- **预期**：消息区**不再包含 B 的任何块**；A 的历史块按时间顺序从上到下出现（含 A 的 YOU 块）；滚动定位到最新消息；会话列表当前项高亮为 A。
- **失败判据**：仍显示 B 的内容，或 A 的记录为空/顺序错乱。

#### UC-0013 切到全新会话消息区为空，切回后记录完整
- **前置**：会话 A 已有记录。
- **步骤**：新建会话 → 观察 → 再切回 A。
- **预期**：新会话消息区为空且不残留 A 的任何块；切回 A 后记录与切走前一致（块数、内容、顺序相同）。
- **失败判据**：新会话显示旧内容，或切回后 A 的记录缺失/多出内容。

#### UC-0014 刷新后记录完整（含 YOU 块）且顺序与实时一致
- **前置**：在一个会话中完成至少 2 轮对话（含至少 1 次工具调用）。
- **步骤**：刷新页面（或断开重连）。
- **预期**：回放出的块序列与刷新前的实时块序列**逐项一致**：YOU 块 → 思考/内容块 → 工具调用块 → 结果块 → …；YOU 块不再丢失；无重复块、无孤立块。
- **失败判据**：YOU 块缺失，或块顺序与实时不一致，或出现重复块。

#### UC-0015 长会话上翻分页无重复、无缺失、顺序单调
- **前置**：一个会话产生足够多的消息组（超过一页，建议 ≥ 25 组）。
- **步骤**：在消息区顶部反复上翻触发分页，直到不再加载。
- **预期**：每次分页插入的块都是整条消息（内容不缺半截）；全程不出现重复块；`msg_index` 自上而下严格递增；最顶部为最早的消息。
- **失败判据**：出现内容被截断的块、重复块、或顺序颠倒。

#### UC-0016 运行中切换会话被拒绝并提示
- **前置**：在会话 A 发起一个会持续一段时间的任务（例如要求执行多条命令）。
- **步骤**：任务运行中点击会话 B。
- **预期**：弹出/显示"当前任务运行中，无法切换会话"提示；消息区仍为 A 且 A 的任务继续正常输出；任务结束后可正常切换到 B。
- **失败判据**：切换成功（导致 A 的记录被打断或串会话），或没有任何提示。
