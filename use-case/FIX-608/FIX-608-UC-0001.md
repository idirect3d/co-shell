# FIX-608 UC-0001：移动端下载工作区文件（iOS 实现 WKDownload + 前端不再卸载页面）

> 分支：**FIX-608**　版本：**v0.96.2**　BUILD：**1221**
> 现象：移动端（co-shell iOS App 的 WKWebView）点击工作区文件的下载图标后，**主工作区变白、无响应**，下载被阻止。
> 判定口径：修复后，移动端点击下载应能真正拿到文件（弹保存/分享面板），且 **SPA 页面不被卸载**（成功、失败、取消三种情况都不白屏）。

## 背景（现象与根因）

- **不是 iOS 系统权限问题**。两层原因：
  1. **服务端门（既有权限开关，非本次修改点）**：`web/server.go:1508` `downloadEnabled(r) = opts.DownloadEnabled && isRemoteRequest(r)`；未启用 `--download-enabled` 时 `GET /api/download` 返回 **403 JSON**（hub 的 agent 配置里「启用下载功能」开关决定是否注入该参数）。
  2. **根因（本次修复）**：
     - 前端 `web/static/app.js:6283` `downloadFile(path)` 用 `window.location.href = "api/download?path=..."` —— 这是**整页导航**，导航一旦开始，SPA 页面即被卸载。
     - iOS 端 `mobile/ios/Runner/WebViewController.swift` **未实现任何下载处理**（源码中无 `WKDownloadDelegate`、无 `decidePolicyFor`、无 `navigationResponse`）。WKWebView 对 `Content-Disposition: attachment` 响应既不落盘也无法渲染，导航被取消，而页面已被卸载 → **白屏且不自动恢复**。

## 变更点（计划）

| 位置 | 变更 |
|---|---|
| `mobile/ios/Runner/WebViewController.swift` | 实现 `WKNavigationDelegate.decidePolicyFor navigationResponse`：附件响应 / `canShowMIMEType == false` → `.download`；`webView(_:navigationResponse:didBecome:)`、`webView(_:navigationAction:didBecome:)` 设置 `WKDownload.delegate` |
| 同上 | 实现 `WKDownloadDelegate`：`download(_:decideDestinationUsing:suggestedFilename:completionHandler:)` 落到沙盒 `Documents/download/`（文件名净化）；`downloadDidFinish` 弹 `UIActivityViewController`（保存到「文件」/分享）；`didFailWithError` 弹 alert；取消不影响页面 |
| `mobile/ios/Runner/Info.plist` | 视需要声明 `UIFileSharingEnabled` / `LSSupportsOpeningDocumentsInPlace`（让沙盒目录在「文件」App 可见） |
| `web/static/app.js` `downloadFile()` | 改为**不卸载页面**的下载触发方式（隐藏 `iframe`），保留 `encodeURIComponent(path)`；服务端 403 时给出可见提示（不再空白页） |
| 测试 | 前端断言测试（`web/`）+ iOS 源码结构断言 + 真机人工验收 |

## 用例与结果

> 状态列在实施完成前为 `待验证`；`(R)` = 可自动化/命令行复现，`(M)` = 需真机人工验收。

### A. 前端：下载不再卸载页面

- **UC-01（R）** `downloadFile()` 不再使用整页导航：`web/static/app.js` 的 `downloadFile` 函数体内**不含** `window.location.href`（也不含 `location.assign` / `location.replace`）。
- **UC-02（R）** 下载走非导航手段：复用一个隐藏 `iframe` 触发 `api/download?path=`（不新建/不残留临时节点，也不卸载当前文档）。
- **UC-03（R）** URL 与参数保持不变：仍为 `api/download?path=` + `encodeURIComponent(path)`（路径含空格/中文/`#` 等字符时编码正确）。
- **UC-04（R）** 失败有可见反馈：服务端返回 403/404 时前端不产生白屏，给出可见提示（`T.downloadFailed` 之类文案存在 zh/en 双语）。
- **UC-05（M）** 桌面浏览器点击文件树下载图标：文件正常保存，页面**不刷新、不跳转**（DevTools Network 中该请求类型为 `document`/`iframe`，主文档导航计数不变）。
- **UC-06（M）** 桌面浏览器在未启用 `--download-enabled` 的实例上点击下载：页面保持原样并提示失败原因（对照修复前的空白 JSON 页）。

### B. iOS：WKDownload 下载处理（源码结构 + 真机）

- **UC-07（R）** 源码实现下载策略：`WebViewController.swift` 含 `decidePolicyFor` 的 `navigationResponse` 分支，且对附件响应返回 `.download`（含 `Content-Disposition`/`attachment` 判定与 `canShowMIMEType` 兜底）。
- **UC-08（R）** 源码挂接下载代理：含 `webView(_:navigationResponse:didBecome:)` 并设置 `download.delegate`（下载由响应策略接管，不需要 `<a download>` 的动作分支）。
- **UC-09（R）** 源码实现 `WKDownloadDelegate`：含 `decideDestinationUsing`（返回沙盒 `Documents/download/` 下的目标路径）与完成/失败回调；目标文件名做非法字符与重名处理。
- **UC-10（R）** 普通导航不受影响：非附件响应仍走 `.allow`（原有页面加载、`target=_blank` 在当前 WebView 打开的逻辑保留）。
- **UC-11（M）** 真机点下载（开关已开、经 hub 访问）：出现保存/分享面板，可存到「文件」App；**主工作区不变白**。
- **UC-12（M）** 真机取消保存：页面回到原工作区，可继续操作，不白屏、不无响应。
- **UC-13（M）** 真机下载失败（服务端 403 / 网络中断）：页面不白屏，有可见失败提示。
- **UC-14（M）** 真机较大文件（≥10MB）下载：下载期间页面可交互，完成后文件完整（大小与源文件一致）。
- **UC-15（M）** 真机连续下载多个文件：每次都能落地且文件名不互相覆盖（重名时自动加序号）。

### C. 服务端行为回归（本次不改判定逻辑，仅确认无回归）

- **UC-16（R）** 启用开关 + 非 loopback 客户端（`bind=127.0.0.1` + `X-Client-IP: 192.168.3.39:51000`）→ **200**，`Content-Disposition: attachment`。
- **UC-17（R）** 未启用开关 → **403**（`download disabled`）。
- **UC-18（R）** 路径穿越 `path=../../etc/passwd` → **403**；目录 → **404**。
