# FIX-329: 循环检测误判修复与循环报警类型区分

## 背景

本次误判根因：LLM 流式输出以嵌套代码块结尾，最后两行为 `  }`（带缩进）与 `}`（顶格）。`LoopDetector.AddChunk` 对每行先 `strings.TrimSpace` 再 hash 比较，`  }` 与 `}` 被归一化为同一行 `}`。`checkLoop` 从 p=1 开始检查，当 threshold=2 时，流末尾出现两行相同即触发循环报警（`countAtEnd(1,2)` 命中）。而 judge 模型看到"分析代码但未修改文件"的语义无进展，确认了该误报。

同时存在以下问题：
1. judge 提示词仅传 `{TASK}`（第一条指令）与 `{LAST_INPUT}`（最后一条指令），判模对"中间是否有效推进"信息不足。
2. 疑似循环提示无法区分触发类型（单行重复/多行周期/字符周期/单行超长/长输出/工具调用重复）。

## 修复方案

### 改动 1：LoopDetector 行匹配不再 TrimSpace（agent/loop_detector.go）
- AddChunk 对每行只做 `strings.TrimSuffix(line, "\r")` 去 `\r`，保留行首尾缩进（`  }` ≠ `}`）。
- 空行判断仍用 `strings.TrimSpace(line) == ""` 跳过纯空白行。
- 效果：`  }` 与 `}` hash 不同，不再于 threshold=2 时误判。

### 改动 2：p=1 单行重复数量块限制（新配置 loop-single-line-block-limit）
- `LoopDetector` 新增 `singleLineBlockLimit` 字段，`NewLoopDetector(threshold, blockLimit)` 传参。
- `checkLoop` 中 p==1 时追加判定：`len(sample) * k > blockLimit` 才判循环；否则 `continue`。
- 默认 200：`}` × 2 = 2 字符 < 200 不触发；80 字行 × 2 = 160 仍 < 200 不触发（需更高重复次数）；80 字行 × 3 = 240 > 200 触发。
- 新增 `LLMConfig.LoopSingleLineBlockLimit`（JSON `loop_single_line_block_limit`），接入 DefaultConfig、:set、:config 向导、CLI --help。

### 改动 3：judge 提示词升级（agent/loop.go + i18n/zh_loop.go + i18n/en_loop.go）
- 新增 `getAllUserPrompts()`：按时间顺序收集所有真实用户输入（过滤 XML 工具结果 `[{TOOL_CALL}] 返回结果：...`、continue prompt、`<loop_feedback>true</loop_feedback>` 消息），编号输出（`1. xxx\n2. yyy`），去 `<environment_details>` 后缀，总量截断 4000 字符。
- 新增 `getIterationTools()`：按迭代输出工具调用名序列（`iter1: read_file, search_files\niter2: replace_in_file`）。
- `KeyLoopJudgeUserPrompt` 模板：`# 用户最后指令\n\n{LAST_INPUT}` 替换为 `# 用户历史提示词\n\n{USER_PROMPTS}`；新增 `# 迭代工具调用序列\n\n{ITERATION_TOOLS}` 段（置于 {ITERATIONS} 之后）。
- `buildLoopJudgeUserPrompt` 新增两个替换。

### 改动 4：循环报警类型区分（agent/loop.go + i18n）
- `LoopDetectedError` 新增 `LoopType string` 字段。
- `checkLoop` 构造错误时按 p 填充 `LoopType`：p==1 → "single_repeat"，p>=2 → "multi_line"。
- `SingleLineLoopDetector.CheckLine` 返回的 `LoopEvent` 已有 `Detector` 标识，handleLoopDetection 从 `LoopDetectedError` 或错误文本匹配出类型。
- `handleLoopDetection` 中 `KeyLoopSuspected` 改为带类型参数的 `KeyLoopSuspectedWithType`：`检测到疑似循环内容（类型: %s）...`。
- zh/en 类型词表：`single_repeat`（单行重复）/`multi_line`（多行周期重复）/`line_too_long`（单行超长）/`char_period`（单行内字符周期）/`long_output`（长输出无进展）/`tool_call`（工具调用重复）。

## 用例列表

### UC-0001 带缩进行与顶格行不再误判（单测）
**前置条件**：NewLoopDetector(2, 200)（threshold=2，blockLimit=200）。
**步骤**：AddChunk("  }\n}\n")（`  }` 带缩进、`}` 顶格各一行）。
**预期**：不返回错误——两行 hash 不同，p=1 无法命中，p>=2 行数不足。

### UC-0002 同一行带不同缩进不误判（单测）
**前置条件**：NewLoopDetector(2, 200)。
**步骤**：AddChunk("    renumberStageRows(parent);\n  }\n}\n")。
**预期**：不返回错误——末尾两行 `  }` 与 `}` 因保留缩进 hash 不同。

### UC-0003 短行重复受 blockLimit 抑制（单测）
**前置条件**：NewLoopDetector(2, 200)。
**步骤**：AddChunk("}\n}\n")（两行完全相同的顶格 `}`）。
**预期**：不返回错误——p=1 命中 k=2，但 `1 字符 × 2 = 2 ≤ 200`，被 blockLimit 拦截。

### UC-0004 长行重复仍触发（单测）
**前置条件**：NewLoopDetector(2, 200)。
**步骤**：AddChunk(78字行 + "\n" + 同78字行 + "\n")。
**预期**：返回 LoopDetectedError——`78 × 2 = 156 ≤ 200`……此处使用 120 字行验证：`120 × 2 = 240 > 200` 触发，且 LoopType=="single_repeat"。
（注：78×2=156 不触发是 blockLimit 预期行为；用例用 120 字行验证触发分支）

### UC-0005 多行周期不受 blockLimit 影响（单测）
**前置条件**：NewLoopDetector(2, 200)。
**步骤**：AddChunk("lineA\nlineB\nlineA\nlineB\n")。
**预期**：触发——p=2 不检查 blockLimit，k=2 ≥ threshold 即触发，LoopType=="multi_line"。

### UC-0006 LoopDetectedError 携带类型标识（单测）
**前置条件**：触发单行重复（120字行×2）。
**步骤**：断言错误类型。
**预期**：`err.(*LoopDetectedError).LoopType == "single_repeat"`；多行周期场景 `LoopType == "multi_line"`。

### UC-0007 getAllUserPrompts 过滤系统消息（单测）
**前置条件**：Agent.messages 含真实用户输入、XML 工具结果（`[read_file] 返回结果：...`）、continue prompt（i18n KeyContinuePrompt）、循环反馈（env 含 `<loop_feedback>true</loop_feedback>`）。
**步骤**：调用 getAllUserPrompts()。
**预期**：只含真实用户输入，按时间顺序编号，XML 工具结果/continue prompt/循环反馈被过滤。

### UC-0008 getAllUserPrompts 去 environment_details 后缀（单测）
**前置条件**：用户消息带 `<environment_details>` 块。
**步骤**：调用 getAllUserPrompts()。
**预期**：输出不含 `<environment_details>`。

### UC-0009 getIterationTools 输出工具序列（单测）
**前置条件**：Agent.messages 含 2 条带 ToolCalls 的 assistant 消息。
**步骤**：调用 getIterationTools()。
**预期**：输出 `iter1: read_file, search_files\niter2: replace_in_file` 格式。

### UC-0010 judge user 模板 {USER_PROMPTS} 与 {ITERATION_TOOLS} 被填充（单测）
**前置条件**：i18n 已初始化。
**步骤**：调用 buildLoopJudgeUserPrompt()。
**预期**：无 `{USER_PROMPTS}` / `{ITERATION_TOOLS}` 残留占位符；含用户历史提示词列表与工具序列。

### UC-0011 handleLoopDetection 渲染类型（断言测试）
**前置条件**：构造 LoopDetectedError{LoopType:"single_repeat"}。
**步骤**：调用 handleLoopDetection（LoopJudgeEnabled=false）。
**预期**：输出含 `类型` 和 `single_repeat` 中文词（单行重复）。

### UC-0012 运行时复现原始误判场景（运行时）
**前置条件**：loop-detect-threshold=2，loop-single-line-block-limit=200，LLM 输出以嵌套代码块结尾。
**步骤**：让 LLM 输出 `  }\n}` 结尾的代码块。
**预期**：不再触发循环报警（修复前触发）。

### UC-0013 运行时真实循环仍被检测（运行时）
**前置条件**：loop-detect-threshold=2，loop-single-line-block-limit=200。
**步骤**：LLM 连续重复输出同一长行 ≥2 次。
**预期**：触发循环报警，且提示含"单行重复"类型。
