# FIX-463 测试用例

## UC-0001: gitStatusMap 在 git status 正常时返回状态映射

### 测试目标
验证 gitStatusMap 在 git status 命令正常完成时，能正确解析 git 状态码并返回映射。

### 前置条件
- 存在一个 git 仓库目录（含 .git）
- git 命令可用

### 测试步骤
1. 创建一个临时 git 仓库目录
2. 在仓库中创建文件并修改（产生 M/A/D/U 等状态）
3. 调用 gitStatusMap(root)
4. 检查返回的 map

### 预期结果
- 返回的 map 包含正确的文件路径 → 状态码映射
- M/A/D/R/U 状态码正确解析
- 未修改的文件不在 map 中

### 验证方法
- 单元测试 TestGitStatusMap 通过
- `go test ./web/ -run TestGitStatusMap` 通过

## UC-0002: gitStatusMap 在 git status 卡住时超时返回 nil

### 测试目标
验证 gitStatusMap 在 git status 命令卡住（不返回）时，能在超时后返回 nil，不阻塞调用方。

### 前置条件
- 存在一个 git 仓库目录，其 git status 会卡住（如 mcp-sample 场景）
- 或通过 mock 模拟 git 命令卡住

### 测试步骤
1. 准备一个 git status 会卡住的目录（或 mock 一个卡住的 git 命令）
2. 调用 gitStatusMap(root)
3. 观察是否在超时时间内返回

### 预期结果
- gitStatusMap 在超时（如 3 秒）后返回 nil
- 不永久阻塞
- 调用方（handleTree）能继续执行，文件树正常显示

### 验证方法
- 单元测试 TestGitStatusMapTimeout 通过
- 在 mcp-sample 目录下启动测试服务，curl /api/tree 能正常返回（不再超时）
