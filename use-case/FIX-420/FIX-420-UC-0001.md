# FIX-420 修复问题判定模型（problem solver）调用失败

## 背景

日志显示 `judgeLoop: problem solver call failed: Thinking mode does not support this tool_choice`。问题判定模型 `deepseek-v4-flash` 是 thinking 模型（默认开启思考），DeepSeek API 在 thinking 模式下不支持 `tool_choice` 参数。

根因：`callProblemSolver` 中 `SetThinkingEnabled(false)` 无效（`Chat` 方法不读取 `thinkingEnabled` 字段），且 `SetBodyAdditions` 只注入了 `tool_choice`，未注入 `{"thinking":{"type":"disabled"}}`，导致请求体同时带 thinking 和 tool_choice → 400 错误 → judgeLoop 返回 nil → 回退到直接循环反馈。

修复方案：`agent/problem_solver.go` `callProblemSolver` 移除无效的 `SetThinkingEnabled(false)`，改用 `llm.GetThinkingAdapter(modelCfg.Provider)` + `BuildAdditions(ThinkingModeDisabled)` 生成 thinking disabled 参数，与 `tool_choice` 合并到同一个 `SetBodyAdditions`。

## 验收标准

1. `callProblemSolver` 在 OpenAI 模式下，`SetBodyAdditions` 同时包含 `tool_choice` 和 thinking disabled 参数（如 `{"thinking":{"type":"disabled"}}`）。
2. 问题判定模型为 thinking 模型（如 deepseek-v4-flash）时，请求体不再同时带 thinking 和 tool_choice 冲突。
3. 移除无效的 `SetThinkingEnabled(false)` 调用。
4. 编译通过：`go build ./... && go vet ./... && go build -o work/co-shell .`
5. agent 包测试通过：`go test ./agent/`
