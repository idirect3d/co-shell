# FIX-348: SSE 跨行 data 帧被切行丢弃导致工具参数截断

## 背景

1. co-flow 08-11 单日 132 次 `cannot parse tool arguments: unexpected end of JSON input`，原始报文截断在 `"replacements": `。字节级调查（co-flow `co-shell-2026-08-11.log` 4457/4458 行）确认根因链：
   - 上游 vLLM 发送工具参数 `arguments` 时，JSON 字符串值内含**真实换行（0x0a）**（多行代码未正确转义）→ SSE `data` 帧**跨行**；
   - `StreamReader.Read()`（`llm/client.go`，BUILD-32 起从未修改）按 `\n` 切行，把跨行帧拆成多行；
   - `parseSSELine` 只解析单行 `data:` 完整 JSON：跨行帧第一行（不完整 JSON）`json.Unmarshal` 失败 → `continue` 静默丢弃；续行（无 `data:` 前缀，如日志 4458）返回 nil → `continue` 静默丢弃；
   - 工具 `arguments` 在跨行点丢失全部后续内容 → 截断在 `"replacements": ` → `json.Unmarshal` 报错。
2. 08-07 已有 4 次（write_to_file `content` 大代码）、08-11 大规模暴露（replace_in_file `replacements` 大代码）——凡携带大段多行代码参数的工具都可能触发。
3. 附加隐患：ChatStream 读循环串行执行 `read → log → parse → eventCh <-`，`eventCh` 缓冲 100；消费者（agent 端 ToolCallDelta → JSONToolCallParser → REPL 渲染）慢时 `eventCh <-` 阻塞会拖住读循环，raw chunk 日志延迟（co-flow 4456→4457 曾出现 17.6s 空窗 + 5 帧同毫秒堆积）。

## 目标

- **方案 A（根治数据丢失）**：ChatStream 读循环实现 SSE 跨行 data 帧拼接——`data:` 行解析失败（不完整 JSON）时暂存 `pendingData`，把后续**无 `data:` 前缀的续行**按真实换行拼回原帧，直到 JSON 完整或遇空行/新 `data:` 帧；拼接成功后再 `parseSSELine` 并处理事件。**续行不再丢失，arguments 完整**。
- **方案 B（日志实时加固）**：eventCh 发送改非阻塞 `sendEvent()`（先补发 FIFO pending 队列，`select` 非阻塞发送，满则入队）+ 缓冲 100→1024，保证读循环不被消费者慢拖住，`LLM ChatStream raw chunk` 日志"收到即记录"。

## 用例

### S1 跨行 SSE data 帧拼接（单测：mock SSE 含真实换行的 data 帧）

前置：`go build ./...` 通过；单测用 mock HTTP SSE server，模拟 vLLM 发送含真实换行（0x0a）的 data 帧。

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|---------|
| UC-0001 | 跨行帧 arguments 完整 | mock SSE 发送 `data: {"choices":[{"delta":{"tool_calls":[{"index":0,"id":"c1","function":{"name":"read_file","arguments":"{\"path\":\"a\",\n\"intent\":\"x\"}"}}]}}]}`（arguments 值内含真实换行）→ `[DONE]` | 消费者收到 1 个完整 ToolCallDelta 事件，`Arguments` = `{"path":"a",\n"intent":"x"}`（**含真实换行，完整无截断**） |
| UC-0002 | 跨行帧不产生错误事件 | 同 UC-0001 | 事件流**无** StreamEventError；跨行帧各切片不产生多余事件（总共只产生 1 个 ToolCallDelta） |
| UC-0003 | vLLM 真实场景（replacements 大代码跨行） | mock 发送：完整帧 `arguments += ", \"replacements\": "` → 跨行帧 `data: {...arguments":"{\n\tby, bm, bd := b.Date()\n\t...\n}"}` → finish_reason → `[DONE]` | 累积 arguments 最终 = `", \"replacements\": " + "{\n\tby, bm...\n}"` 完整，`json.Unmarshal` 成功，无 "unexpected end of JSON input" |
| UC-0004 | 正常单行帧回归 | mock 发送多个单行 data 帧（content + tool_calls delta + `[DONE]`） | 行为与 FIX-348 前完全一致：每帧 1 个事件，顺序正确 |
| UC-0005 | 真坏数据行丢弃 | mock 发送 `data: {bad json`（非法）→ 空行 → 正常帧 | 坏数据行不产生事件、不 panic；后续正常帧正常处理 |
| UC-0006 | 跨行帧后紧跟正常帧顺序 | 跨行 tool_calls 帧 → 正常 content 帧 → `[DONE]` | 事件顺序 = 跨行帧事件 → content 事件 → Done，无错乱 |
| UC-0007 | `[DONE]` 信号 | 跨行帧处理后 `data: [DONE]` | Done 事件正常发送；raw chunk 日志含 `data: [DONE]` |
| UC-0008 | 空行结束残余丢弃 | `data: {...不完整`（无闭合）→ 空行 → 后续正常帧 | 不完整残余在空行处丢弃，不产生错误事件；后续帧正常 |

### S2 eventCh 非阻塞发送（单测：慢消费者）

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|---------|
| UC-0009 | 慢消费者下日志实时 | mock SSE 慢速发 4 帧（500ms/帧）；消费者处理每帧 `time.Sleep(300ms)` | `LLM ChatStream raw chunk` 日志**逐帧实时**（帧到达后 ~20ms 内出现），不被 eventCh 阻塞拖累 |
| UC-0010 | 事件不丢失 | 消费者 sleep 导致 eventCh 满；之后消费者恢复消费 | 所有事件最终都送达消费者（pending 队列补发），**无丢失** |
| UC-0011 | 事件顺序 FIFO | 快速发送多帧 + 消费者慢 | 消费者收到事件顺序与发送顺序一致 |
| UC-0012 | 缓冲增大缓解抖动 | eventCh 缓冲 1024；消费者间歇性慢（每 5 帧 sleep 1 次） | 读循环不阻塞，日志实时；事件顺序保持 |
