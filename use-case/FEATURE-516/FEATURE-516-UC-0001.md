# FEATURE-516 测试用例 — 图标矢量化（4 主题 + 暂停 + 主模型 + 视觉模型）

> 分支：FEATURE-516
> 版本：v0.55.0
> 关联任务：FEATURE-516
> 关联特性/缺陷：FEATURE-477（主题体系 dark/light/light-tp/paper 与顶栏 logo）、FEATURE-445（`#scrollDownBtn` 内联 SVG 的既有范式）、FEATURE-487（状态条仅保留 🧠/👀 图标）

## 背景

现有图标大量使用 **Unicode 字符与 emoji**（`☾ ☀ ♤ ☕︎ ⏸ 🧠 👀`），其字形由操作系统与浏览器选用的字体决定：

- 同一字符在 Windows / macOS / Linux 下可能落到不同字体（如 `⏸` 在部分环境由彩色 emoji 字体渲染，在另一些环境由单色符号字体渲染），表现为**大小、粗细、基线、颜色**差异；
- 彩色 emoji（🧠/👀）无法继承 `color`，在 4 个主题下无法随主题文字色变化；
- 字形基线由字体决定，与相邻文字对齐容易出现偏移。

本次把以下 7 个图标改为**矢量（内联 SVG sprite + `currentColor`）**，几何由路径定义、颜色继承主题文字色，从而保证跨系统/跨浏览器一致并可随主题自动变色：

| # | 图标 | 语义（用户确认） | 现有实现 |
|---|------|------------------|----------|
| 1 | 主题-暗色 | 月亮 | `☾`（`app.js themeIcon()`） |
| 2 | 主题-亮色 | 太阳 | `☀` |
| 3 | 主题-tp | 黑桃（矢量重绘，延续现有识别符号） | `♤` |
| 4 | 主题-护眼 | 叶片 / 植物 | `☕︎` |
| 5 | 暂停键 | 双竖线 | `⏸`（`sendBtn`） |
| 6 | 主模型 | 大脑 | `🧠`（`index.html .mi-ico`、状态条） |
| 7 | 视觉模型 | 眼睛 | `👀`（状态条） |

## 验收标准

- 7 个图标全部以矢量（`<svg>` + `<use>` 引用 `<symbol>`）渲染，DOM 中**不再出现**上述字体字符/emoji 作为图标内容。
- 图标颜色使用 `currentColor`：在 dark / light / light-tp / paper 四个主题下随所在元素文字色变化，无需为每个主题单独配色。
- 同一图标在 4 个主题、以及不同字号（如 12/14/16/24px）下均无模糊、无形变，宽高严格等于设定值。
- 主题切换按钮显示与当前主题一致的图标；切换主题后按钮图标同步更新。
- 发送按钮空闲态为发送图标、运行态为双竖线暂停图标，切换正常且可中断。
- 模型管理菜单与状态条的主模型图标为矢量大脑；状态条视觉模型图标为矢量眼睛。
- `go build ./... && go vet ./...` 通过；`node --check web/static/app.js` 通过。

## 运行时用例

### UC-0001 预览页 7 个图标全部以矢量渲染（核心）

**前置条件**
- 打开预览页（`work/icons-preview.html` 或经 `--serve --port <port>` 提供）。

**步骤**
1. 打开预览页，查看 7 个图标区域。
2. 用开发者工具检查任一图标节点的 DOM 结构。

**预期**
- 7 个图标全部可见，形状分别为：月亮、太阳、黑桃、叶片、双竖线、大脑、眼睛。
- 每个图标的 DOM 为 `<svg class="ico">…<use href="#i-xxx">…</svg>`，**不是**文本节点（`☾ ☀ ♤ ☕ ⏸ 🧠 👀`）。
- 页面中不存在因字体缺失而出现的「豆腐块」（□/▯）或空白占位。

### UC-0002 暗色主题图标 = 月亮，且颜色继承主题文字色（核心）

**步骤**
1. 在预览页把主题切到 `dark`。
2. 观察第 1 个图标（暗色/月亮）的颜色。

**预期**
- 图形为月牙（月亮）形状，可辨识。
- 图标颜色与所在行的文字颜色一致（同为 `currentColor` 解析值），暗色主题下为浅色（`#d5dbe7` 一类）。
- 图标不呈现彩色 emoji 效果（无双色/渐变色块）。

### UC-0003 亮色主题图标 = 太阳，且颜色继承主题文字色

**步骤**
1. 主题切到 `light`，观察第 2 个图标（亮色/太阳）。

**预期**
- 图形为太阳（圆形 + 光芒/放射线）形状。
- 颜色随主题文字色变为深色（`#1d2433` 一类），在浅底上清晰可辨。

### UC-0004 tp 主题图标 = 黑桃，且颜色继承主题文字色

**步骤**
1. 主题切到 `light-tp`，观察第 3 个图标。

**预期**
- 图形为黑桃（♠ 形）矢量重绘，轮廓平滑无锯齿，与旧 `♤` 的识别意象一致（一眼可认出是"扑克黑桃"）。
- 颜色随主题文字色变化（继承 `currentColor`），与旧实现（字体字符固定字形）不同，可随主题着色。

### UC-0005 护眼主题图标 = 叶片，且颜色继承主题文字色

**步骤**
1. 主题切到 `paper`，观察第 4 个图标。

**预期**
- 图形为叶片/植物形态（叶身 + 主脉），轮廓柔和，符合"护眼"语义。
- 颜色随主题文字色变化（paper 主题下为暖棕色 `#4a3b2a` 一类）。

### UC-0006 主题切换按钮：4 个主题下显示对应图标（核心）

**前置条件**
- `co-shell --serve --port <port>` 启动，浏览器打开页面。

**步骤**
1. 依次把主题切换为 dark → light → light-tp → paper。
2. 每次切换后查看顶栏右侧主题切换按钮（`#themeToggle`）。

**预期**
- 按钮内的图形依次为：月亮、太阳、黑桃、叶片。
- 四个图标均为矢量（`<svg>`），不是字体字符。
- 四个图标尺寸一致（同为 16px 或设定的同一尺寸），按钮不因图标切换而发生宽度跳动。

### UC-0007 切换主题后按钮图标同步更新（核心）

**步骤**
1. 在设置面板中把主题模式从固定主题改为 `auto`。
2. 触发系统外观变化（或模拟 `prefers-color-scheme` 变化）。

**预期**
- `auto` 解析为 dark 时按钮显示月亮、解析为 light 时显示太阳。
- 图标更新即时，无需刷新页面；图标颜色同步随主题文字色变化。

### UC-0008 发送按钮空闲态/运行态图标切换（核心）

**步骤**
1. 页面空闲（无运行中回合）时查看输入行右侧按钮（`#sendBtn`）。
2. 发送一条消息，等待回合开始运行。

**预期**
- 空闲态：显示发送图标（向上箭头或三角形，沿用现有 ▶ 语义），为矢量。
- 运行态：显示**双竖线**暂停图标（两条等宽竖线），为矢量，颜色变为运行态配色（红色系）。
- 两态切换无残留字符、无重叠、按钮尺寸不变。

### UC-0009 中断后按钮回到发送图标（回归）

**步骤**
1. 在运行态点击暂停按钮触发中断。
2. 等待回合结束。

**预期**
- 回合结束后按钮恢复为发送图标。
- 中断行为与既有实现一致（点击即中断，事件流出现中断标记）。

### UC-0010 模型管理菜单主模型图标为矢量大脑

**步骤**
1. 打开顶栏「模型管理」菜单（`.mi-ico`）。

**预期**
- 该菜单项的图标为矢量大脑（`<svg>`），不是 emoji 🧠。
- 图标颜色随菜单文字色变化，在 4 个主题下均可辨识。

### UC-0011 状态条主模型图标为矢量大脑

**前置条件**
- 状态条已开启（`showStatus`）。

**步骤**
1. 查看底部状态条的主模型区域（`#sbModelText`）。

**预期**
- 主模型图标为矢量大脑，其后紧跟模型名与占用率文本。
- 点击该区域仍可打开模型切换（既有交互回归）。
- 鼠标悬停时图标与文字一并变色（继承 `currentColor`）。

### UC-0012 状态条视觉模型图标为矢量眼睛（有视觉能力时）

**步骤**
1. 切换到支持视觉能力的模型。
2. 查看状态条视觉模型区域（`#sbModelVision`）。

**预期**
- 视觉模型图标为矢量眼睛，后续为模型名与占用率文本。
- 无视觉能力时该区域隐藏或按既有逻辑降级，不出现孤立图标。

### UC-0013 图标在不同字号下缩放不模糊、尺寸精确（核心）

**步骤**
1. 在预览页把图标尺寸依次设为 12 / 14 / 16 / 24 / 48px。
2. 放大观察边缘，并测量渲染尺寸。

**预期**
- 各尺寸下边缘均平滑锐利（矢量重绘），无位图放大造成的模糊或锯齿。
- 实测宽高严格等于设定值（误差 0px），不随字体 `line-height` 抖动。
- 4 个主题下同一尺寸的图标外接框一致。

### UC-0014 图标与相邻文字基线对齐、无垂直偏移

**步骤**
1. 查看状态条「🧠 模型名」与「👀 模型名」两组文字，以及模型管理菜单项。
2. 放大截图比对图标中心与文字视觉中心。

**预期**
- 图标与相邻文字垂直居中对齐，无上下偏移。
- 图标与文字间距均匀，不出现"图标沉底"或"图标顶格"。

### UC-0017 深色/浅色下图标对比度可辨识，不出现"描边消失"（边界）

**步骤**
1. 在 dark 主题与 light 主题下分别查看 7 个图标。

**预期**
- 线描类图标（月亮/太阳/黑桃/叶片/大脑/眼睛）在深浅两种背景下均可清晰辨认轮廓。
- 不出现描边与背景同色导致图形"消失"的情况（若采用 stroke 绘制，stroke 必须为 `currentColor`）。

### UC-0018 页面无控制台报错，图标 sprite 只加载一次（性能/回归）

**步骤**
1. 打开页面，查看开发者工具 Console 与 Network。

**预期**
- Console 无报错（尤其无 `use` 引用不存在的 `symbol` 导致的告警、无 404）。
- 图标 sprite 随 HTML 内联（或作为单个静态资源请求一次），不出现每个图标一次网络请求。

## 静态用例

### UC-0015 代码中不再以字体字符/emoji 作为这 7 个图标

**步骤**
1. 对前端资源执行检索：

```bash
# 以下字符不应再作为「图标内容」出现（注释/文档中的说明性提及不算）
grep -n '☾\|☀\|♤\|☕\|⏸\|▶\|🧠\|👀\|👁' web/static/app.js web/static/index.html
```

2. 逐一核对命中行的用途。

**预期**
- `themeIcon()` 不再返回字符，而是返回 icon id（如 `i-theme-dark`）供 `<use>` 引用。
- `sendBtn` 不再以 `textContent = "⏸"/"▶"` 切换图标。
- `.mi-ico`（模型管理）与状态条 `#sbModelText` / `#sbModelVision` 不再输出 emoji 字符。
- 允许保留：注释中的历史说明、`i18n/*`（本次不涉及 CLI 文案）。

### UC-0016 非本次范围的 emoji（CLI/i18n 文案）不受影响（回归）

**步骤**
1. 检查 `i18n/zh.go`、`i18n/en.go` 中的 `👁` 文案。
2. 运行 CLI 命令 `:model`（或对应列出视觉模型的分支），查看输出。

**预期**
- CLI 文案中的 emoji 保持原样（本次只改 Web UI 图标，不动 CLI 文案）。
- `go test ./i18n/ -short` 通过。

## 备注

- 预览页与集成实测必须使用 `--serve` 启动，避免自动打开的系统浏览器占用 WebSocket 单客户端连接。
- 图标统一 `viewBox="0 0 24 24"`，线描图标 `stroke="currentColor"` + `fill="none"`，实心图标 `fill="currentColor"`；`stroke-width` 统一（建议 1.8~2），保证 7 个图标视觉重量一致。
