# FEATURE-624 UC-0001：ask_user 表单「一屏一题」逐题独立界面（进度可感知）

> 分支：**FEATURE-624**　版本：**v0.107.0**　BUILD：**1271**
> 需求（用户 2026-10-09 21:52 提出）：
> ① 每个问题**单独成一个独立界面**，回答完单独一题后再显示下一题；
> ② 界面做好**问题总数**与**已完成问题数**的表示；
> ③ 改善观感，使用户判断「总题数」和「答题进度」更方便、直观。
>
> 现状（问题）：`web/static/app.js::renderQuestions()`（FEATURE-512）一次性创建**全部** `.qs-card` 并全部 append 到 `askInteraction`，所有题目**同时可见**（只有非当前题的热键/提示行被隐藏）；题目一多列表很长，用户看不出总共几题、自己答到第几题。提交按钮只在最后一题显示。本次改造**不改后端协议**（`kind:"questions"` 的 payload 与 `answers` 回传格式不变），只改前端呈现与交互。

## 术语

- **逐题视图**：ask 区域内**只显示当前题**（active question），其余题的卡片不占位、不可见。
- **进度标示**：显式展示「第 N 题 / 共 M 题」+「已完成 X / M」+ 进度条（宽度 = X/M）。
- **已完成题**：沿用现有口径 —— 该题 `selected.size > 0` 或自由文本非空（见 `refreshSubmit`）。
- **N / M**：N = 当前题序号（1-based），M = 题目总数。
- `(M)` = 需 `--serve` 隔离实例 + 调试浏览器运行时断言；`(R)` = 离线静态校验。

## 设计基线（本次实现基准，供确认）

| 项 | 设计 |
|----|------|
| 进度区 | 表单顶部新增 `.qs-progress`：左「第 N 题 / 共 M 题」，右「已完成 X / M」，下方细进度条 `.qs-progress-bar > .qs-progress-fill`（宽度 X/M） |
| 一屏一题 | 非当前题 `.qs-card` 加 `.qs-off`（`display:none`），当前题可见；切题时当前题播放轻微淡入（`.qs-enter`，动画结束自动移除类） |
| 推进方式 | 沿用现有键盘/点击语义：单选点击后自动前进；多选需 Enter/「下一题」；Enter = 下一题（末题 = 提交）；「+」= 上一题；空格 = 备注；「-」= 取消；数字 1..9 = 选第 n 项 |
| 进度刷新 | 切题与答题时实时刷新进度区（含进度条宽度） |
| 单题表单 | M = 1 时进度区显示「第 1 题 / 共 1 题」，提交按钮直接可见 |
| 回退 | 保留「上一题」能力，回退后已答内容与进度不回退（已完成数只增不减，除非取消选择） |

## 用例清单

### UC-01 (M) 进入表单时只显示第 1 题

- 前置：3 题（`it.questions.length === 3`）。
- 断言：`askInteraction` 内 `.qs-card` 数量 = 3；其中 `getComputedStyle(el).display !== "none"` 的数量 = 1，且该可见卡片对应第 1 题；其余 2 张 `display === "none"`。

### UC-02 (M) 初始进度标示正确

- 断言：`.qs-progress` 存在且文本含「第 1 题」「共 3 题」（en：`Question 1 / 3`）；已完成数显示 `0`；`.qs-progress-fill` 宽度为 0%。

### UC-03 (M) 单选点击后自动切到第 2 题

- 步骤：点击第 1 题的某个单选选项。
- 断言：第 1 题 `display:none`、第 2 题可见；进度变为「第 2 题 / 共 3 题」；已完成数 = 1；进度条宽度 ≈ 33%。

### UC-04 (M) 多选不自动前进，Enter 才前进

- 步骤：第 2 题（`multi:true`）点选 1 个选项。
- 断言：**仍停在第 2 题**（不自动前进）；进度已完成数 +1。按 Enter 后切到第 3 题。

### UC-05 (M) 自由文本题 Enter 前进并计入完成

- 步骤：在某自由文本题输入文本，按 Enter。
- 断言：切到下一题；已完成数 +1；该题 `text` 保留。

### UC-06 (M) 必填未答时提交被拦截并跳回该题

- 步骤：不答必填第 1 题，走到底部点「确定」。
- 断言：**不发出** submit；第 1 题卡片出现 `.qs-missing`；视图自动切回第 1 题；`.qs-warn` 文本含 `Q1`。

### UC-07 (M) 末题显示提交按钮，提交回传全部答案

- 断言：处于第 3 题时 `.qs-submit` 可见（前两题时隐藏）；点击后 `answerInteraction` 发出 `action:"submit"`，`answers` 长度 = 3、顺序与题目一致，且含 `question/selected/notes/text` 字段。

### UC-08 (M) 「上一题」回退保留已答内容

- 步骤：从第 3 题按 `+` 回退到第 2 题。
- 断言：第 2 题可见且原选中的选项仍为 `on`；进度显示「第 2 题 / 共 3 题」；已完成数不因回退而减少。

### UC-09 (M) 键盘快捷键全部仍可用

- 断言：数字键 1..9 选中对应选项；Enter 前进/提交；`+` 上一题；空格打开备注；`-` 取消整个表单。均与改造前一致。

### UC-10 (M) 备注输入与上报

- 步骤：点某选项的「补充说明」（或长按该选项），输入备注。
- 断言：备注框展开并可输入；提交时 `answers[i].notes` 含 `{option, note}`。

### UC-11 (M) 通答题全流程进度一致

- 步骤：逐题作答直至提交，每步读取进度区。
- 断言：每一步 `.qs-progress` 显示的 N / X / M 与实际 `activeQ+1` / 已完成数 / 总数一致（无跳变、无滞后）。

### UC-12 (M) 单题表单边界（M = 1）

- 断言：只显示第 1 题；`.qs-submit` 直接可见可点；提交 `answers` 长度 = 1；进度区显示「第 1 题 / 共 1 题」。

### UC-13 (M) 取消/固定键仍可用

- 步骤：按 `-`（或点底部固定键，如"再想想/暂不"）。
- 断言：`answerInteraction` 发出 `action:"select"` 且 value 为该键 value；表单区域停止交互（不残留可点选项）。

### UC-14 (M) 切题观感（无残留、无裁切）

- 断言：连续切题后，可见 `.qs-card` 恒为 1 张（无两张同时可见的闪烁残留）；当前题在 ask 区域内可完整看到标题、选项与提示行；切换动画类 `.qs-enter` 在动画结束后被移除（不长期残留在 DOM 上）。

### UC-15 (M) 中英文进度文案

- 断言：`lang=zh` 显示「第 N 题 / 共 M 题」「已完成 X 题」；`lang=en` 显示对应英文；界面无 `%d` 等占位符残留。

### UC-16 (M) 刷新/历史重放不受影响

- 断言：刷新页面后重放历史消息不会出现常驻的 `.qs-progress`；已提交答案的气泡仍正常显示（`answersAsText` 格式不变）。

### UC-17 (R) 静态校验

- 断言：`node --check web/static/app.js` 通过；`go build ./... && go vet ./... && go test ./...` 全绿。
