# FIX-594 UC-0001：前端 CPU 占用优化（hub 聚合页 + 流式渲染 + 长历史滚动）

> 分支：**FIX-594**　版本：**v0.92.1**
> 判定口径：修复后，**长历史会话的缓慢滚动**与**流式输出**两个场景下，前端主线程每帧成本与长任务显著下降；hub 聚合页不再因 busy 状态点动画而持续满载合成；**行为与视觉保持不变**。
> 判定方式：Chrome 基线的函数级 / 帧级实测对比（修复前基线见下表）+ 静态检查 + Go 编译与测试。

## 背景（改前实测基线）

| 场景 | 指标 | 改前实测 | 测量方式 |
|---|---|---|---|
| 空闲（单页 Web UI） | CPU / 长任务 | 0.0%，6s 零长任务 | Chrome + `top`/`ps` |
| 长历史滚动（748 块） | 每帧 follow-scroll 强制布局 | 0.8 ms | 页面内受控实验 |
| 长历史滚动（748 块） | blockNav 全量扫描 | 0.48 ms/次（O(块数)） | 页面内受控实验 |
| 流式渲染（60KB 消息） | 单次 mdRender（全量重建 DOM） | 3.8 ms / 6555 节点 | 离屏容器实测 |
| `#streamB` 样式 | contain / content-visibility | `none` / `visible` | `getComputedStyle` |
| hub 页面（有 busy 实例） | WebKit.GPU / WindowServer | 平均 100% / 51~58% | `ps`/`top` 多次采样 |
| 页面 rAF 帧率 | 帧率 | 120 Hz | 页面内探针 |

根因位置（改前）：

- hub：`hub/gateway/webui_static.go:237`（`stBreath` 关键帧含 `box-shadow`，无限动画）、`:1124`（`ensureFrame()` 每实例建 iframe 并永久缓存不销毁）、`:917`（`setInterval(refresh, 3000)` 轮询 + `innerHTML` 全量重建）
- Web UI：`web/static/md.js:18`（每次 `textContent=""` 全量重建整条消息 DOM）、`web/static/app.js` `renderMdNow → scrollStream()`（读 `scrollHeight` 强制同步布局）、`app.js` `MD_TIERS`（≤4096 字符 `minIntervalMs=0` → 每帧渲染）、`app.js` `updateBlockNav`（每次滚动遍历**所有** `.ev` 读 `offsetTop/offsetHeight`）、`web/static/style.css`（`#streamB` 无布局/绘制隔离）

## 用例

- **A 长历史滚动 · 每帧成本（浏览器实测，主判定）**
  构造 ≥300 块的长会话，程序化以固定速率上下滚动 5s；测量滚动期间 `longtask` 数量/总时长与每帧强制布局耗时。
  **通过条件**：相比修复前基线，滚动期间长任务总时长与每帧成本下降 ≥50%，且滚动过程中不出现 >50ms 的长任务。

- **B `updateBlockNav` 不再全量遍历（静态 + 运行时）**
  修复后 `updateBlockNav` 不得对全部 `.ev` 逐个读 `offsetTop/offsetHeight`（改为按可见区/缓存高度计算或仅处理邻近块）。
  **通过条件**：单次耗时不随块数线性增长——100 块与 300 块的单次耗时比值 < 1.5（改前 ≈ 6 倍）。

- **C 布局/绘制隔离生效（静态 + 运行时）**
  `.ev`（或滚动容器）具备 `content-visibility:auto` + `contain-intrinsic-size`，或 `contain: layout paint style`。
  **通过条件**：`getComputedStyle` 断言生效；滚动时 layout 时长相比基线明显下降。

- **D 流式渲染每帧成本（浏览器实测）**
  模拟一条持续增长的消息（0→60KB，逐帧追加），测量每帧渲染成本。
  **通过条件**：不再每帧全量重建整条消息 DOM（同长度文本重复渲染不整体重排），每帧成本相比基线下降 ≥50%。

- **E 流式渲染正确性回归**
  流式期间与结束后，消息文本/代码块/表格/链接的渲染结果与修复前逐字符一致；THINK 固定高度、SUP 块、折叠/展开、复制行为不变。

- **F hub · busy 动画合成友好（静态 + 实测）**
  `.agent .st.busy` 的 `@keyframes` 不再包含 `box-shadow`（仅用 `transform`/`opacity` 等合成属性），或动画仅在抽屉可见时运行。
  **通过条件**：hub 页面存在 busy 实例时，`WebKit.GPU` 不再长期贴近 100%，`WindowServer` 占用明显低于基线。

- **G hub · 非激活 iframe 降载（运行时）**
  切换到 agent B 后，agent A 的 iframe 不再继续执行渲染重活（销毁/重建，或显式暂停其渲染与高频更新）。
  **通过条件**：多实例同时流式时，整体 CPU 不再随"已打开实例数"线性增长。

- **H hub · 轮询增量更新（静态 + 运行时）**
  `refresh()` 不再无条件 `innerHTML=''` 全量重建列表。
  **通过条件**：agent 列表无变化时不重建 DOM（`MutationObserver` 计数为 0 次列表重建）。

- **I 交互响应回归**
  长会话下翻页、选中工作区文件、打开菜单的响应明显改善且功能无回归（点击/选中/展开/预览均正常）。

- **J 编译与静态检查**
  `go build ./... && go vet ./...` 通过；`node --check web/static/app.js web/static/md.js` 通过；改动的 Go 文件 `gofmt -l` 无输出。

- **K 回归测试集**
  `go test ./... -short` 的失败集为 `main` 基线失败集的子集（零新增失败）。
