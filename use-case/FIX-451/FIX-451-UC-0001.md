# FIX-451 测试用例：修复 path 参数缺失 bug（LLM 将参数误嵌套进 meta 对象）

## 背景

用户报告 search_files 等带 path 参数的工具，即便 LLM 传了 path 参数，也会报 "path argument is required"。

**根因**：LLM 生成工具参数时，偶尔会把 path、regex 等工具参数错误地嵌套在 meta 对象内部（OpenAI 模式 JSON 或 XML 模式），导致解析后 `args["path"]` 不存在（path 成为 `args["meta"]["path"]`），`searchFilesTool` 的 `args["path"].(string)` 断言失败。

**修复**：在 `executeToolCall` 解析 args 后调用 `promoteMisplacedMetaParams(args)`，将 meta 内部误放的工具参数（非 intent/risk/risk_reason/affected_objects/progress 的键）自动提升到顶层。

## 测试用例

### UC-0001：meta 内部误放的 path/regex 被提升到顶层

- **前置**：无
- **操作**：构造 args，其中 path 和 regex 嵌套在 meta 内部，调用 `promoteMisplacedMetaParams`
- **预期**：path 和 regex 被提升到顶层；intent/risk/risk_reason/affected_objects/progress 仍保留在 meta 内部
- **验证**：`TestPromoteMisplacedMetaParams` Case 1 通过

### UC-0002：顶层已存在的参数不被 meta 内部覆盖

- **前置**：无
- **操作**：构造 args，顶层已有 path，meta 内部也有 path，调用 `promoteMisplacedMetaParams`
- **预期**：顶层 path 保持不变（顶层优先）
- **验证**：`TestPromoteMisplacedMetaParams` Case 2 通过

### UC-0003：无 meta 对象时 no-op

- **前置**：无
- **操作**：构造不含 meta 的 args，调用 `promoteMisplacedMetaParams`
- **预期**：args 不变
- **验证**：`TestPromoteMisplacedMetaParams` Case 3 通过

### UC-0004：executeToolCall 集成验证（OpenAI 模式 JSON）

- **前置**：无
- **操作**：构造 `tc.Arguments` 为 JSON，其中 path 嵌套在 meta 内部，调用 `executeToolCall`
- **预期**：searchFilesTool 能正确获取 path，不再报 "path argument is required"
- **验证**：executeToolCall 中 `promoteMisplacedMetaParams(args)` 在 args 解析后、工具执行前被调用

### UC-0005：编译与全量测试

- **前置**：无
- **操作**：运行 `go build ./... && go vet ./... && go build -o work/co-shell .` 和 `go test ./... -short`
- **预期**：编译通过，全量测试通过
- **验证**：BUILD-715 编译成功，agent 包测试通过
