# FIX-341: show-parse-error-raw 未覆盖 OpenAI 模式 JSON 解析错误路径

## 背景

`show-parse-error-raw` 开关（FEATURE-336 [BUILD-378]）的设计目标是：工具调用解析失败时在用户界面显示原始报文，便于诊断。但实测发现 OpenAI 模式下 LLM 返回参数 JSON 不完整时（如 write_to_file 的 `arguments` 为空对象 `{}`），控制台仅输出：

```
[⚠️ ]  工具 write_to_file 调用无效（parse-error-action=retry）: cannot parse tool arguments: unexpected end of JSON input
已丢弃无效调用并重新发送。
```

开关已开启却**没有打印原始工具参数报文**，与 XML 模式的显示行为不一致。

## 根因

`agent/run_stream.go` 中 `ShowParseErrorRaw` 的显示逻辑只加在 **XML 解析错误分支**（第 644/720 行，数据来源 `taskInstructionCache` 的 `raw` 字段），未覆盖 **OpenAI（非 XML）模式工具执行失败分支**（第 1074-1093 行 FIX-314/FIX-317 分支）。该分支中 `tc.Arguments`（LLM 返回的原始工具参数 JSON）完全可获取，但从未被显示。

## 修复方案

在 `agent/run_stream.go` 中提取统一辅助函数 `emitParseErrorRaw(cb, rawDetail)`，三处调用点统一复用：
1. XML 分支 exit action（原第 644 行内联逻辑）
2. XML 分支 retry/prompt（原第 720 行内联逻辑）
3. **OpenAI JSON 解析错误分支（新增，rawDetail = tc.Arguments）**

复用 `i18n.KeyXMLParseErrorRaw`（zh: `解析错误原始报文:\n%s\n`），不新增 i18n key。

## 用例

| 编号 | 场景 | 操作 | 预期结果（修复后） | 修复前行为 |
|------|------|------|-------------------|-----------|
| UC-0001 | OpenAI 模式 JSON 参数解析失败 + 开关开启 | `:set show-parse-error-raw on`，LLM 返回 write_to_file 调用且 `arguments` 为 `{}` | 显示 `工具 write_to_file 调用无效...` 摘要 **之后**，紧跟 `解析错误原始报文:` + `{}` | 只显示摘要，无原始报文 |
| UC-0002 | OpenAI 模式 JSON 参数解析失败 + 开关关闭 | `:set show-parse-error-raw off`，重复 UC-0001 | 只显示摘要，不显示原始报文 | 同左（无变化） |
| UC-0003 | OpenAI 模式 JSON 参数解析失败 + 原始参数为空串 | 开关开启，`tc.Arguments == ""` | 不显示原始报文（空串不输出） | 同左（无变化） |
| UC-0004 | XML 模式解析错误回归 | 开关开启 + XML 模式 parse error | 仍然显示原始报文（与原行为一致） | 显示（无回归） |
| UC-0005 | OpenAI 模式参数校验失败（missing required）| 开关开启 + LLM 返回缺参数但 JSON 语法合法的调用 | 显示错误摘要后输出 `解析错误原始报文:` + 原始参数 JSON | 无原始报文（仅结构化错误回灌） |
| UC-0006 | parse-error-action=exit 分支也显示原始参数 | `:set parse-error-action exit` + OpenAI 模式工具失败 | 报错退出前显示原始参数 | 无原始报文 |
