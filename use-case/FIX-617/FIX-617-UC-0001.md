# FIX-617 验收测试用例（UC-0001）：文件树 `git status` 不再持 `.git/index.lock`

> 权威依据：`ROADMAP.md` v0.102.1 / FIX-617；分支 **FIX-617**，版本 **v0.102.1**（FIX 走 patch 递增）。
> 相关代码：`web/server.go` 的 `gitStatusMap()`（`server.go:1292`）与 `handleTree()`（`server.go:1244`）。

> 问题（已取证）：`gitStatusMap()` 执行 `git status --porcelain -z`，该命令**默认会刷新并回写 index**（git 的“可选锁”），实测每次持 `index.lock` 约 **6.9–10.2ms**，占其运行时长的 **44.7%**；它由 `GET /api/tree` 每请求调用，而前端一次工作区刷新会发出 **1+N** 次 `/api/tree`（N＝展开的目录数），因此与并发的 git 写操作（`add/commit/merge/tag`）频繁撞锁，报 `fatal: Unable to create '.git/index.lock': File exists`。

> 已确认决策（用户选定）：**只做【首选·最小改动】**——让文件树刷新不再写 index：把该处调用改为
> `git --no-optional-locks status --porcelain -z`（等价于 `GIT_OPTIONAL_LOCKS=0`）。
> 实测（探针 B/C'）该项可把撞锁归零，且 `status` 输出不受影响。

> 本次不做（范围外）：`gitStatusMap` 结果 TTL 缓存、超时改 SIGTERM、主动清理残留锁。

## 实现要点（预期）

- `web/server.go` `gitStatusMap()`：`exec.CommandContext(ctx, "git", "status", "--porcelain", "-z")`
  → `exec.CommandContext(ctx, "git", "--no-optional-locks", "status", "--porcelain", "-z")`。
- **为什么用 `--no-optional-locks` 而不是 `cmd.Env` 加 `GIT_OPTIONAL_LOCKS=0`**：环境变量方式在父环境已存在同名变量时会出现重复键（`getenv` 取首个匹配），存在“设了不生效”的隐患；命令行开关无此歧义，且本地自解释。
- 不改动其它 4 处 git 调用（`git diff` / `git log` / `git rev-parse`，均为只读、不写 index）；不改动 3s 超时与 `.git` 存在性守卫。

## 用例详情

### A. 静态断言（`web/fix617_test.go`，读 `server.go` 断言）

**A-001 命令行含 `--no-optional-locks`**
- 断言：`web/server.go` 中 `gitStatusMap` 的 `exec.CommandContext` 参数序列为
  `"git", "--no-optional-locks", "status", "--porcelain", "-z"`。

**A-002 其余只读调用未动**
- 断言：`git diff --`、`git log -1 --format=%H --`、`git rev-parse --verify` 三处仍以 `"git"` 为首参（未插入新开关）。

### B. 锁行为对照实测（探针脚本，运行时）

**B-001 `index.lock` 出现次数对照**
- 步骤：在真实仓库用 0.2ms 采样器监视 `.git/index.lock`，分别并发执行 20 次
  ① `git status --porcelain -z`（旧）与 ② `git --no-optional-locks status --porcelain -z`（新）。
- 断言：① 出现次数 **> 0**（基线，实测 21）；② 出现次数 **= 0**。

**B-002 与写入者的碰撞率对照**
- 步骤：临时仓库中，轮询者分别用 ①/② 命令持续运行，同时反复执行 `git commit --allow-empty`，统计含 `index.lock` 的失败次数。
- 断言：轮询者用 ① 时失败次数 **> 0**（基线，实测 149/408）；用 ② 时失败次数 **= 0**。

### C. 功能与边界回归（单测）

**C-001 解析结果不变**
- `go test ./web/ -run TestGitStatusMap` 通过（覆盖 M/A/D/R/U 与 clean 树）。

**C-002 非仓库 / 无 git**
- 非 git 目录 → `gitStatusMap` 返回 nil；`PATH` 中无 `git` → 返回 nil 且不 panic。

**C-003 超时保护不变**
- `go test ./web/ -run TestGitStatusMapTimeout` 通过（fake 慢 git，3s 内返回 nil）。

**C-004 运行时文件树回归**
- 隔离实例打开 Web UI：展开/收起目录、修改一个工作区文件后刷新，断言徽标（M/A/D/U）与目录变更计数仍正确。

### D. 端到端回归（运行时）

**D-001 刷新期间不再撞锁**
- 步骤：隔离实例下连续触发工作区刷新（多次 `GET /api/tree`，含 `?path=` 分层请求），期间并发执行 `git commit`/`git add`。
- 断言：命令行不再出现 `Unable to create '.../index.lock': File exists`。

### E. 输出一致性（运行时对照）

**E-001 `statusMap` 逐项一致**
- 步骤：同一临时仓库、同一工作区状态下，分别用旧命令与新命令生成状态映射。
- 断言：两者 map 内容逐项相等（键集合与状态码完全一致）。
