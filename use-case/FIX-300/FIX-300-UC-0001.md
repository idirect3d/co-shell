# FIX-300 `:set defaults` 时自动重命名 mode 留存目录，恢复默认系统提示词

## 基本信息

| 项目 | 内容 |
|------|------|
| 任务编号 | FIX-300 |
| 任务名称 | `:set defaults` 时自动重命名 mode 留存目录，恢复默认系统提示词 |
| 类型 | Bug 修复 (Fix) |
| 版本 | v0.6.0 |
| 作者 | L.Shuang |

---

## 背景

`work/mode/{mode}/IDENTITY.md` 等内容（FEATURE-299 引入 `{AGENT_PRINCIPLES}` 占位符之前创建）不包含占位符，导致 `buildSectionWithPlaceholders` 无法替换，principles 被静默丢弃；act 模式因无自定义 IDENTITY.md 正常，plan/research 等自定义 mode 受影响，且用户对留存配置的存在无感知。

**修复思路**：`handleSetDefault()` 在参数重置并保存 config.json 后，扫描运行目录 `{cwd}/mode/` 下与已知 mode 名（内置 act/plan/research + cfg.WorkModes 用户自定义）同名的目录，列出清单后经用户 y/n 确认，将目录重命名为 `原名.YYYYMMDD`（冲突追加序号），使系统提示词自然回退到 i18n 默认模板。重命名失败不阻断参数重置，仅汇总报告。

---

## 测试环境

- Go 1.22+
- 单元测试：`go test ./cmd/ -run TestSetDefaultsModeDirs`
- 源码编译：`go build ./...`

## 测试用例

### UC-0001: 命中已知 mode 名的目录被列入重命名清单

**描述**：运行目录存在与已知 mode 名（act/plan/research 或用户自定义）同名的目录时，应列入待重命名清单。

**验证方法（单元测试）**：
- 在临时目录创建 `mode/research/`、`mode/plan/`、`mode/act/` 子目录
- 已知 mode 名集合 = {act, plan, research}
- 调用收集函数
- 断言：清单包含 3 项 `research → research.20260101`、`plan → plan.20260101`、`act → act.20260101`（dateStr 参数固定为 `20260101`）

**预期结果**：3 个目录均被列入清单，新名格式为 `原名.YYYYMMDD`。

---

### UC-0002: 非已知 mode 名目录不被误伤

**描述**：与已知 mode 名不同的目录（如 act_old、claim、research.v0、account.v0 等历史存档）不应出现在清单中。

**验证方法（单元测试）**：
- 在临时目录创建 `mode/act_old/`、`mode/claim/`、`mode/research.v0/` 目录
- 已知 mode 名集合 = {act, plan, research}
- 调用收集函数
- 断言：清单为空

**预期结果**：非 mode 名目录全部跳过，不被误伤。

---

### UC-0003: 目标新名已存在时追加序号

**描述**：目标名 `原名.YYYYMMDD` 已存在时，应追加 `.1`、`.2`… 直到不冲突。

**验证方法（单元测试）**：
- 临时目录存在 `mode/research/`，且已存在 `mode/research.20260101/`
- 调用收集函数
- 断言：清单中 `research → research.20260101.1`

**预期结果**：冲突时自动追加序号，避免覆盖既有目录。

---

### UC-0004: 用户拒绝（n）时不重命名，参数重置仍生效

**描述**：列出清单后用户输入 n/y 之外表示拒绝时，目录不被重命名，但 `:set defaults` 的参数重置与保存仍正常完成。

**验证方法（交互/逻辑测试）**：
- 确认回调返回 false（用户拒绝）
- 断言：`os.Rename` 未被调用，目录仍在原位置
- 断言：`handleSetDefault` 仍然返回成功消息（参数重置不受影响）

**预期结果**：拒绝重命名不影响参数重置流程。

---

### UC-0005: 确认（y）后目录被重命名

**描述**：用户确认后，目录被重命名为 `原名.YYYYMMDD`。

**验证方法（单元测试）**：
- 在临时目录创建 `mode/research/`，内置 `IDENTITY.md`
- 确认回调返回 true
- 调用重命名逻辑
- 断言：`mode/research` 不存在，`mode/research.20260101/IDENTITY.md` 存在

**预期结果**：目录被移动，文件完整保留，用户可手动改回恢复。

---

### UC-0006: 重命名失败不阻断参数重置，仅在结果中报告

**描述**：单个目录重命名失败（如权限错误）时，流程继续处理其余目录，参数重置不受影响，失败项在返回消息中报告。

**验证方法（单元测试）**：
- 构造一个 rename 必定失败的条件（如目标路径非法）
- 断言：函数返回部分成功 + 失败项清单
- 断言：不向调用方返回 error（不阻断 handleSetDefault）

**预期结果**：部分失败可容忍，参数重置仍生效。

---

### UC-0007: 无 mode 留存目录时流程静默跳过

**描述**：运行目录下没有与已知 mode 名同名的目录时，不弹出确认、不改变任何文件，输出与现有行为一致。

**验证方法（单元测试）**：
- 临时目录无 `mode/` 或 `mode/` 下无匹配目录
- 断言：清单为空，确认回调不被调用，无文件变化

**预期结果**：完全静默，无副作用。
