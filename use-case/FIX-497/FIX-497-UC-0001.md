# FIX-497 测试用例

> 任务：Windows 下 co-shell 可执行文件 .exe 后缀未处理
> 分支：FIX-497
> 版本：v0.44.0

## 背景

hub 在 Windows 上执行时，系统找不到 PATH 路径下以及当前文件夹下的 co-shell.exe。原因是查找 co-shell 可执行文件时未考虑 Windows 上可执行文件带 .exe 后缀。

## 用例列表

### UC-001 defaultCoShellPath 在 Windows 上返回 .exe 后缀

- 前置：模拟 Windows 平台（runtime.GOOS == "windows"）
- 步骤：调用 `defaultCoShellPath()`，假设当前可执行文件位于 `C:\hub\co-shell-hub.exe`
- 预期：返回 `C:\hub\co-shell.exe`（带 .exe 后缀）
- 验证方式：单元测试（GOOS=windows 交叉编译测试）

### UC-002 defaultCoShellPath 在非 Windows 上返回无后缀

- 前置：模拟非 Windows 平台（runtime.GOOS == "darwin"/"linux"）
- 步骤：调用 `defaultCoShellPath()`，假设当前可执行文件位于 `/usr/local/bin/co-shell-hub`
- 预期：返回 `/usr/local/bin/co-shell`（无后缀）
- 验证方式：单元测试

### UC-003 ResolveCoShellPath 在 Windows 上查找 .exe

- 前置：模拟 Windows 平台，PATH 中包含含 co-shell.exe 的目录
- 步骤：调用 `ResolveCoShellPath("")`
- 预期：返回 PATH 中 co-shell.exe 的完整路径
- 验证方式：单元测试（GOOS=windows 交叉编译测试）

### UC-004 ResolveCoShellPath 在 Windows 上检查同目录 .exe

- 前置：模拟 Windows 平台，co-shell.exe 与 bridge 同目录
- 步骤：调用 `ResolveCoShellPath("")`
- 预期：返回同目录 co-shell.exe 的完整路径
- 验证方式：单元测试（GOOS=windows 交叉编译测试）

### UC-005 hub DefaultConfig 在 Windows 上默认 CoShellPath 带 .exe

- 前置：模拟 Windows 平台
- 步骤：调用 `hub.DefaultConfig()`
- 预期：`CoShellPath == "co-shell.exe"`
- 验证方式：单元测试（GOOS=windows 交叉编译测试）

### UC-006 编译验证

- 步骤：`go build ./... && go vet ./...`
- 预期：编译通过，无 vet 告警
- 验证方式：命令行执行

### UC-007 交叉编译 Windows 版本验证

- 前置：代码修改完成
- 步骤：`GOOS=windows go build ./...`
