# FIX-525 测试用例：hub 配置界面 co-shell 下拉「每次进入都重新扫描」

## 背景

co-shell-hub 的 Web UI 在「Agent 管理 → 新建 Agent」与「点卡片箭头 → 修改 Agent」两个界面里都有 co-shell 可执行程序下拉。用户把新编译的 co-shell 复制到被扫描目录（进程 CWD / PATH / hub 同目录）后，**不重启 hub、不刷新页面就选不到新版本**。

**本次根因（代码定位，非推测）**：

| 入口 | 位置 | 缓存行为 |
|---|---|---|
| 新建表单 | `hub/gateway/webui_static.go` `manageBtn.onclick` | `if (!defaultsLoaded) loadDefaults();` —— 整个页面生命周期只请求一次 `/api/agent-defaults` |
| 修改表单 | `hub/gateway/webui_static.go` `loadCoShellOptions()` | `if (coShellsCache){ cb(); return; }` —— 命中缓存即回调，不再请求后端 |

后端 `DetectCoShells()`（`hub/gateway/detect.go`）**每次请求都重新扫描目录**并逐个执行 `--version` 校验，无任何缓存 —— 即缺陷完全在前端，本次不需要改后端。

## 需求（用户确认）

1. 进入配置界面时（**新建**、**修改** 两个入口）都**重新搜索一遍**并刷新 co-shell 下拉列表。
2. **不额外增加手动「刷新」按钮**（仅进入表单时自动重扫）。
3. 版本 `0.59.1`（FIX，patch+1）；任务号 `FIX-525`；分支 `FIX-525`。

## 实现契约（需确认）

| 项 | 约定 |
|---|---|
| 新建表单触发点 | `manageBtn.onclick` → 每次都 `loadDefaults()`（去掉 `defaultsLoaded` 一次性门控） |
| 新建表单重扫接口 | `GET /api/agent-defaults`（原有端点，含 workspace/ID/端口默认值） |
| 修改表单触发点 | `showAgentEdit()` → `loadCoShellOptions()` 每次都请求 |
| 修改表单重扫接口 | `GET /api/co-shell-locations`（轻量：只重扫可执行文件，不重算 config 候选） |
| 失败降级 | 请求失败（`st >= 400` / 网络错误）时**保留上一次的候选列表**，不把下拉清空 |
| 已填字段保护 | 新建表单的 Workspace / ID / 端口仍只在**为空**时填充；co-shell 已选值在**仍被探测到**时保持选中 |
| 仍不存在的当前值 | 修改表单中「已配置但当前未探测到」的路径继续显示为 `<路径>（当前值）`，保存不丢失（FIX-521 行为不回归） |
| 涉及文件 | `hub/gateway/webui_static.go`（前端）；`main.go`、`cmd/co-shell-hub/main.go`（版本号） |
| 非目标 | 不做候选自动清理 / 排序调整；不做后端缓存；不加手动刷新按钮 |

## 验收前置（独立实例，不影响生产）

```bash
rm -rf /tmp/fix525 && mkdir -p /tmp/fix525/bin /tmp/fix525/cwd /tmp/fix525/agent1
cd /Users/direct3d/github/co-shell
go build -o work/co-shell-0.59.1.darwin.arm64 .                    # agent 二进制（仅作候选素材）
go build -o /tmp/fix525/bin/co-shell-hub ./cmd/co-shell-hub        # 待测 hub
# 初始：hub 同目录下没有任何可用的 co-shell 候选（co-shell-hub 自身 --version 无效，应被过滤）
ls /tmp/fix525/bin
```

启动独立 hub（CWD = `/tmp/fix525/cwd`，与 hub 同目录 `/tmp/fix525/bin` 区分开）：

```bash
cd /tmp/fix525/cwd && /tmp/fix525/bin/co-shell-hub --serve \
  --web-addr 127.0.0.1:12921 --tcp-addr 127.0.0.1:12920 \
  --registry /tmp/fix525/hub-agents.json --base-port 28520
```

- Web UI：`http://127.0.0.1:12921/`，用调试浏览器打开（**全程不刷新页面**，除 UC-0009 外）。
- 页面打开后用 console 挂请求计数器（供 UC-0003 使用）：

```js
window.__calls = [];
(function(){ var of = window.fetch; window.fetch = function(u, o){ window.__calls.push(String(u)); return of.apply(this, [u, o]); }; })();
```

## UC-0001 复制新二进制后，新建表单下拉立即可见（核心）

**类型**：运行时（浏览器 + 真实 hub）
**步骤**：
1. 浏览器打开 hub 页面，点「Agent 管理」进入新建界面，记录 `#m-coshell` 选项数（预期 1，仅「未找到」提示项）。

   `cp work/co-shell-0.59.1.darwin.arm64 /tmp/fix525/bin/co-shell-0.59.1.darwin.arm64 && chmod +x /tmp/fix525/bin/co-shell-0.59.1.darwin.arm64`

**预期**：
- 步骤 4 出现 `/tmp/fix525/bin/co-shell-0.59.1.darwin.arm64（hub 同目录）  (v0.59.1)` 这一项
- 全程**未重启 hub、未刷新页面**

## UC-0002 修改表单进入时重扫（核心）

**类型**：运行时
**前置**：用新建表单成功创建一个本地 Agent（workspace `/tmp/fix525/agent1`，端口 28520）。

4. 返回列表，再次点箭头进入修改界面，再读选项列表。

**预期**：
- 步骤 4 的选项比步骤 2 多出 `/tmp/fix525/bin/co-shell-0.59.0-test（hub 同目录）  (v0.59.1)`
- 每项 `value` 仍为纯绝对路径

## UC-0003 每次进入都重新请求后端（请求计数）

**类型**：运行时
**步骤**：
1. 挂上 `window.__calls` 计数器（见前置）。
2. 进入「新建」界面 3 次（列表 ↔ 新建来回切换），统计 `window.__calls` 中 `/api/agent-defaults` 的出现次数。
3. 进入「修改」界面 3 次，统计 `/api/co-shell-locations` 的出现次数。
4. 清空计数后停在同一界面 30 秒，再统计两个端点的出现次数。

**预期**：
- 步骤 2：`/api/agent-defaults` 出现 **3 次**（修复前恒为 1 次）
- 步骤 3：`/api/co-shell-locations` 出现 **3 次**（修复前恒为 0 次，命中 `coShellsCache`）
- 步骤 4：**0 次**（不在界面停留时轮询式重扫，无额外开销）
