# FIX-521 测试用例：hub 探测 co-shell 增加「hub 自身目录」并标注候选来源

## 背景

`DetectCoShells()`（`hub/gateway/detect.go`）只扫描 **hub 进程的当前工作目录（CWD）** 与 **PATH 各目录**，**不扫描 hub 可执行文件自身所在目录**；而启动 managed agent 时用的 `defaultCoShellPath()`（`cmd/co-shell-hub/main.go`）恰恰取 hub 同目录。两条路径语义不一致，导致「co-shell 与 hub 放同一目录却在下拉里搜不到」。

**本次实测证据（非推测）**：
- hub 进程（pid 61435）CWD = `/Users/direct3d`（主目录，双击/Finder 启动的典型结果），`PWD` 环境变量同为该值
- 该进程 PATH 首位 = `/Users/direct3d/bin`，`co-shell` 恰在其中 → `GET /api/co-shell-locations` 返回：
  `[{path:/Users/direct3d/bin/co-shell, source:path, 0.57.0/1021}, {path:/Users/direct3d/bin/co-shell-b455.exe, source:path, 0.7.8/455}]`
- 即：**能搜到只是因为 PATH 兜住了**；CWD 那一路扫的是主目录，与 co-shell 所在目录无关
- `~/bin` 下存在被命名为 `.exe` 的旧 macOS 二进制 `co-shell-b455.exe`（`file` = Mach-O arm64，版本 0.7.8），会混入下拉

## 需求（用户确认）

1. `DetectCoShells()` 在现有「CWD」+「PATH」之外，新增扫描 **hub 可执行文件所在目录**，与 `defaultCoShellPath()` 的启动语义对齐；取目录时解析软链（macOS 上 `os.Executable()` 不保证解引用）。
2. 候选列表的 `source` 能区分三类来源，**hub Web UI 的 co-shell 下拉对每个候选显示来源**，便于区分同名或版本陈旧的二进制。
3. **不改名、不删除**任何既有文件（用户明确：不动 `co-shell-b455.exe`）。

## 本次实现契约（需用户确认）

| 项 | 约定 |
|---|---|
| `source` 取值 | `hubdir`（**新增**） / `cwd` / `path` |
| 扫描顺序 | **进程 CWD → PATH 各目录 → hub 自身目录**（hub 同目录**追加在最后**，对现有候选顺序零影响；用户确认） |
| 去重规则 | 同一绝对路径只出现一次，保留**首次发现**（优先级更高）的来源标注 |
| 前端 option 文案 | `<路径>（<来源中文>）`；来源中文：`hub 同目录` / `当前目录` / `PATH` |
| 版本 / 分支 | 版本 `0.57.1`；分支 `FIX-521`；编译后 BUILD `1022` |
| 涉及文件 | `hub/gateway/detect.go`、`hub/gateway/webui_static.go`、`hub/gateway/detect_test.go` |
| 实现约束 | hub 前端 HTML 位于 Go 原始字符串字面量（反引号）中，新增 JS 内**禁止出现反引号与 `${}`**，字符串一律用单引号拼接（沿用现有风格） |
| 非目标 | 不做候选筛选/排序/自动清理；不改动 `~/bin` 下任何文件 |

## 验收前置

```bash
# 1) 准备三个互不相同的候选来源目录
rm -rf /tmp/fix521 && mkdir -p /tmp/fix521/bin /tmp/fix521/cwd
cd /Users/direct3d/github/co-shell && go build -o work/co-shell . && go build -o work/co-shell-hub ./cmd/co-shell-hub

# 2) hub 同目录：放一个"真" co-shell（--version 可解析）
cp work/co-shell /tmp/fix521/bin/co-shell
# 3) hub 自身（放在同一目录，使 os.Executable() 的目录 = /tmp/fix521/bin）
cp work/co-shell-hub /tmp/fix521/bin/co-shell-hub
# 4) CWD 候选（文件名以 co-shell 开头且可执行、--version 有效）
cp work/co-shell /tmp/fix521/cwd/co-shell-cwdtest
# 5) 反例：名字以 co-shell 开头但 --version 无效（应被过滤）
printf '#!/bin/sh\necho not-a-co-shell\n' > /tmp/fix521/bin/co-shell-fake && chmod +x /tmp/fix521/bin/co-shell-fake
# 6) 反例：名字不以 co-shell 开头（应被过滤）
printf '#!/bin/sh\necho hi\n' > /tmp/fix521/bin/not-co-shell && chmod +x /tmp/fix521/bin/not-co-shell
```

启动**独立测试实例**（不使用生产实例、独立端口与注册表）：

```bash
cd /tmp/fix521/cwd && /tmp/fix521/bin/co-shell-hub --serve \
  --web-addr 127.0.0.1:12901 --tcp-addr 127.0.0.1:12900 \
  --registry /tmp/fix521/hub-agents.json --base-port 28500
```

- Web UI：`http://127.0.0.1:12901/`
- 说明：从 `/tmp/fix521/cwd` 启动，使 **CWD ≠ hub 所在目录**，从而能区分两类来源（这是复现原问题的关键场景）。

## UC-0001 源码静态校验：新增来源与自身目录扫描（运行时）

**类型**：运行时（源码检索 + Go 编译）
**步骤**：
1. `grep -n "os.Executable" hub/gateway/detect.go`（应出现且用于取 hub 自身目录）
2. `grep -n "EvalSymlinks" hub/gateway/detect.go`（软链解析）
3. `grep -n "sourceHubDir\|\"hubdir\"" hub/gateway/detect.go`（新增来源常量/取值）
4. `grep -c '`' hub/gateway/webui_static.go`（原始字符串字面量的反引号计数）
5. `cd hub && go build ./... && go vet ./...`

**预期**：
- 步骤 1~3 均有匹配；`hubdir` 作为可辨识来源值出现在 `detect.go`
- 步骤 4 反引号计数 = `2`（仅界定 `webIndexHTML` 字面量的两个，未破坏 Go 原始字符串）
- 步骤 5 编译与 vet 通过

## UC-0003 单元测试：反例过滤仍生效（运行时）

**步骤**：
1. 用例中构造三个文件：文件名不以 `co-shell` 开头、名字以 `co-shell` 开头但非可执行、名字以 `co-shell` 开头且可执行但 `--version` 输出无版本号

**预期**：三个反例均**不出现**在候选结果中（沿用现有 `coShellCandidates` + `coShellVersion` 过滤语义，未因本次改动放宽）。

## UC-0004 单元测试：去重与来源归属（运行时）

**类型**：运行时（`go test`）
**步骤**：
1. 用例中让「hub 自身目录」与「CWD」指向同一目录（或同一路径同时可由两路发现）
2. `cd hub && go test ./gateway/ -run '<对应用例>' -v`

**预期**：
- 该路径在结果中**只出现一次**
- 其 `Source` 为**先被扫到的来源**（顺序：CWD → PATH → hub 目录）：同一路径同时属于 CWD 与 hub 目录时标注为 `cwd`；仅由 hub 目录发现时标注为 `hubdir`

## UC-0005 运行时 HTTP：CWD ≠ hub 目录时三类来源同时返回（运行时）

**类型**：运行时（HTTP）
**前置**：按「验收前置」准备好 `/tmp/fix521`，并从 `/tmp/fix521/cwd` 启动 hub
**步骤**：
1. `curl -s http://127.0.0.1:12901/api/co-shell-locations`
2. 检查返回的 `co_shells` 数组

**预期**：
- 含 `/tmp/fix521/bin/co-shell` 且 `source == "hubdir"`（**本次修复的核心断言**：CWD 为主目录/临时目录时仍能被发现）
- 含 `/tmp/fix521/cwd/co-shell-cwdtest` 且 `source == "cwd"`
- 若 PATH 中存在 co-shell，对应条目 `source == "path"`；若无则该项自然缺失（不视为失败）
- 每个元素的 `path` 均为**绝对路径**，`ok == true`，且 `version` 非空

## UC-0006 运行时 HTTP：hub 目录缺 co-shell 时不报错、旧行为不回归（运行时）

**类型**：运行时（HTTP）
**步骤**：
1. 另建目录 `/tmp/fix521/bin2`（**只放** hub，不放 co-shell），`cd /tmp/fix521/cwd` 用它的 hub 启动第二个实例（`--web-addr 127.0.0.1:12902`、`--registry /tmp/fix521/hub-agents2.json`）
2. `curl -s http://127.0.0.1:12902/api/co-shell-locations`
3. 同时确认进程未崩溃、`GET /api/agent-defaults` 仍返回 200

**预期**：
- 步骤 2 返回 `{"co_shells":[...]}`（`hubdir` 路无候选时不报错、不 panic）
- CWD 与 PATH 的候选**照常出现**（旧行为未回归）
- 步骤 3 返回 200

## UC-0007 运行时 HTTP：两个接口的候选列表一致（运行时）

**类型**：运行时（HTTP）
**步骤**：
1. `curl -s http://127.0.0.1:12901/api/co-shell-locations`
2. `curl -s http://127.0.0.1:12901/api/agent-defaults`
3. 比对 `co_shells` 字段

**预期**：两个接口返回的 `co_shells` 数组**元素与顺序完全一致**（两者同源调用 `DetectCoShells()`，修复后不得出现其中一个漏掉 `hubdir` 的情况）。

## UC-0008 前端 DOM：下拉选项显示来源标注（运行时）

**类型**：运行时（浏览器 DOM）
**步骤**：
1. 打开 `http://127.0.0.1:12901/`，点「添加 Agent」（新建表单）展开
2. 读取 `#m-coshell` 的所有 `<option>` 文本与 `value`
3. 关闭表单，点击已有 agent 卡片的箭头打开「修改」界面，读取 `#d-coshell` 的所有 `<option>`

**预期**：
- 两个下拉的每个 option 文本均为「**绝对路径（来源）**」形式，来源中文为 `hub 同目录` / `当前目录` / `PATH` 三者之一
- `value` 仍为**纯绝对路径**（不含来源标注），保存提交的 `co_shell` 不受标注影响
- `/tmp/fix521/bin/co-shell` 出现在列表**末位**（hub 目录追加扫描）并带「hub 同目录」标注
- 下拉**非空**（本次问题的直接验收点：即使 CWD 中无 co-shell、PATH 中也没有，仍能看到 hub 同目录那份）

## UC-0009 前端 DOM：陈旧/同名文件可凭来源区分（运行时）

**类型**：运行时（浏览器 DOM）
**场景**：模拟实测环境（`~/bin` 下同时存在 `co-shell` 与命名为 `.exe` 的旧 0.7.8 二进制）
**步骤**：
1. 备一份旧二进制到候选目录并命名以 `co-shell` 开头（例如 `cp <任一旧版本co-shell> /tmp/fix521/bin/co-shell-oldtest`）
2. 刷新页面，读取 `#m-coshell` 选项文本

**预期**：
- 新旧两个二进制**都**出现在列表中，但可通过「路径 + 来源」文案区分（不再出现"两个同名项无法分辨"的情况）
- 本次改动**不**新增任何自动过滤/改名行为（用户明确不清理文件）

## UC-0010 边界：通过软链启动 hub 时按真实目录扫描（运行时）

**预期**：仍返回 `/tmp/fix521/bin/co-shell` 且 `source == "hubdir"`（软链被解析到真实目录；若某平台 `os.Executable()` 已返回真实路径，此用例同样应通过）。
