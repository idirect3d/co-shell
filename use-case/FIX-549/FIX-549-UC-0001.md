## 1. 缺陷背景（用户实测反馈）

| # | 现象 | 实测根因（已用隔离实例 + 调试浏览器确认） |
|---|------|------------------------------------------|
| 1 | 回放出来的“LLM 块”都按 THINK 块显示（暗色字 + 斜体） | 回放走 `renderEvent` 尾部通用分支，标题只按通道取（`app.js:2184` `CHAN_LABEL[ev.chan]` → `LLM`），而实时流式路径用类型专属标题（`app.js:1956-1958` `THINK`/`LLM`/`TOOL`）。实测 DOM：`cls: ev thinking  label: LLM` |
| 2 | 完成报告（`TOOL: 完成任务`）之后又跟着若干 LLM 块，本应显示在其之前 | 合并器类型一变即 flush（`eventcoalesce.go:84-97`）落盘为 `content, tool, content`；而前端实时在工具片段到达时不关闭 `curLLM`（`app.js:1937-1950`），正文追加回工具卡上方那一个 LLM 块 → 实时与回放顺序不一致 |
| 3 | 回放的所有信息块时间戳显示为同一个时间 | 持久化事件不含时间字段（`server.go:166-172` 仅 `type/level/chan/text/meta`）；前端唯一流内时间戳来自 `app.js:1760` `fmtTime(new Date())`（渲染时刻）→ 回放同瞬间渲染，时间戳全相同。**与排序无关**（回放按 bbolt seq 升序） |

## 2. 交互决策（经用户 ask_user 确认）

1. 顺序口径：**B 实时对齐回放** —— 工具块开始时关闭当前 LLM 块，实时与回放统一为 `[LLM(前段)][TOOL][LLM(后段)]`，保持严格时间序（用户补充：持久化保存自然顺序、恢复按自然顺序取，**不按时间排序**）。
2. 时间戳：**A** —— 后端在持久化事件里带发生时间 `ts`（epoch 毫秒），前端优先用 `ts` 显示，缺失时回退渲染时刻。
3. 版本/编号：**v0.71.1** / **FIX-549**，并把此前 BUILD-1102 的计数变更一并提交到本分支。

## 3. 验收标准（全部满足方可交付）

1. 回放中 THINK 块标题为 `THINK`、正文块为 `LLM`、工具块为 `TOOL`，且与各自样式一致。
2. 同一次 LLM 消息中「正文 → 工具 → 正文」在实时与回放中都呈现 `[LLM][TOOL][LLM]`，顺序一致。
3. 回放事件按库内自然顺序（seq 升序）渲染，`ts` 只用于显示、不参与排序。
4. 回放的迭代行（token_iter）时间戳取自事件 `ts`，同一会话内不同行时间不同；老数据（无 `ts`）回退渲染时刻且不报错。
5. `go build ./... && go vet ./...` 通过；新增/相关单测全绿；隔离实例 + 调试浏览器实测通过。
