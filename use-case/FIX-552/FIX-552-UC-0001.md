# FIX-552-UC-0001: no-tool-action=prompt 保留 LLM 最后一轮输出

## 测试目标
验证当 `no-tool-action=prompt` 且 LLM 返回 0 个工具调用时，系统**不再删除** LLM 最后一轮输出，而是将其保留在 `a.messages` 中，并直接追加提醒调用任务报告的消息（continuePrompt），模拟一问一答；同时验证 `no-tool-action=retry` 时处理策略不变（仍丢弃 assistant 输出）。

## 前置条件
- 已构建最新版 co-shell（BUILD >= 1109）
- 配置文件可正常读写
- 至少一个可用 LLM API 配置
- 当前分支：`FIX-552`

---

## UC-0001-01: prompt 模式保留 assistant 输出并追加 continuePrompt

### 验证点
`no-tool-action=prompt` 时，LLM 未调用任何工具，最后一轮 assistant 输出应保留在 `a.messages` 中，且其后追加 continuePrompt 用户消息。

### 验证步骤
1. 启动 co-shell，设置 `:set no-tool-action prompt`
2. 输入一个需要工具但 LLM 可能直接回答的任务（如「帮我看看当前目录」）
3. 观察 LLM 返回 0 个工具调用时的行为

### 预期结果
- `a.messages` 末尾应包含：`assistant`（内容为 LLM 最后一轮输出，含 `finalContent` 与 `finalReasoning`）+ `user`（内容为 continuePrompt）
- 不再出现「删除最后一轮输出」的行为
- 循环继续，LLM 能看到自己上一轮的回答，从而更可能调用工具或给出任务报告

### 验证命令（单元测试）
```bash
go test -run "TestNoToolActionPromptKeepsAssistant" ./agent/ -v -count=1
```

## UC-0001-02: retry 模式仍丢弃 assistant 输出

### 验证点
`no-tool-action=retry` 时，LLM 未调用任何工具，assistant 输出仍被丢弃（不加入 `a.messages`），处理策略不变。

### 验证步骤
1. 启动 co-shell，设置 `:set no-tool-action retry`
2. 输入一个需要工具但 LLM 可能直接回答的任务
3. 观察 LLM 返回 0 个工具调用时的行为

### 预期结果
- `a.messages` 末尾**不**追加 assistant 消息
- 直接进入下一轮迭代，行为与 FIX-552 之前一致

### 验证命令（单元测试）
```bash
go test -run "TestNoToolActionRetryDiscardsAssistant" ./agent/ -v -count=1
```

## UC-0001-03: prompt 模式循环检测兼容性

### 验证点
保留 assistant 输出后，`stripLastAssistantAndContinue` 在循环检测时仍能正确剥离「末尾 assistant（无 tool_calls）+ continue prompt」对，避免死循环。

### 验证步骤
1. 启动 co-shell，设置 `:set no-tool-action prompt`
2. 构造一个会触发循环检测的场景（LLM 反复不调用工具）
3. 观察循环检测触发后的历史清理

### 预期结果
- 循环检测触发时，`stripLastAssistantAndContinue` 能剥离末尾的 assistant + continuePrompt 对
- 不会因新增的 assistant 消息导致历史清理异常

### 验证命令（单元测试）
```bash
go test -run "TestStripLastAssistantAndContinue" ./agent/ -v -count=1
```
