# FIX-588 UC-0002：运行时用例——“用完即卸”在真实会话中的可观察行为

> 分支：**FIX-588**　版本：**v0.91.4**　需求：用户 2026-10-02「SKILLS 段需要进一步明确，当不再需要时，应及时卸载 skill」
> 判定口径：模型在真实会话中**主动**调用 `skill_unload` 的时机提前到“任务/中间产物用完、后续步骤不再依赖”时，而不再长期保留已加载技能；且提示词、REPL、Web 三处显示与实际状态一致。

## 目的

`UC-0001` 锁定文案契约（静态可测），本用例验证**行为效果**：新文案能否把“卸载”从可选建议变成默认收尾动作。文案类改动无法用单测覆盖行为，故以真实会话观察为准。

```bash
cd /Users/direct3d/github/co-shell

go build -o work/co-shell-0.91.4.darwin.arm64 .            # 产物
./work/co-shell-0.91.4.darwin.arm64 --serve --port <port>  # 需要 Web 观察时用（必须带 --serve）
```

## 用例 A：提示词中 SKILLS 段已是新口径

**步骤**：启动一次会话（REPL 或 `--serve` 的 Web UI），在设置页“系统提示词”预览（或本轮请求日志中按文件名定位今天的 `log/llm-interaction-*.log`，用 `tail -c` 有界读取，**禁止**对整个 `log/` 目录无范围 grep）。

**期望**：SKILLS 段“卸载”条为强约束表述（含“立即调用 skill_unload”“用完即卸/默认要做的动作”“交付前自检”）；`skill_load` / `skill_unload` 的工具描述与用法块均含卸载引导；`<skills>` 清单结构不变。

## 用例 B：技能任务完成后模型主动卸载

**步骤**：在一个会话中提出一个**明确需要技能且可闭环**的任务（例如“用 image-generate 生成一张图并保存到 output/”，或任一具备完整步骤的技能任务），观察模型在任务交付前的工具调用序列。

**期望**：

1. 任务开始 → 调用 `skill_load`（合理）；
2. 任务完成/交付前 → **主动**调用 `skill_unload`，且 intent 说明“任务已完成/不再需要”。**不要求**用户显式提醒；
3. 卸载后若继续追问**不依赖该技能**的问题，模型**不会**重新加载该技能；若追问**仍依赖该技能**（例如“再改一版图”），允许重新 `skill_load`（加载仍是按需行为，不能因“用完即卸”而拒绝必要的重新加载）。

## 用例 C：REPL / Web 显示与后端状态一致

**步骤**：在用例 B 的会话中观察三处显示。

**期望**：

| 出口 | 卸载后 |
|---|---|
| REPL/流式 | 出现一行 `🔓 skill 已卸载：<name>（内容将在下一次上下文重整/裁剪时移除）` |
| Web「已加载技能」面板 | 该行消失（`skill_state` 事件整体重绘）；列表空时整块隐藏 |
| 最新 env 的 `<skills>` 块 | 该行不再带 `[已加载]`（技能仍在可用清单中） |

## 用例 D：上下文确实被回收（不长期占用）

**步骤**：在用例 B 之后触发一次上下文重整（`reorganize_context`）或窗口裁剪，检查上下文中的技能正文。

**期望**：已卸载技能的 SKILL.md 正文**不再出现在**重整后的上下文中；仍处于加载状态的技能正文逐字节保留（pin 不受影响）。

## 通过判据

- A 必须通过（静态可核）；
- B 为主判据：模型在技能任务闭环后**无提醒即卸载**；在“仍依赖”时允许并正确重新加载；
- C/D 作为一致性佐证，任一不符即为回归；
- 回归保护：`go test ./agent -run 'FIX588|FIX587|Feature583' -count=1` 全绿。
