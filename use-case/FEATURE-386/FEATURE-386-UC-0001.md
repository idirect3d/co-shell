# FEATURE-386-UC-0001: 任务计划与会话绑定

## 描述
任务计划（taskplan，即 `track_task_progress` 维护的待办任务清单）当前是全局单例，用固定 key `"current"` 存储单个全局任务计划，无 session 维度。切换会话时任务计划不变，导致不同会话的任务清单互相污染。本特性让任务计划与会话绑定：存储 key 加 session 前缀（`current:{sessionID}`），切换会话时自动加载目标会话绑定的任务计划，旧数据迁移到当前会话。

## 前置条件
1. 已启动 co-shell（REPL 或 serve 模式）
2. 存在至少两个命名会话（会话 A、会话 B），可通过 `.session` 命令切换

## 用例

### UC-0001: 会话 A 创建任务计划，切换到会话 B 后任务计划为空
- 操作：在会话 A 中调用 `track_task_progress` 创建任务计划（含若干步骤）；切换到会话 B
- 预期：会话 B 的任务计划为空（`view_task_plan` 返回"无任务计划"），不显示会话 A 的计划

### UC-0002: 会话 B 创建任务计划，切回会话 A 后任务计划恢复
- 操作：在会话 B 中调用 `track_task_progress` 创建任务计划；切回会话 A
- 预期：会话 A 的任务计划恢复为 UC-0001 中创建的计划（标题、步骤、状态完整保留）

### UC-0003: 各会话任务计划互不干扰
- 操作：会话 A 和会话 B 各创建不同的任务计划，反复切换
- 预期：每次切换后，当前会话显示的是该会话自己绑定的任务计划，互不污染

### UC-0004: 会话内更新任务计划不影响其他会话
- 操作：在会话 A 中更新任务计划（如标记某步骤完成）；切换到会话 B 再切回会话 A
- 预期：会话 A 的计划保留更新后的状态；会话 B 的计划不受影响

### UC-0005: 旧数据迁移
- 操作：升级前存在全局 `"current"` 计划（无 session 前缀）；升级后首次启动
- 预期：全局 `"current"` 计划迁移到当前会话名下，当前会话能读取到该计划

### UC-0006: 无会话场景回退全局 key
- 操作：sessionID 为空时（如测试环境、未绑定会话）调用任务计划工具
- 预期：回退到全局 `"current"` key，行为与旧版一致，不报错

### UC-0007: 任务计划归档/删除仅作用于当前会话
- 操作：在会话 A 中调用 `track_task_progress` 传入空 steps 归档删除计划；切换到会话 B
- 预期：会话 A 的计划被归档删除；会话 B 的计划不受影响

## 验证方法
1. `go build ./... && go vet ./... && go test ./...` 全绿
2. 单元测试：`taskplan` 包新增测试验证 `planKey` 按 session 隔离、`SetSessionID` 切换、`migrateLegacyPlan` 迁移
3. 集成验证：REPL 中创建两个会话，分别创建任务计划，反复切换验证各会话计划独立
