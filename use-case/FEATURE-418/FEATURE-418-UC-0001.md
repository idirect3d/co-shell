# FEATURE-418 .rules/ 按需加载层级显示

## 背景

FEATURE-417 实现了 .rules/ 按需加载，但子文件夹只显示文件夹名 + 路径，未展示子文件夹内部的规则文件。希望按 md 层级显示：子文件夹名→# 标题，内部 .md 文件→## 标题+路径，支持递归遍历子文件夹。

## 方案

修改 `loadRulesDir`，递归遍历子文件夹，按 md 层级输出：子文件夹名作为 `# 标题`，子文件夹内的 .md 文件作为 `## 文件名: 路径`，如果还有子文件夹继续递归（层级加深）。

## 验收标准

1. `loadRulesDir` 递归遍历子文件夹，按 md 层级输出。
2. 子文件夹名作为 `# 标题`，子文件夹内的 .md 文件作为 `## 文件名: 路径`。
3. 支持递归遍历多层子文件夹（层级加深）。
4. 子文件夹内的文件内容不加载。
5. 编译通过：`go build ./... && go vet ./... && go build -o work/co-shell .`

## 测试用例

### UC-001 子文件夹按层级显示
- 前置：`.rules/前端控件使用规范/` 子文件夹存在，内含多个 .md 文件
- 步骤：调用 `loadRulesDir`
- 期望：结果中包含 `# 前端控件使用规范` 标题，以及每个 .md 文件的 `## 文件名: 路径` 条目

### UC-002 递归遍历多层子文件夹
- 前置：存在多层嵌套子文件夹
- 步骤：调用 `loadRulesDir`
- 期望：嵌套子文件夹按层级加深显示（如 `## 子文件夹名`，内部文件 `### 文件名: 路径`）

### UC-003 子文件夹内容不加载
- 前置：`.rules/前端控件使用规范/` 子文件夹存在
- 步骤：调用 `loadRulesDir`
- 期望：结果中不包含子文件夹内文件的具体内容

### UC-004 根目录规范始终加载
- 前置：`.rules/PROJECT STANDARDS.md` 和 `.rules/go使用规范.md` 存在
- 步骤：调用 `loadRulesDir`
- 期望：结果中包含 PROJECT STANDARDS 和 go使用规范 的完整内容

### UC-005 编译验证
- 前置：无
- 步骤：运行 `go build ./... && go vet ./... && go build -o work/co-shell .`
- 期望：全部通过，无编译错误、无 vet 告警
