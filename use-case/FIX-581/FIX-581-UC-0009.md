# FIX-581 UC-0009：兜底与边界（WaitDelay / 0 = 不限制 / 失败语义 / i18n）

> 分支：**FIX-581**　版本：**v0.89.1**　对应方案：**超时执行的兜底与边界处理**
> 依据：ROADMAP v0.89.1 需求 ③（`0` = 不限制）＋ 事故机理（孙进程持有管道会让 `Wait` 永不返回）＋ 项目 i18n 规范（提示信息必须支持多语言）
> 判定口径：任何情况下交付工具都不会永久阻塞；`0` 时不做超时限制；命令失败（非零退出）不得被误报为超时；超时文案中英齐备。

## 目的

覆盖“命令已结束但管道仍被后台进程持有”的兜底路径、`0 = 不限制` 语义、失败与超时的区分，以及中英文案完备性。

## 前置条件

- 分支 `FIX-581`，`agent/tools.go` 的 demo 命令执行已设置 `Cmd.Cancel`（超时按进程组 kill）与 `Cmd.WaitDelay`（I/O 兜底）。
- 运行：`go test ./agent/ -run FIX581 -v`、`go test ./i18n/ -short`。

## 用例 UC-0009：命令已退出但后台进程仍持有管道 —— 不永久阻塞，且不杀该进程

```go
// 后台任务继承 stdout 管道（未重定向）→ shell 立即退出、管道写端仍被占用
"command": "sleep 300 &",
// 断言：attemptCompletionTool 在 WaitDelay 宽限内返回（不永久阻塞）
// 断言：sleep 300 仍存活（未超时 → 不杀）
```

**期望**：调用在 ≤ `超时上限 + WaitDelay + ε` 内返回；返回内容含已产生的输出或超时/结束提示；后台 `sleep 300` **仍存活**（测试收尾自行 kill）。

## 用例 UC-0010：`demo-cmd-timeout = 0` 表示不限制

```go
ag.cfg.LLM.DemoCommandTimeout = 0
"command": "sleep 4 && echo done",   // 超过默认 3s
// 断言：正常完成、输出含 done、不出现任何超时提示
```

**期望**：命令完整跑完（约 4s），返回输出含 `done`，无超时提示（`0` 时**不得**套用默认 3s）。

## 用例 UC-0011：命令失败（非零退出）不误判为超时

```go
"command": "echo boom && exit 3",
// 断言：返回失败提示（含退出状态/输出），且不含“超时”字样
```

**期望**：按既有失败分支返回「命令执行失败」类提示（附输出 `boom`），**不**显示超时文案（沿用原 `KeySettingCmd_610` 语义）。

## 用例 UC-0012：超时文案中英齐备

```go
// i18n 断言：新增的 demo 命令超时 key 在 zh/en 均非空且不相同
zh := i18n.SetLang("zh"); zhMsg := i18n.T(i18n.KeySettingCmd_XXX)
en := i18n.SetLang("en"); enMsg := i18n.T(i18n.KeySettingCmd_XXX)
// 断言：两者均非空、不含未替换占位符（如 %!d(MISSING)）、且 zh != en
```

**期望**：zh/en 两套文案均存在且可读（zh 例：「demo 命令执行超时（%ds），已终止该进程组」；en 例：`Demo command timed out after %ds; process group terminated.`）。
