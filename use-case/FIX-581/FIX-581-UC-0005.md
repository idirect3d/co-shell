# FIX-581 UC-0005：demo 命令超时与整组进程清理

> 分支：**FIX-581**　版本：**v0.89.1**　对应方案：**`attemptCompletionTool` 超时执行 demo 命令（超时才按进程组 kill）**
> 依据：ROADMAP v0.89.1 需求 ②（超时后 kill 整个进程组含孙进程并返回“命令超时”提示）④（只有超时才杀死子进程）＋ 2026-10-02 实测事故（14:28:19→14:47:05 静默 18 分 46 秒 + 孤儿 PID 10184）
> 判定口径：常驻命令必须在超时上限内返回且整组进程被杀（无孤儿残留）；命令在超时前结束时，其后台子进程**不得**被杀。

## 目的

验证本次修复的核心行为：demo 命令不再可能永久阻塞交付工具；超时按进程组清理，且不会误杀正常结束命令的后台子进程。

## 前置条件

- 分支 `FIX-581`，改动落地：`agent/tools.go:attemptCompletionTool` 使用 `exec.Command` + `setProcessGroupAttr` + 超时 goroutine（超时 `killProcessGroup`）+ `Cmd.Cancel` / `Cmd.WaitDelay`。
- 新增测试文件 `agent/fix581_test.go`（复用既有 `newAttemptCompletionAgent` / mock interaction manager）。
- 运行：`go test ./agent/ -run FIX581 -v`。

## 用例 UC-0005：常驻命令在超时上限内返回并报“命令超时”

```go
// agent/fix581_test.go
ag, _ := newAttemptCompletionAgent(false)          // 关闭确认对话框，避免阻塞
ag.cfg.LLM.DemoCommandTimeout = 1                  // 1s 加速验证
start := time.Now()
msg, err := ag.attemptCompletionTool(context.Background(), map[string]interface{}{
    "result": "done", "session_title": "t", "session_keywords": "k",
    "command": "sleep 60",                          // 模拟常驻命令
})
elapsed := time.Since(start)
// 断言：err == nil；elapsed < 5s；msg 含超时提示（zh: 命令超时 / en: timed out）
// 由 mock 断言的确认对话框 Body 或返回消息中读取
```

**期望**：调用在 **≤ 超时上限 + 宽限（约 1~2s）** 内返回（实测应 ≈1s）；返回结果含「命令超时（1s）」类提示与已产生的输出；`err == nil`。

## 用例 UC-0006：超时按进程组 kill —— 孙进程一并清理

```go
// 同上，command 用管道构造孙进程
"command": "sleep 60 | cat",
```

```bash
# 测试结束后在 shell 侧核对（或测试内用 syscall.Kill(pid,0) 断言）
pgrep -fl "sleep 60" || echo "no sleep 60 left"
pgrep -fl "^cat$"    || echo "no cat left"
```

**期望**：`sleep 60` 与 `cat` 两个进程**都不存在**（`setProcessGroupAttr` 使其同属一个会话/进程组，超时整组 SIGKILL）；工具返回超时提示。

## 用例 UC-0007：事故场景复现 —— `--serve` 作为 demo 命令

```go
// 直接使用本轮事故的等价命令，端口改为临时端口
"command": "./work/co-shell-0.89.1.darwin.arm64 --serve --port 28399",
```

```bash
lsof -nP -iTCP:28399 -sTCP:LISTEN || echo "port 28399 free"
pgrep -fl "co-shell-0.89.1.*--serve" || echo "no leftover co-shell --serve"
```

**期望**：工具在超时上限内返回（**不再出现 18 分钟静默**）；进程组被杀，端口 `28399` 释放、无孤儿 `co-shell --serve` 进程；日志出现 `Timeout kill: killing process group of PID ...` 记录。

## 用例 UC-0008：只有超时才杀死子进程（正常结束不误杀）

```go
// 命令立即结束，但留下一个后台子进程（stdout 已重定向，不占用管道）
"command": "sleep 300 >/dev/null 2>&1 & echo $!",
```

```bash
# 期望：命令返回后后台 sleep 仍在运行
pgrep -fl "sleep 300" && echo "background child survived"
```

**期望**：工具**正常返回**（含后台 PID 输出，`err == nil`，不报超时）；后台 `sleep 300` **存活**（超时 goroutine 在 `cmd.Wait()` 返回后撤销待杀，遵循 FIX-320）；测试收尾自行 `kill` 该后台进程以免残留。
