# FEATURE-414 项目规范增加版本计划规定

## 背景

当前规范（`.rules/PROJECT STANDARDS.md`）在新建分支时，仅当用户未指定版本时才提示制定版本计划，且打版本标签的时机不明确（仅提交到其他分支时也可能打标签）。需要明确：新建任何分支前（含 feature/fix）都需让用户确认成果归属版本，合并到 main 时按计划打版本标签，仅提交到其他分支时不打版本标签。

## 验收标准

1. `.rules/PROJECT STANDARDS.md` 的「新建开发任务」步骤 1 改为：新建任何分支前（含 feature/fix）需让用户确认成果归属版本，用户明确后先更新 ROADMAP 版本计划下对应内容。
2. `.rules/PROJECT STANDARDS.md` 的「代码提交及合并」步骤 4 改为：合并到 main 分支时按计划打版本标签，仅提交到其他分支时不打版本标签。
3. 规范文档修改不影响现有开发流程。
4. 编译通过：`go build ./... && go vet ./... && go build -o work/co-shell .`

### UC-002 合并到 main 时按计划打版本标签
