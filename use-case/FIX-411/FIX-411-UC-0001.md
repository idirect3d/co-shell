# FIX-411 测试用例：修复 Web UI REPL 输出块不新建

## 背景
在 Web UI 执行 REPL 命令时，系统输出内容都追加到同一个 REPL 输出块，即使有新的 REPL 命令并显示了新的 YOU 模块，REPL 内容仍加到前一个 REPL 块而不新建。导致多个用户消息堆叠，输出在最前面，用户消息多时看不到 REPL 输出。

## 用例列表

### UC-001 新 REPL 命令新建 REPL 输出块
- **前置**：Web UI 已启动。
- **步骤**：发送第一条 REPL 命令（如 `:help`），等待输出；再发送第二条 REPL 命令（如 `:version`）。
- **预期**：第二条 REPL 命令的输出新建一个独立的 REPL 块，而不是追加到第一条 REPL 块。

### UC-002 每个用户消息对应独立 REPL 块
- **前置**：Web UI 已启动。
- **步骤**：连续发送 3 条 REPL 命令。
- **预期**：每条命令对应一个独立的 YOU 块和一个独立的 REPL 输出块，互不堆叠。

### UC-003 用户确认/选择后新建 REPL 块
- **前置**：Web UI 已启动，出现需要确认的交互。
- **步骤**：用户做出确认/选择。
- **预期**：确认/选择后，后续 REPL 输出新建独立块，不追加到之前的 REPL 块。

### UC-004 连续 ui_text 行仍合并到同一块
- **前置**：Web UI 已启动。
- **步骤**：发送一条 REPL 命令，其输出包含多行 ui_text。
- **预期**：同一命令的多行输出仍合并到同一个 REPL 块（不因修复而拆散）。
