# FIX-561 测试用例 —— hub Ctrl+C 退出卡死修复

> 分支：**FIX-561**｜版本：**v0.76.4** (BUILD-1133)｜产物：`work/co-shell-0.76.4.darwin.arm64`、`work/co-shell-hub-0.76.4.darwin.arm64`

## 问题与根因

**现象**：hub 启动后若有 agent 在运行，终端按 Ctrl+C 无法终止退出（进程挂着，子进程也一直活着）；没有 agent 时能正常退出。

**复现（修复前，已实测）**：独立实例 + 1 个 managed agent，`kill -INT <hub pid>` 6 秒后进程仍存活；`kill -QUIT` 抓取 goroutine 栈：

```
goroutine 1 [sync.Mutex.Lock]:
  gateway.(*Proxy).dropAgentLink        proxy.go:165   ← 二次抢 p.mu
  gateway.(*Proxy).superviseAgent.func1 proxy.go:120   ← AgentConn 的 onClose 回调
  gateway.(*AgentConn).Close            agent.go:128
  gateway.(*Proxy).Close                proxy.go:608   ← 已持有 p.mu（defer 解锁）
  main.main.deferwrap2                  cmd/co-shell-hub/main.go:176
  main.main                             cmd/co-shell-hub/main.go:288
```

**根因**：`Proxy.Close()` 在持有 `p.mu` 的情况下逐个调用 `AgentConn.Close()`，而 `Close()` 的 onClose 回调 `dropAgentLink()` 也要抢 `p.mu` → 自死锁（RWMutex 不可重入）。有 agent 才会进入该循环，故「有 agent 就卡死」。

## 修复内容

1. `hub/gateway/proxy.go` — `Proxy.Close()` 改为：持锁时把各连接**快照并摘除**，**释放锁后**再逐个 `ac.Close()`，消除自死锁。
2. `cmd/co-shell-hub/main.go` — 收到 SIGINT/SIGTERM 时**先关停全部运行中的 managed agent**（走与「列表关闭 agent」同一个 `Manager.Stop`：cancel + Kill），再关闭 TCP/Web 监听并退出；新增 `stopManagedAgents()`，每个被关停的 agent 打日志。**只停进程，不删注册项**（与列表里的「删除」不同，配置保留）。
