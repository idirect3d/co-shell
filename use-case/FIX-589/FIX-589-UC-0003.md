> 分支：**FIX-589**　版本：**v0.91.5**　需求：用户 2026-10-03「先修复 C」
> 判定口径：以**实测数值**证明「单次树请求体量」从 6.89 MB 降到根层 < 100 KB、每次刷新的请求数 = 1 + 展开目录数，且既有 UX/接口行为零回归。

## 目的

本任务的动机是性能。UC-0001/0002 锁定行为契约，本用例锁定**可复现的性能数字**与回归面，避免"功能对但收益不可验证"。

## 用例 A：根层体量（核心指标）

- 请求 `GET /api/tree`（无参数）。
- 断言：`bytes < 102,400`（100 KB）；记录实测值到交付说明。
- 断言：响应体里任何 `dir=true` 的条目都不含 `children` 字段（懒加载无整树泄漏）。

## 用例 B：单层请求耗时

- 对根层与 3 个典型目录（含 `web`、`mobile` 这类多子项目录）各请求 5 次。
- 断言：**p50 < 50 ms**、最大值 < 300 ms（服务端时间，含一次 `git status` 与目录遍历）。
- 断言：目录 `changes` 徽标数值与 `depth=full` 基线一致（见 UC-0001 用例 D）。

## 用例 C：刷新开销（说明收益来源）

- 场景：根 + 2 个目录展开。
- 断言：一次 `loadTree()` 的请求数 = 3（1 + 2），总字节 < 300 KB。
- 对照基线：改前每次刷新 = 1 次 6,892,343 B。**节省 ≥ 95%**。
