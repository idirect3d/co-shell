# FIX-589 UC-0001：/api/tree 按层返回契约——后端用例

> 分支：**FIX-589**　版本：**v0.91.5**　需求：用户 2026-10-03「先修复 C（/api/tree 按需加载）」
> 判定口径：`GET /api/tree` 默认**只返回一个目录的一层子项**（缺省为工作区根），可用 `path` 指定目录；`depth=full` 保留整树出口（兼容既有调用方与测试）。每层返回的条目必须携带 `status`（文件）/`changes`（目录：其下改动文件数），保证未展开目录也能显示徽标。

## 目的

把「整树 6.89MB、每次刷新全量拉取」改为「按层返回」，同时不破坏既有字段语义、git 徽标、排除规则与安全边界。本用例锁定接口契约，UC-0002 锁定前端接线。

## 现状基线（改前实测）

| 指标 | 实测值 |
|---|---|
| `GET /api/tree` 响应体 | 6,892,343 B（6.89 MB） |
| 节点数 | 23,549（4,683 目录 + 18,866 文件） |
| 服务端耗时 | 0.178 s |

## 变更点（后端）

| 文件 | 变更 |
|---|---|
| `web/server.go` | `handleTree` 支持 `path` / `depth` 参数；新增「单层构建」路径（复用 `treeNode` 结构体与 `treeWalk` 过滤）；目录 `changes` 改为由 git 状态映射构建的祖先计数索引计算 |
| `web/*_test.go` | 既有树测试按新接口调整（整树断言改走 `depth=full` 或逐层遍历）；新增 FIX-589 接口用例 |

> 不改动 `treeNode` 的 JSON 字段名与含义；不改动 `config/tree_excludes.go` 的排除规则语义。

## 接口契约

```
GET /api/tree                      → 根节点 + 根的一层子项（目录项不含 children）
GET /api/tree?path=<rel-dir>       → 该目录节点 + 该目录一层子项
GET /api/tree?depth=full           → 兼容出口：整树（深度 ≤ 8 层、每层 ≤ 500 项，与改前一致）
GET /api/tree?path=<rel-dir>&depth=full → 以该目录为根的整树
```

统一响应体（节点）：

```json
{ "name": "co-shell", "path": "", "dir": true, "changes": 12,
  "children": [ { "name": "web", "path": "web", "dir": true, "changes": 3 } ] }
```

## 用例 A：默认只返回一层（体量 + 结构）

- 请求 `GET /api/tree`。
- 断言：响应为根节点（`dir=true`、`path=""`、`name` = 工作区目录名）；`children` 仅含**直接子项**；**所有 `dir=true` 的条目都没有 `children` 字段**（`omitempty`，未序列化）。
- 断言：响应体 **< 100 KB**（对比改前 6.89 MB）。

## 用例 B：path 指定目录的一层

- 请求 `GET /api/tree?path=web`。
- 断言：根节点 `path="web"`、`name="web"`；`children` 为该目录直接子项（不含更深层）。
- 断言：对同一目录，`?path=web` 返回的子项集合与 `depth=full` 响应中 `web` 节点的子项集合**一致**（名称/类型/status/changes 全等）。

## 用例 C：depth=full 兼容整树

- 请求 `GET /api/tree?depth=full`，按容器逐层遍历收集所有节点路径。
- 断言：与改前同一工作区全量树的路径集合**完全一致**（即兼容出口没有丢节点）。
- 断言：深度上限 8 层、每层上限 500 项的行为保持不变（构造 >500 项的目录验证截断，报错方式与改前一致：静默截断）。

## 用例 D：status / changes 语义不变（git 徽标）

- 构造含改动的工作区（修改 1 个文件、删除 1 个、新增 1 个）。
- 断言：`GET /api/tree` 的根节点 `changes` = 改动文件总数；改动文件所在目录（一级与更深层）在自己的层响应里 `changes` 正确（**递归计数**，含所有后代）。
- 断言：文件条目 `status` ∈ {M,A,D,R,U}，且未改动文件不带 `status`。
- 断言：`?path=<子目录>` 返回的子目录 `changes` 与该子目录在 `depth=full` 里的 `changes` 相等（同一口径）。

## 用例 E：排除规则（TreeExcludes）在每层生效

- 在设置中排除某目录名（按名）与某具体路径（按路径）。
- 断言：这两个目录不出现在根层响应中；若被排除目录位于更深层，其父层响应中同样不出现；`depth=full` 同样不出现（与改前一致）。

## 用例 F：安全与错误处理

| 请求 | 期望 |
|---|---|
| `?path=../../etc` | 400（路径穿越，拒绝） |
| `?path=/etc` | 400（拒绝绝对路径/越界） |
| `?path=web/../..` | 400（Clean 后越界） |
| `?path=not-exist-dir` | 404 |
| `?path=README.md`（文件而非目录） | 400 |
| `?path=` 空值 | 等价于根层（200） |
| `?depth=bogus` | 按默认层处理（200）或 400——按实现取一，用例断言二者之一并在实现中固定 |

- 断言：错误响应为 JSON 且不泄漏服务器绝对路径（只回通用错误信息）。

## 用例 G：排序与上限

- 断言：同一层内目录排在文件之前，同类按名称升序（与改前一致）。
- 断言：单层条目数上限 500（含目录与文件合计），超出静默截断（与改前一致）。
