# FEATURE-507 测试用例：前端消息滑动窗口缓存渲染（P1）

> 版本：v0.49.0 ｜ 分支：FEATURE-507
> 范围：P1 —— 事件流持久化 + 分页回放接口 + 刷新回填最后 20 条

## 设计要点（已确认）

| 项 | 决定 |
|---|---|
| 存储 | bbolt 新增 bucket `eventstream`，key = `{sessionID}\x00{seq:08d}`，value = StreamEvent JSON |
| 落盘点 | `WebRenderer.Render`（web/session.go:1121，唯一事件出口） |
| token_iter | **落盘**（刷新后逐行可见） |
| 回填粒度 | 按 `msg_index` 分组，取最后 **20 组**对应的全部事件 |
| 单会话上限 | **5000 条**，超出从最旧端删除 |
| P1 范围 | 只做"刷新回填最后 20 条 + 滚到底"，**不做**向上加载更多 |
| 内存约束 | 后端历史仅落盘，内存中只有当前上下文（`agent.Messages()`） |

## UC-0001 刷新浏览器后自动回填最后 20 条消息

**前置**：会话已有 ≥ 20 轮对话（每轮含 YOU/LLM/THINK/TOOL/token 行）。

**步骤**：
1. 在 Web UI 中完成若干轮对话；
2. 按 F5 刷新浏览器；
3. 观察消息区。

**预期**：
- 消息区**非空**，自动渲染出最后 20 组消息对应的全部块（含 YOU/LLM/THINK/TOOL/token 行）；
- 视图**自动滚动到最后一条**（底部）；
- 更早的消息不渲染（P1 不做向上加载）。

**验证方式**：浏览器观察 + 后端日志确认 `history` 消息已推送。

---

## UC-0002 事件流持久化：后端内存不随历史增长

**前置**：co-shell 以 `--serve` 启动。

**步骤**：
1. 记录启动后进程 RSS；
2. 连续进行 50 轮对话（产生大量事件）；
3. 再次记录进程 RSS；
4. 检查 bbolt 文件大小。

**预期**：
- 进程 RSS 增长幅度**远小于**事件流总量（历史不驻留内存）；
- bbolt 文件（`db/co-shell.db`）大小随事件流增长；
- 重启 co-shell 后，历史仍可回放（证明已落盘）。

**验证方式**：`ps` 观察 RSS + `ls -l db/co-shell.db`。

---

## UC-0003 分页游标：按 before 游标读取更早事件

**前置**：会话事件数 > 20 组。

**步骤**：
1. 前端发送 `{"type":"history_get","count":20}`；
2. 记录响应中的 `oldest_seq`；
3. 再发送 `{"type":"history_get","count":20,"before":"<oldest_seq>"}`。

**预期**：
- 第一次返回最后 20 组事件，`has_more: true`；
- 第二次返回**更早**的 20 组事件，且与第一批**无重叠**；
- 当取到最旧事件时，`has_more: false`。

**验证方式**：单元测试 `store` 层 `LoadEvents` + WebSocket 集成测试。

---

## UC-0004 session_pop 一致性：回退后刷新不出现已回退内容

**前置**：会话有 ≥ 3 轮对话。

**步骤**：
1. 点击第 2 个 YOU 块的 ⏪ 回退按钮；
2. 确认前端消息流已截断（第 2 轮之后的内容消失）；
3. 刷新浏览器。

**预期**：
- 刷新后回填的内容**不包含**已回退的第 3 轮及之后内容；
- 事件流持久化与 `popTo` 的截断范围一致。

**验证方式**：单元测试 `DeleteEventsAfter` + 端到端验证。

---

## UC-0005 边界：空会话刷新

**前置**：新建一个空会话（无任何消息）。

**步骤**：
1. 刷新浏览器。

**预期**：
- 消息区为空，**不报错**；
- 后端返回 `events: []`，`has_more: false`。

---

## UC-0006 边界：超长会话触发上限裁剪

**前置**：单会话事件数超过 5000 条。

**步骤**：
1. 持续对话直到事件数 > 5000；
2. 检查 bbolt 中该会话的事件条数。

**预期**：
- 事件条数**稳定在 5000 条**（从最旧端裁剪）；
- 最新事件始终保留；
- 回填仍能正常返回最后 20 组。

---

## UC-0007 会话隔离：不同会话的事件流互不干扰

**前置**：存在会话 A 和会话 B，各有对话。

**步骤**：
1. 切到会话 A，刷新；
2. 切到会话 B，刷新。

**预期**：
- 各自回填**自己**的历史，不串会话；
- 删除会话 A 后，其事件流一并删除（bbolt 中无残留）。
