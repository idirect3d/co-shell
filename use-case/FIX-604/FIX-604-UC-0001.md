# FIX-604 UC-0001：多工具调用意图各自回填到对应 TOOL 块

> 分支：**FIX-604**　版本：**v0.95.1**　BUILD：**1216**
> 判定口径：一次 LLM 迭代中连续调用 ≥2 个工具时，每个 TOOL 块标题栏显示**它自己**的意图（`TOOL: <动作> - <意图>`），互不覆盖、无"意图从第一个工具依次变化到最后一个工具"的可视现象；单工具、跨迭代孤儿块、历史回放路径均不回归。

## 背景（现象与根因）

- **现象**（用户 2026-10-04 19:08）：一次迭代中 LLM 连续调用 2 个以上工具时，意图信息只显示在最后一个工具上，且能看到意图从第一个工具变化到最后一个工具，其他工具标题栏不插入意图信息。参考：该问题曾出现过并修复过（FIX-462 / BUILD-708）。
- **根因**：`web/static/app.js` 的 `token_iter` 分支（~2215 行）在 `FIX-474` 中承担"清空跨迭代查找表"职责（`toolBlockByName = {}; iterToolBlocks = [];`），而 `FIX-508b` 又故意保留 `curTool`。后端 `FIX-555`（v0.74.1）把 `token_iter` 从"迭代末"前移到"LLM 返回后、工具执行前"（`agent/run_stream.go:566-570`）。于是单次迭代调 A/B/C 三工具时：
  ```
  tool_call_stream(A/B/C)   ← 建 3 块并登记查找表
        ↓
  token_iter                ← 清空查找表；curTool 仍指向最后一块 C
        ↓
  tool_call(input A/B/C)    ← target 全为 null → 三个意图全部写到 C，标题被 A→B→C 依次覆盖
  ```
  块 A、B 永远拿不到意图。

## 变更点

| 位置 | 变更 |
|---|---|
| `web/static/app.js` 模块级 | 新增 `iterResetPending` 标志（默认 false）与 `beginIterationReset()`（仅当 pending 时清空 `iterToolBlocks`/`toolBlockByName` 并复位） |
| `web/static/app.js` `token_iter` 分支 | 不再直接清空查找表，改为 `iterResetPending = true`（保留 `curTool` 既有处理） |
| `web/static/app.js` `content_chunk` 新建 LLM 块处 | 调用 `beginIterationReset()` |
| `web/static/app.js` `thinking_chunk` 新建 THINK 块处 | 调用 `beginIterationReset()` |
| `web/static/app.js` `tool_call_stream` 新建 TOOL 块处（`isNewTool`） | 调用 `beginIterationReset()` |
| `web/static/app.js` `openToolStreamBlock()`（历史回放） | 调用 `beginIterationReset()` |
| `web/static/app.js` `done` / replay-reset 分支 | 复位 `iterResetPending = false` |

## 用例与结果

### 离线事件序列模拟（`tmp/fix604_iter_tool_intent_test.js`，加载真实 `web/static/app.js` + DOM shim）— **21/21 通过**

- **UC-01（R）实时 3 工具意图各自归位** → ✅ **通过**。事件序列 `[tool_call_stream(A/B/C), token_iter, tool_call(input A/B/C)]`：`token_iter` 后 `iterToolBlocks.length === 3`、`iterResetPending === true`（查找表未被清空），3 个 TOOL 块标题分别含 `INTENT-0/1/2` 且互不包含他人意图。
- **UC-02（R）同名工具重复调用** → ✅ **通过**。两次 `execute_command`：块 #1 = `CMD-FIRST`、块 #2 = `CMD-SECOND`（按创建顺序各自回填，未都落到最后一块）。
- **UC-03（R）单工具调用不变（回归）** → ✅ **通过**。单工具仅 1 个 TOOL 块（无多余空块），标题含 `ONLY-INTENT`。
- **UC-04（R）跨迭代孤儿块不偷意图（FIX-474 不回归）** → ✅ **通过**。上一迭代 `track_task_progress`（无 input 事件的孤儿块）后，新迭代首个 `content_chunk` 消费 pending 复位并清空查找表，`read_file` 的意图仅落在自己的块上。
- **UC-05（R）历史回放路径** → ✅ **通过**。`isToolStreamBlock → openToolStreamBlock` 同样事件序列，3 块意图各自正确。
- **UC-06（R）多工具迭代无“无意图”块** → ✅ **通过**。3 工具调用后每个 TOOL 块都拿到自己的意图，无空标题块。

### 浏览器注入实测（真实 Chrome，静态服务加载修改后的 `app.js`）— **通过**

- **UC-06b（R）浏览器注入事件序列** → ✅ **通过**。`browser_evaluate` 注入 `[tool_call_stream×3, token_iter, tool_call(input)×3]` 后读取真实 DOM：`blockCount=3`、`titles = ["TOOL: 读取文件 - E2E-INTENT-0", "TOOL: 列出文件 - E2E-INTENT-1", "TOOL: 搜索文件 - E2E-INTENT-2"]`、`everyOwnIntent=true`、`unique=3`；截图确认 3 块标题各自独立。

### 真实 LLM 实测（`work/co-shell-0.95.1.darwin.arm64`，隔离工作区 + 端口 28897）— **通过**
