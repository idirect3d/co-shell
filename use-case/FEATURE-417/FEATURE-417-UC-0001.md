# FEATURE-417 .rules/ 按需加载机制

## 背景

`.rules/` 目录下所有 `.md` 文件被无条件加载到系统提示词 RULES 节。加入前端控件使用规范（594 行）后，RULES 节膨胀约 3.5 倍，大量与当前任务无关的领域特定规范稀释了注意力，可能导致核心执行纪律要求（如使用 track_task_progress）被忽略。

## 方案

`.rules/` 下可以建子文件夹，子文件夹名 + 完整路径会被加载到系统提示词（作为"可用规则类型"提示），但子文件夹里的文件内容不会加载。LLM 看到路径后可直接用 read_file 读取，无需探索。

## 验收标准

1. `loadRulesDir` 函数在加载根目录 `.md` 文件后，扫描子文件夹，将子文件夹名 + 完整路径格式化为"可用规则类型（按需加载，需要时用 read_file 读取）"提示追加到结果末尾。
2. 子文件夹里的文件内容不会加载到系统提示词。
3. `前端控件使用规范.md` 移到 `.rules/前端控件使用规范/` 子文件夹。
4. `.rules/` 根目录只保留核心规范（PROJECT STANDARDS + go使用规范），始终加载。
5. 编译通过：`go build ./... && go vet ./... && go build -o work/co-shell .`

## 测试用例

### UC-001 子文件夹名+路径加载到系统提示词
- 前置：`.rules/前端控件使用规范/` 子文件夹存在
- 步骤：调用 `loadRulesDir` 或构建系统提示词
- 期望：结果中包含"可用规则类型"提示，列出子文件夹名 + 完整路径（如 `前端控件使用规范: .rules/前端控件使用规范/前端控件使用规范.md`）

### UC-002 子文件夹内容不加载
- 前置：`.rules/前端控件使用规范/` 子文件夹存在
- 步骤：调用 `loadRulesDir`
- 期望：结果中不包含子文件夹内文件的具体内容（如不包含"CSS 类名"等前端控件细节）

### UC-003 根目录规范始终加载
- 前置：`.rules/PROJECT STANDARDS.md` 和 `.rules/go使用规范.md` 存在
- 步骤：调用 `loadRulesDir`
- 期望：结果中包含 PROJECT STANDARDS 和 go使用规范 的完整内容

### UC-004 前端控件规范移到子文件夹
- 前置：无
- 步骤：检查 `.rules/` 目录结构
- 期望：`前端控件使用规范.md` 位于 `.rules/前端控件使用规范/` 子文件夹，不在 `.rules/` 根目录

### UC-005 编译验证
- 前置：无
- 步骤：运行 `go build ./... && go vet ./... && go build -o work/co-shell .`
- 期望：全部通过，无编译错误、无 vet 告警
