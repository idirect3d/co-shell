# FIX-574 运行时测试用例：工具调用报错（meta.progress 规则冲突 + 误导性错误提示）

> 分支：**FIX-574**　版本：**v0.85.2**　被测：co-shell Agent 侧（`i18n/zh_system.go`、`i18n/en_system.go`、`agent/progress.go`、`agent/tool_error.go`、`agent/*_defs.go`）
> 需求来源：`research/会话初期工具调用报错分析.md`（用户采纳 P0-A / P1-A / P1-B，**不含 P0-B**）
> 目标：① 消除提示词中「未变化步骤可以不传」与「所有 in_progress 步骤必须上报」的自相矛盾；② 保持"遗漏在办步骤即拒绝该次调用"的硬失败语义，但错误文本必须列出**被遗漏步骤的 index + 描述 + 当前状态**，并**不再回填工具自身参数清单**；③ 在工具 schema 的 meta 描述中写明 progress 最小形态。

## 0. 测试环境与断言方式

- 无 UI/前端改动，全部断言走 Go 测试与静态文本检查 + 一次真实会话观察。
- 单元层命令：`go test ./agent/ -run 'TestFIX574|TestProgress|TestAssessRisk|TestValidateMeta|TestFormatToolError' -v`
- 静态层命令（提示词 / schema）：
  ```bash
  grep -c "未变化的步骤可以不传" i18n/zh_system.go            # 期望 0
  grep -c "steps that did not change can be omitted" i18n/en_system.go   # 期望 0
  grep -c "所有此前处于 in_progress" i18n/zh_system.go          # 期望 ≥ 2（两处模板）
  grep -rc "progress must cover every step that is still in_progress" agent/*_defs.go | grep -v ':0'
  ```
- 会话层：`work/` 下新编译产物以 `--serve` 启动，在 Web UI 新建会话，建立 5 步计划后只上报"当前步骤"触发一次拒绝，观察错误文本是否可照做。
- 基线（修复前，main 分支实测）：错误文本形如
  `Tool call "read_file" failed due to missing required parameters. ... specifies these required parameters: 'path' (string: file path) - required; 'start_line' and 'end_line' are optional`，**全文不含 meta**（见 `log/tool-call-error-2026-10-01.log`）。

## B 组：错误提示可执行化（P1-A，硬失败语义不变）

| 用例 | 步骤 | 期望结果 |
|------|------|----------|
| **UC-0007** 仍拒绝该次调用 | 计划 5 步（step0 completed、step1/step3 in_progress），progress 只报 step3 | `applyProgressReport` 返回错误；`skipExec == true`（工具未执行） |
| **UC-0008** 列出被遗漏步骤 | 同上，检查错误文本 | 文本包含 `[1]` 与 step1 的**描述原文**，以及其状态（in_progress）；多步遗漏时逐条列出 |

| **UC-0010** meta.risk 缺失文案 | `formatToolError("execute_command", metaErr)` | 文本列出 meta 五个字段（intent/risk/risk_reason/affected_objects/progress），**不含** `timeout_seconds`/`on_timeout` |
| **UC-0011** meta.progress 为空文案 | 同上 | 文本给出 progress 最小形态（`[{index, description, status}]` 且 ≥1 条） |
| **UC-0012** 修复指令可照做 | 检查任一 meta 类错误文本 | 含明确的下一步动作（"re-send the same call 并补齐上述步骤/字段"），而非泛泛"check the tool definition" |

| **UC-0014** 真实会话闭环（循环 3 次） | 新会话建立 5 步计划；第 1 次工具调用只报当前步骤 → 按错误提示补齐后重发 | 每次均：第 1 次被拒且错误可照做；第 2 次成功执行；计划状态正确 |

## 修复前后对照（验收要点）

| 维度 | 修复前（v0.85.1） | 修复后（v0.85.2） |
|------|------------------|------------------|
| 提示词 | 同段内"未变化可不传"与"必须全报"共存 | 单一明确规则（三段式），矛盾表述清零 |
| 遗漏在办步骤 | 报错，且提示"缺 path/regex/timeout_seconds"（与真实原因无关） | **仍报错**，但列出被遗漏步骤的 index+描述+状态，并给出补齐动作 |
| meta 字段缺失 | 套用"缺少工具参数"模板 | 列出 meta 五字段与 progress 最小形态 |
| schema | meta 描述只说"见系统提示词" | meta 描述内写明 progress 必须覆盖 in_progress 步骤 |
