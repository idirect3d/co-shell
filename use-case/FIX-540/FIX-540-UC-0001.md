# FIX-540 测试用例 — hub 输入控件字号提升到 16px（消除移动端聚焦自动放大）

- **分支**：FIX-540（基于 main，v0.68.1 已合并）
- **版本**：v0.68.2
- **需求（用户确认）**
  1. hub 抽屉「Chat 会话」里「我」的消息发送框（`#chatInput`）字号改为**移动端不触发自动放大的最小字号**；
  2. 同时把 hub 内**其它输入控件**（Agent 新建、Agent 详情、远程访问设置等表单里的文本框/下拉框，当前 13px）一并提到同一字号。
- **涉及文件**：`hub/gateway/webui_static.go`（内嵌 hub 外壳页 HTML + CSS）
  - `.chat-compose input { font-size:13px }` → 16px
  - `.field input, .field select { font-size:13px }` → 16px
- **不在范围内**：co-shell agent 页面自身输入框（`web/static/style.css` 中已在 FEATURE-487 统一为 16px）；hub 中非输入控件文字（列表行、气泡、按钮等字号不变）。

## 判定依据（为什么 16px）

iOS Safari（以及部分 Android 浏览器）在**聚焦 font-size 小于 16px 的 input/select/textarea** 时，会自动放大（zoom）整个页面，用户看到的是"发消息时局部界面被放大"。把可聚焦编辑控件的 font-size 提升到 **16px（不触发自动放大的最小字号）**即可消除该行为。

因此在无真机自动化手段时，本任务以「**可编辑控件的 computed font-size ≥ 16px**」+「meta viewport 未禁用缩放」作为客观判定，真机手感由用户最终确认。

## 测试前提

1. 使用本次编译产物 `work/co-shell-hub-0.68.2.darwin.arm64` 启动 hub（**不影响用户正在运行的实例**，采用独立端口/临时目录）。
2. 调试浏览器打开 hub 页面 `http://127.0.0.1:<port>/`，在 DevTools 中把视口切到手机尺寸（如 390×844）以复现窄屏布局。
3. 检查脚本（在页面控制台/调试浏览器 evaluate 中执行）：

```js
// 列出所有可聚焦编辑控件的计算字号
[...document.querySelectorAll('input, select, textarea')]
  .filter(el => el.type !== 'checkbox' && el.type !== 'radio' && el.type !== 'range')
  .map(el => ({ id: el.id || el.className, type: el.type, fs: getComputedStyle(el).fontSize }));
```

## 用例清单

### UC-0001 — 会话发送框字号 = 16px

- **前置**：hub 页面已打开，抽屉「Chat」中进入任一会话详情（Level 2）视图。
- **步骤**：执行上述检查脚本（或 `getComputedStyle(document.getElementById('chatInput')).fontSize`）。
- **预期**：`#chatInput` 的 font-size 为 `16px`（原 13px），且 `type="text"`、`maxlength="8192"` 等属性不变。

### UC-0002 — 会话发送框聚焦不放大（真机/模拟器）

- **前置**：手机（iOS Safari 或移动端浏览器）打开 hub，进入会话详情。
- **步骤**：点击发送框使其获得焦点（弹出软键盘）。
- **预期**：页面不发生自动放大；输入区域、气泡列表布局保持原尺寸稳定；输入文字后可正常发送。

### UC-0003 — Agent 新建（本地）表单控件字号 = 16px

- **前置**：抽屉 →「Agent 管理」→ 新建视图，模式为「本地」。
- **步骤**：检查脚本运行于该视图（或逐个读取）。
- **预期**：`#m-ws`、`#m-port`、`#m-id`、`#m-name`、`#m-extra`、`#m-coshell`(select) 均为 `16px`；隐藏的开关 checkbox 不参与判定。

### UC-0004 — Agent 新建（远程）表单控件字号 = 16px

- **前置**：同 UC-0003，模式切到「远程」。
- **步骤**：检查 `#e-host`、`#e-port`、`#e-id`、`#e-name`。
- **预期**：全部 `16px`。

### UC-0005 — Agent 详情视图控件字号 = 16px

- **前置**：Agent 列表中点击某 agent 的「›」进入详情视图。
- **步骤**：检查 `#d-id`、`#d-name`、`#d-type`、`#d-ws`、`#d-host`、`#d-port`、`#d-extra`、`#d-coshell`。
- **预期**：全部 `16px`（`readonly` 字段同样为 16px）。

### UC-0006 — 远程访问设置视图控件字号 = 16px

- **前置**：抽屉底部「⚙ 设置」进入设置视图。
- **步骤**：检查 `#s-cert`、`#s-keyfile`、`#s-whitelist`、`#s-accesskey`。
- **预期**：全部 `16px`。

### UC-0007 — 窄屏（≤640px）会话发送框布局不溢出

- **前置**：视口 390×844（`max-width:640px` 媒体查询生效，抽屉 `width:100vw`），进入会话详情。
- **步骤**：观察 `.chat-compose` 一行：输入框 + 「发送」按钮；输入一段长文本。
- **预期**：输入框仍占据剩余宽度，按钮未被挤出/换行到下一行；`.chat-compose` 高度正常（不出现按钮被裁切）；文字不溢出容器。

### UC-0008 — 桌面端（宽屏）表单布局无退化

- **前置**：视口 ≥1280px，打开 Agent 新建/详情/设置视图。
- **步骤**：逐屏观察字段行。
- **预期**：每个字段仍为「标签一行 + 控件一行（width:100%）」，控件不被文字撑破、`placeholder` 未被裁切；`.hint` 提示仍位于控件下方；无横向滚动条。

### UC-0009 — 发送消息流程回归

- **前置**：进入某会话详情。
- **步骤**：在发送框输入文本 → 点击「发送」（或回车提交）。
- **预期**：请求 `POST /api/board/conversations/{key}/messages` 成功；发送框清空；列表与消息区刷新，新消息以「我」的气泡出现在右侧；字号放大未影响按钮可用性（发送中按钮 disabled 再恢复）。

### UC-0010 — 改动无外溢（非输入控件字号不变）

- **前置**：同一页面。
- **步骤**：读取 `.agent`（列表行，13px）、`.chat-bubble`（气泡，12px）、`.conv-title`（13px）、`.btn`（12px）的 computed font-size。
- **预期**：与改动前一致（13px / 12px / 13px / 12px），说明本次只影响输入控件。

### UC-0011 — 隐藏控件不受影响

- **前置**：任意含开关的视图。
- **步骤**：观察 `.switch`（滑块开关）外观与点击切换行为。
- **预期**：开关尺寸（34×18）、滑块位置、切换动画与功能不变（`font-size` 对其不可见）。
