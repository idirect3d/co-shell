# FEATURE-423 Web UI 主消息区自动分割后自动融合

## 背景

FEATURE-416 实现了主消息区自动分割：LLM 输出时用户上滚，B 区（历史）变静态、A 区（动态）承接新输出。当前分割后需手动点击浮动融合按钮才能合并。希望当用户下滚到 B 区底部、且 A 区内容未填满（上下内容刚好接上）时，自动触发融合，减少手动操作。

## 方案

在 `streamB` 的 scroll 事件中，当 `splitActive` 为 true 时，检测 B 区是否滚动到底部（`scrollTop + clientHeight >= scrollHeight - 4`），且 A 区内容未填满（`streamA.scrollHeight < streamA.clientHeight`，即 A 区无滚动条、内容刚好接上），满足则自动调用 `mergeStream()`，相当于自动点击浮动融合按钮。

## 验收标准

1. 自动分割后，用户下滚（页面上滚）到 B 区底部，且 A 区内容未填满（上下内容刚好接上）→ 自动触发融合，A 区内容合并回 B 区，恢复单一流。
2. 自动分割后，用户下滚到 B 区底部，但 A 区内容已填满（A 区有滚动条）→ 不触发自动融合（避免融合后跳动）。
3. 自动分割后，用户未下滚到 B 区底部 → 不触发自动融合。
4. 未分割（splitActive 为 false）时，正常滚动行为不受影响。
5. 编译通过：`go build ./... && go vet ./... && go build -o work/co-shell .`

## 测试用例

### UC-001 B 区到底 + A 区未填满 → 自动融合
- 前置：Web UI 已加载，LLM 正在输出，已自动分割（B 区静态、A 区动态），A 区内容未填满（无滚动条）
- 步骤：用户下滚（页面上滚）到 B 区底部
- 期望：自动触发融合，A 区内容合并回 B 区，恢复单一流，浮动融合按钮消失

### UC-002 B 区到底 + A 区已填满 → 不自动融合
- 前置：Web UI 已加载，LLM 正在输出，已自动分割，A 区内容已填满（有滚动条）
- 步骤：用户下滚（页面上滚）到 B 区底部
- 期望：不触发自动融合，A 区保持独立，浮动融合按钮仍可见

### UC-003 B 区未到底 → 不自动融合
- 前置：Web UI 已加载，LLM 正在输出，已自动分割
- 步骤：用户下滚但未到 B 区底部
- 期望：不触发自动融合，A 区保持独立

### UC-004 未分割时滚动行为不受影响
- 前置：Web UI 已加载，LLM 正在输出，未分割（splitActive 为 false）
- 步骤：用户上滚/下滚
- 期望：正常触发自动分割（上滚）或保持底部（下滚），无异常

### UC-005 编译验证
- 前置：无
- 步骤：运行 `go build ./... && go vet ./... && go build -o work/co-shell .`
- 期望：全部通过，无编译错误、无 vet 告警
