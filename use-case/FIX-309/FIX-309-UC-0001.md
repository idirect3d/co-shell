# FIX-309-UC-0001: stripCodeBlockXML 闭合行处理缺陷

## 描述
当 LLM 输出的工具调用参数内容为 Markdown 代码块，且代码块闭合 ``` 与参数闭合标签（如 `</cs:replace>`）位于同一行时，`stripCodeBlockXML` 会连同闭合标签一起删除，导致 XML 解析器报告"参数缺少闭合标签"。

## 前置条件
1. 已启动 co-shell 并进入 REPL
2. 工具调用模式为 XML（`cs:` 前缀）
3. 使用 `.simulate` 命令（或直接调用 `ParseXMLToolCallsWithTools`）注入模拟 LLM 输出

## 测试步骤

### 用例 A：单元测试（stripCodeBlockXML 函数）

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| A1 | 输入内容：`` ```\ncode\n```</cs:replace> ``（闭合 ``` 与 `</cs:replace>` 同行） | `stripCodeBlockXML` 输出中保留 `</cs:replace>` |
| A2 | 输入内容：`` ```\ncode\n```\n``（闭合 ``` 独立一行，原有行为） | 输出与修复前一致（代码块被移除） |
| A3 | 输入内容：`` ```xml\n<tag>\n```\n``（带语言标识） | 代码块内容被移除，无异常 |

### 用例 B：集成测试（ParseXMLToolCallsWithTools）

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| B1 | 模拟 LLM 输出：`<cs:replace_in_file><cs:path>x.md</cs:path><cs:replace>…```\n```</cs:replace></cs:replace_in_file>`（闭合 ``` 与 `</cs:replace>` 同行） | 解析出 1 个 `replace_in_file` 工具调用，参数包含完整 `replace` 内容 |
| B2 | 解析结果中 `replace` 参数的 JSON 值完整无缺失 | 不产生 `参数 <replace> 缺少闭合标签 </replace>` 错误 |

### 用例 C：回归测试（现有行为不破坏）

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| C1 | 运行现有 `TestStripCodeBlockXML_*` 全部测试 | 全部通过 |
| C2 | 运行 `go test ./agent/ -run CodeBlock` | 全部通过 |

## 验收标准

1. `stripCodeBlockXML` 对闭合 ``` 与 `</参数>` 同行的输入，保留 `</参数>` 闭合标签
2. `ParseXMLToolCallsWithTools` 能正确解析含代码块的参数内容，不产生"缺少闭合标签"错误
3. 现有代码块剥离测试全部通过（无回归）
4. `go build ./...` 编译通过
