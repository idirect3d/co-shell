# FEATURE-564 运行时用例 UC-0002：进度口径（有任务计划 / 无任务计划）

## 目标

验证子代理进度的两种口径：

- **有任务计划**：显示 `已完成数/总任务数`，其中「已完成数」= 非 pending 的终态步骤数
  （`completed` + `cancelled` + `failed`），分母 = 全部步骤数。
- **无任务计划**：分母固定为 1，分子 = 子代理主任务是否完成（完成 → 1，未完成 → 0）。

## 前置条件

- 使用本分支构建的 co-shell（v0.78.0）以 `--serve` 启动，浏览器打开 Web UI。
- 子代理日志流为默认开启（`run-*.jsonl` 含 `task_plan` 事件）。

## 步骤

1. **场景 A（无任务计划）**：创建一个只做一次简单工具调用、不建立任务计划的子代理：
   `launch_sub_agent(tasks=[{id:"uc2-noplan", instruction:"执行 ls 并回报"}], timeout_seconds=30)`
   - 观察子代理运行中与结束后的进度显示。
2. **场景 B（有任务计划）**：创建一个会建立 5 步任务计划的子代理
   （例如指令要求“分 5 步：先列出目录、再统计文件数、再统计 Go 文件数、再生成汇总表格、最后归档到 output/”）：
   `launch_sub_agent(tasks=[{id:"uc2-plan", instruction:"请分 5 步完成：①列目录 ②统计文件数 ③统计 Go 文件数 ④生成汇总表格 ⑤写入 output/summary.md"}], timeout_seconds=120)`
   - 观察进度从 `(0/5)` 逐步推进到 `(5/5)`。
3. 若子代理计划中出现 `cancelled`（取消）或 `failed`（失败）步骤，确认这些步骤也计入“已完成数”。

## 预期结果

- 场景 A：运行中显示 `uc2-noplan ...(0/1)`；进程结束且主任务成功（exit code 0）后显示 `(1/1)`。
  失败/被杀（exit code != 0 或 killed）时保持 `(0/1)`。
- 场景 B：列表行显示 `uc2-plan ...(已完成数/5)`，分母为 5；步入终态的步骤立即计入分子
  （例如 2 步完成 + 1 步失败 → `(3/5)`）。
- 两个子代理同时存在时，各自独立显示、互不影响。

## 验证方式

- 浏览器截图 + `browser_evaluate` 读取清单行文本断言正则 `\(\d+/\d+\)` 与具体数值。
- 交叉验证：读取 `{workspace}/sub-agents/uc2-plan/run-*.jsonl` 中最后一条 `task_plan` 事件，
  人工核对步骤状态与界面分母/分子一致。
