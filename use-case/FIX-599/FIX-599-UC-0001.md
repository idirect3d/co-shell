# FIX-599 UC-0001：LLM 流式中断后的断点续传

> 分支：**FIX-599**　版本：**v0.92.3**　BUILD：**1206**
> 判定口径：流式输出被瞬时故障（网络/5xx/429）截断后，重试**接着已显示的内容继续**，不重复、不丢弃；半截工具调用与超预算场景仍终止本轮。

## 背景（FIX-598 的遗留）

FIX-598 让网络类错误不再删上下文并有界重试，但加了"**已流出内容就不重试**"的保守条件（重试会用**未修改的上下文**再问一次，模型从头重写答案，用户会看到重复文本）。因此长回答一旦中途断网，只能终止。

## 变更点

| 位置 | 变更 |
|---|---|
| `agent/stream_resume.go`（新增） | `streamAttemptTracker`：包装流式回调，累计本次尝试已发给 UI 的正文（`EventContentChunk`/`EventContent`）与思考（`EventThinkingChunk`/`EventThinking`）；`resumable(hasToolAttempt)`：仅"确实流出过正文且无工具调用分片"为真；`appendPartialAssistantAndContinue`：把部分回答作为 assistant 消息留在上下文，并追加一条"从中断处继续、不要重复"的 user 提示 |
| `agent/run_stream.go` | 流式调用改为 `a.streamLLMResponse(ctx, tools, attempt.wrap(cb))`；可恢复错误分支改为两路：**未流出** → 原样重试（原行为）；**已流出且可续传** → 先落入上下文再重试；**有工具分片或超预算** → 终止（保持保守）。两者共用同一 per-turn 预算（≤3 次）与 1s/2s/4s 退避 |
| `i18n/{keys,zh,en}.go` | 新增 `KeyLLMErrResumePrompt`（续写提示）、`KeyLLMErrRetryResume`（"已保留已输出的 %d 字符，%v 后从中断处继续（第 %d/%d 次）"） |
| `agent/fix599_test.go`（新增） | 追踪器采集（不吞事件）、续传判定 4 组、部分回答落入上下文 + 续写提示、nil 回调安全 |

## 用例与结果

- **A 追踪器只统计文本且不吞事件** → ✅ 正文/思考分别累计（`Hello world` / `think`），4 个事件全部继续传给真实回调。
- **B 续传判定** → ✅ 未流出 → 否；仅空白 → 否；有工具分片 → 否；有正文且无工具分片 → 是。
- **C 部分回答落入上下文（主判定）** → ✅ 追加后为 `[system, assistant(部分回答+reasoning), user(续写提示)]`，且续写提示不等同于部分回答本身。
- **D nil 回调安全** → ✅ `wrap(nil)` 返回 nil，未使用的追踪器不报告可续传。
- **E 编译与静态检查** → ✅ `go build ./... && go vet ./...` 通过；`-short` 失败集与改动前一致。

## 不在本次范围 / 待人工验证

- 未做"新响应前缀与已显示内容逐字比对"（采样差异下易误判）；改以**语义续写**（保留部分回答 + 续写提示）保证连贯，代价是模型偶尔仍可能重复少量文字——这属于提示词层面，必要时可加强提示。
- 半截工具调用不续传（会破坏调用结构），仍按 FIX-598 终止。
- 端到端建议：流式中途断网后观察是否"接着写"而非重头写、且不出现 `已移除有问题的上下文`。
