# FIX-575 UC-0004：旧事件流（无 `phase` 标记）回放向后兼容

> 分支：**FIX-575**　版本：**v0.85.3**　对应验收标准：**§4（向后兼容）**
> 关键约束：**升级前的数据库**中，合并后的 `tool_call` 事件**没有** `meta.phase`。
> 修复后 app.js 的规则是“无 phase 即块起点”，因此旧数据必须与新数据渲染结果一致。

## 目的

用一份**升级前生成的**事件流（无 `phase`）验证：回放后 TOOL 块数量/顺序/参数与实时一致，不因缺少标记而丢块或错并。

## 前置条件（务必先备份）

```bash
cd /Users/direct3d/github/co-shell
mkdir -p tmp
cp db/co-shell.db tmp/fix575-db-backup.db     # 备份，用例结束可回滚
ls -l tmp/fix575-db-backup.db
```

- 用于回放的旧数据来源（任选其一）：
  1. `tmp/fix575-db-backup.db` 中**升级前**已写入的历史会话（推荐：取一个含多个工具调用的会话）；
  2. 若本机库已是新格式，则用一个**旧版本二进制**（如 `work/co-shell-0.85.2.darwin.arm64`，若存在）先跑出会话数据，再用 0.85.3 打开。
- 启动：`./work/co-shell-0.85.3.darwin.arm64 --serve --port 28256`

## 步骤

1. 用 0.85.3 启动，打开旧会话（含 ≥3 次工具调用），等回放完成。
2. 执行 UC-0001 的**脚本 A**，记录 `toolCount / heads / yellowCount`。
3. 用 sqlite/bbolt 无关方式核对数据侧（可选，命令行）：
   ```bash
   # 确认库中这些事件确实没有 phase 字段（用 grep 观察事件流 dump 或日志）
   grep -c '"phase"' log/eventstream-dump.log   # 期望 0（若无 dump 文件则跳过本步）
   ```
4. 与“同内容实时渲染”的期望值对比（可用一条新会话重放同样提示词作对照）。
5. 反复刷新 2 次，确认稳定。

## 预期结果

| 断言 | 期望 |
|------|------|
| D1 | 旧数据（无 `phase`）的每个合并块**仍各自成块**：`toolCount` == 数据中工具调用次数 |
| D2 | `heads` 顺序与数据顺序一致（每块含自己的工具名） |
| D3 | 新旧数据的 `toolCount`/`heads` 对同一提示词**结果一致**（误差 0） |
| D4 | 无新增 JS 异常：`browser_console` 无 `Uncaught` 报错 |
| D5 | 刷新两次结果不变（不因旧数据而随机） |

## 修复前失败现象（基线）

旧数据本身就带“无 phase”特征，正是缺陷的高发场景：旧库回放时中间若干 `⚙️` 块缺失，
`toolCount` 显著小于数据中的工具调用次数，且随工具种类变化而随机。
