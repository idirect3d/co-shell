# FIX-575 UC-0003：write_to_file / replace_in_file 的 diff 与参数区在恢复后完整

> 分支：**FIX-575**　版本：**v0.85.3**　对应验收标准：**§1、§2（参数/附加内容不丢）**
> 场景特点：写文件类工具同时产生 `tool_call_stream`（参数流）与 `tool_call_diff`（diff 块），
> 是“参数区 + 附属渲染”双通道，回放时若块边界判断错误，diff 会挂到错误的块或整体消失。

## 目的

确认恢复后：① 写文件工具**自成一块**；② 参数区完整；③ `tool_call_diff` 渲染在**同一块**内，且不被并入前一个工具块。

## 前置条件

- 同 UC-0001 启动方式。
- 在一个轮次内制造“先读、后写”的组合，例如提示词：
  `请先读取 notes/fix575-uc3.txt（若不存在则创建），然后写入内容 "hello fix575"，接着用 replace_in_file 把 hello 改为 HELLO。`
  （先手工 `mkdir -p notes` 亦可；文件路径任意，只要同一 turn 内出现 write_to_file 与 replace_in_file。）

## 步骤

1. 发送提示词，等本轮结束（正文应出现 `write_to_file`、`replace_in_file` 两块的参数与 diff）。
2. 执行 UC-0001 的**脚本 A**（实时基线），并额外执行脚本 B 统计 diff 块。
3. 刷新页面 → 重开同一会话 → 等回放完成。
4. 再次执行脚本 A + B。
5. 逐块核对：diff 内容与该块的 `path` 参数一致（同属 `notes/fix575-uc3.txt`）。

### 脚本 B（diff 统计）

```js
(() => {
  const blocks = [...document.querySelectorAll('#stream .ev.tool')];
  return blocks.map((b, i) => ({
    i,
    head: (b.querySelector('.ev-head-label') || {}).textContent?.trim() || '',
    diffCount: b.querySelectorAll('.diff, .tool-diff, pre.diff').length,
    paramText: (b.querySelector('.ev-body') || b).textContent.trim().slice(0, 120)
  }));
})()
```

## 预期结果

| 断言 | 期望 |
|------|------|
| C1 | `write_to_file` 与 `replace_in_file` **各自成块**（回放与实时 `toolCount` 相等） |
| C2 | 回放后每块的 `diffCount` 与实时一致（不得为 0，也不得全部堆到某一块） |
| C3 | `paramText` 含该块自身 `path`，不出现前一块的参数残串 |
| C4 | 视觉上 diff 显示在对应 TOOL 卡片内部（不游离到卡片外） |
| C5 | 反复刷新 2 次结果稳定 |

## 修复前失败现象（基线）

- `replace_in_file` 块被并入 `write_to_file` 块 → diff 堆叠/错位；
- 或该块的参数与 diff 整体丢失（文本被静默丢弃），滚动加载也无法恢复。
