# FIX-575 UC-0005：切换会话 / 断线重连 / 服务重启后不缺失、不重复、不串会话

> 分支：**FIX-575**　版本：**v0.85.3**　对应验收标准：**§1、§4**
> 场景特点：`#msgVizTrack` 与消息流都依赖**当前会话**的事件分组（`LoadEventsByGroups`），
> 会话切换或重连若复用上一条会话的渲染状态（`curTool` / `iterToolBlocks` / `toolBlockByName`），会出现串会话或块错位。

## 目的

验证在「会话切换 → 断线重连 → 进程重启」三类恢复路径下，每个会话各自的 TOOL 块完整且互不污染。

## 前置条件

- 准备两个都会产生多次工具调用的会话：**会话 A**（≥3 次工具调用）、**会话 B**（≥2 次工具调用）。
- 启动：`./work/co-shell-0.85.3.darwin.arm64 --serve --port 28256`（WebSocket 单客户端，注意不要同时开多个浏览器窗口）
- 记录 A、B 各自实时的 `{toolCount, heads}` 作为基线。

## 步骤

1. 打开会话 A，执行脚本 A，记录基线 A。
2. 切到会话 B，执行脚本 A，记录基线 B。
3. **来回切换 3 次**（A→B→A→B），每次切换后执行脚本 A：
   - 期望：切到 A 时结果 == 基线 A；切到 B 时结果 == 基线 B；且不叠加（不出现 A+B 混合）。
4. **断线重连**：关闭页面（或断网 5 秒）后重新打开同一会话，执行脚本 A，与对应基线比对。
5. **进程重启**：`Ctrl+C` 结束 serve → 重新 `--serve --port 28256` → 打开会话 A 与 B，各执行脚本 A。
6. 每步后执行 `browser_console`，确认无新增 JS 异常。

## 预期结果

| 断言 | 期望 |
|------|------|
| E1 | 切换会话后 `toolCount/heads` 等于**该会话**基线（不串会话） |
| E2 | 切换 N 次后块数**不累加**、不重复 |
| E3 | 断线重连后与基线一致 |
| E4 | 服务重启后与基线一致（数据来自库，渲染来自回放） |
| E5 | 可视化条 `yellowCount` == 当前会话 `toolCount`（切会话必须刷新，见项目规范「切换会话时主动推送刷新」） |
| E6 | 控制台无 `Uncaught` / `TypeError` |

## 修复前失败现象（基线）

- 切换会话后 TOOL 块数骤减（前一会话遗留的 `curTool` 状态影响新会话首块判定）；
- 重启后同一会话，中间若干工具调用不成块；
- 可视化条与正文块数不一致（黄线条数少于 TOOL 块数）。
