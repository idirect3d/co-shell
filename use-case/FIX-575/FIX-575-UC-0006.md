# FIX-575 UC-0006：顶部消息可视化条与正文块数量严格一致

> 分支：**FIX-575**　版本：**v0.85.3**　对应验收标准：**§3**
> `#msgVizTrack` 的黄线是「TOOL 块」的镜像。缺陷期间黄线数量随 TOOL 块一起随机减少，
> 因此黄线是**最直观的验收指标**：黄线数 == `.ev.tool` 数，且刷新前后不变。

## 目的

锁定可视化条与正文块的一一对应关系，并覆盖上滚加载（分页）时线与块**成对增加**。

## 前置条件

- 会话需足够长以便触发分页上滚加载：`page_buffer_size=20`，即消息较多时向上滚动会分批加载。
- 启动：`./work/co-shell-0.85.3.darwin.arm64 --serve --port 28256`

## 步骤

1. 打开一个包含 ≥5 个 TOOL 块的长会话，等回放完成。
2. 执行下方**脚本 C**，记录 `tool / llm / other / lineCount / yellow`。
3. 刷新页面，等回放完成后再次执行脚本 C。
4. 向上滚动触发一次分页加载（观察 DOM 中消息数增加），再执行一次脚本 C。
5. 重复步骤 4 两次（多轮加载），确认一致性始终成立。

### 脚本 C（可视化条一致性）

```js
(() => {
  const tool = document.querySelectorAll('#stream .ev.tool').length;
  const llm  = document.querySelectorAll('#stream .ev.llm, #stream .ev.assistant').length;
  const all  = document.querySelectorAll('#stream .ev').length;
  const lines  = [...document.querySelectorAll('#msgVizTrack .msgviz-line, #msgVizTrack .line')];
  const yellow = lines.filter(l => {
    const s = l.getAttribute('style') || '';
    return /facc15|250,\s*204,\s*21/i.test(s) || l.classList.contains('tool') || l.dataset.kind === 'tool';
  }).length;
  return { tool, llm, other: all - tool - llm, lineCount: lines.length, yellow,
           okLineSum: lines.length === all, okYellow: yellow === tool };
})()
```

> 说明：选择器以实际实现为准（若类名不同，用 `#msgVizTrack` 下的线元素并按其 `style`/`data-kind` 归类）。

## 预期结果

| 断言 | 期望 |
|------|------|
| F1 | `yellow === tool`（黄线数严格等于 TOOL 块数） |
| F2 | `lines.length === all`（一条线对应一个块，无多余/缺失） |
| F3 | 刷新前后 `{tool, yellow, lineCount}` **完全相等** |
| F4 | 上滚分页加载后，`tool` 与 `yellow` **同步增加**（差值始终为 0），不出现“有块无线上”或“有线无块” |
| F5 | 多轮加载后仍满足 F1/F2（不随加载漂移） |

## 修复前失败现象（基线）

- `yellow < tool`（黄线少于 TOOL 块）；
- 或 `yellow` 与 `tool` 都随机变化，刷新后数值不同（同一会话每次刷新结果不一样）；
- 上滚补加载后差值不收敛（滚动也补不回来）。
