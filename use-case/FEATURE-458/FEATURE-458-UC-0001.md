# FEATURE-458 Web UI 连接状态开关 — 测试用例

> 版本：v0.26.0 ｜ 分支：FEATURE-458 ｜ 类型：Web UI 前端功能
> 前置条件：启动 Web UI（`./work/co-shell --serve --port <port>`），打开浏览器访问。

## UC-0001 连接状态显示为可点击开关
- **前置**：Web UI 已打开，WebSocket 已连接
- **步骤**：观察右上角连接状态显示（已连接/已断开）
- **预期**：连接状态显示为可点击的开关（鼠标悬停显示手型光标），点击可触发连接/断开动作

## UC-0002 已连接时指示灯圆点高亮
- **前置**：Web UI 已打开，WebSocket 已连接
- **步骤**：观察已连接文字左边的指示灯圆点
- **预期**：指示灯圆点高亮（主题 accent 色 + 光晕），指示当前为已连接状态

## UC-0003 已断开时指示灯圆点灰色
- **前置**：WebSocket 已断开
- **步骤**：观察已断开文字左边的指示灯圆点
- **预期**：指示灯圆点灰色（--fg-faint），指示当前为已断开状态

## UC-0004 点击已连接状态断开连接
- **前置**：Web UI 已打开，WebSocket 已连接
- **步骤**：点击右上角连接状态开关
- **预期**：WebSocket 主动关闭，状态变为"已断开"，指示灯圆点变灰

## UC-0005 断开后不自动重连
- **前置**：WebSocket 已断开（主动断开或异常断开）
- **步骤**：等待超过 2 秒（原自动重连间隔）
- **预期**：不会自动重新连接，状态保持"已断开"，指示灯圆点保持灰色

## UC-0006 点击已断开状态重新连接
- **前置**：WebSocket 已断开
- **步骤**：点击右上角连接状态开关
- **预期**：重新建立 WebSocket 连接，状态变为"已连接"，指示灯圆点高亮

## UC-0007 异常断开后不自动重连
- **前置**：Web UI 已打开，WebSocket 已连接
- **步骤**：模拟 WebSocket 异常断开（如后端重启）
- **预期**：状态变为"已断开"，指示灯圆点变灰，且不会自动重连，需用户手动点击重新连接

## UC-0008 两个浏览器互抢连接问题缓解
- **前置**：两个浏览器同时访问同一 Web UI 服务
- **步骤**：浏览器 A 断开连接，观察浏览器 B 的连接状态
- **预期**：浏览器 A 断开后不会自动重连，不会与浏览器 B 互抢 WebSocket 单客户端连接；浏览器 B 保持已连接状态

## UC-0009 断开后输入框不可用
- **前置**：WebSocket 已断开
- **步骤**：尝试在输入框输入指令并发送
- **预期**：输入框不可用或发送无效（无 WebSocket 连接），提示用户需先重新连接

## UC-0010 重新连接后功能恢复正常
- **前置**：WebSocket 已断开，用户点击重新连接
- **步骤**：重新连接成功后，发送一条指令
- **预期**：连接恢复，指令正常发送并收到响应，状态显示"已连接"

## UC-0011 连接按钮有外框
- **前置**：Web UI 已打开
- **步骤**：观察右上角连接状态开关
- **预期**：连接状态开关有外框（边框），外框高度与旁边的明暗风格按钮（themeToggle）一致

## UC-0012 连接按钮外框宽度自适应
- **前置**：Web UI 已打开
- **步骤**：观察连接状态开关外框宽度
- **预期**：外框宽度自适应，能容纳连接圆点指示灯和连接状态文字（已连接/已断开），不固定宽度

## UC-0013 连接按钮外框与明暗按钮对齐
- **前置**：Web UI 已打开
- **步骤**：观察连接状态开关与旁边明暗风格按钮（themeToggle）的垂直对齐
- **预期**：连接状态开关外框与明暗按钮高度一致、垂直居中对齐，视觉协调
