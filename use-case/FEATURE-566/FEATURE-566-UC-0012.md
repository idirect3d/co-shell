# FEATURE-566 运行时用例 UC-0012：不递归、不雪崩（通知触发的新迭代不得再产生通知风暴）

## 目标

验证通知机制不会自激：由"子代理完成通知"启动的新迭代，若该迭代又启动子代理，也必须遵守同一规则但不产生无限循环；子代理进程不能自己再创建子代理（`--subagent-enabled off`），从而阻断递归链。

## 前置条件

- `work/` 下已构建本分支可执行码（v0.80.0）；以 `--serve --port <port>` 启动。

## 步骤

1. 输入：「启动 A1 执行 `sleep 5`，timeout_seconds 设 2；A1 完成通知到达后，如果你认为有必要，可再启动 A2 执行 `sleep 5`」。
2. 观察完整链路：A1 完成 → 通知 → 新迭代 →（可能）启动 A2 → A2 完成 → 通知 → 又新迭代。
   - 预期：每一层都是"一个完成事件对应一次通知"，不出现同一事件重复通知、不出现通知风暴（短时间内多次重复起迭代）。
3. 检查 A1/A2 子进程的命令行。
   - 预期：均带 `--subagent-enabled off`（`subagent/launch.go:204`），子代理无法创建自己的子代理（递归被结构性阻断）。
4. 让链路自然收敛后确认 agent 回到空闲。
   - 预期：`IsBusy()=false`、无 pending 事件残留、无长期占用的 goroutine（可观察 goroutine 数回落）。

## 预期结果

- 通知是"事件驱动一次"而非"链式放大"；系统可自然收敛到空闲。
- 递归被结构性阻断（子代理 disabled），不依赖提示词约束。

## 验证方式

- 后端日志：每次完成仅一条通知、每次通知最多一次起新迭代。
- 单元测试补充：同一完成事件重复投递（同一 key 已终态）不会二次触发通知；子进程参数含 `--subagent-enabled off`。
