# FEATURE-566 运行时用例 UC-0009：通知驱动主 agent 继续处理（端到端）

## 目标

验证通知的**业务价值**：主 agent 收到完成通知后能自主取结果并推进原任务，而不是"收到通知但无所作为"或重复等待。

## 前置条件

- `work/` 下已构建本分支可执行码（v0.80.0）；以 `--serve --port <port>` 启动。

## 步骤

1. 输入：「启动 A1，指令：把 README.md 的前 5 个二级标题列出来，写进 output/toc.md；timeout_seconds 设 3」，回合结束后保持空闲。
2. 约 10~30 秒后 A1 完成 → 自动起新迭代并送达通知。
3. 观察新迭代内主 agent 的行为链：
   - 预期：调用 `sub_agent_status`（或 `sub_agent_status` + 读取 `output/toc.md`）取得结果；
   - 预期：在主迭代里给出结论（例如列出 5 个标题）或继续下一步工作；
   - 预期：不重复"傻等"（不出现再次无意义的 `sleep`/轮询循环）。
4. 若 A1 结果为空或失败，重复步骤 1 用会产生失败的指令（如不存在的文件）。
   - 预期：主 agent 依据失败通知给出失败原因与下一步（重试/更换方案/向用户汇报），而不是静默结束。

## 预期结果

- 通知 → 取结果 → 结论/动作 形成完整闭环（这正是本特性要解决的核心痛点）。
- 主 agent 的行为在通知后**必然**发生（不依赖用户再输入）。

## 验证方式

- 会话流中可见"通知（user 消息）→ assistant 工具调用（sub_agent_status）→ assistant 结论"。
- 该用例通过是 FEATURE-566 的核心验收项之一；若主 agent 收到通知却无任何后续动作，判定不通过。
