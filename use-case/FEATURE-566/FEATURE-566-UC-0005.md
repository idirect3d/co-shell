# FEATURE-566 运行时用例 UC-0005：通知正文内容与体量（仅状态 + id/run + 查询提示）

## 目标

验证完成通知的正文符合已确认口径：**只带状态 + id + run + 「请调用 sub_agent_status 取结果」提示**，不内联子代理结果正文、不内联日志，避免 token 浪费；同时保证主 agent 凭该提示能自助取到详情。

## 前置条件

- `work/` 下已构建本分支可执行码（v0.80.0）；以 `--serve --port <port>` 启动。
- 子代理指令能让其在结束时产出较长的最终答复（例如让其读取一个较大文件并总结），以便观察"结果没有被塞进通知"。

## 步骤

1. 输入：「用 launch_sub_agent 启动 A1，指令：读取 README.md 并写一段 300 字摘要，timeout_seconds 设 5」，回合结束后保持空闲。
2. 等 A1 结束，观察通知正文。
   - 预期：正文包含 —— 状态（完成/失败）、`id=A1`、`run=1`、以及"调用 sub_agent_status 取结果"的提示。
   - 预期：**不包含** 300 字摘要正文、不包含 jsonl 日志片段、不包含完整工具调用清单。
3. 主 agent 依提示调用 `sub_agent_status`（ids=A1，可选 wait_seconds）。
   - 预期：能拿到最终结果、输出文件清单与工具轨迹（沿用 FEATURE-563 行为）。
4. 检查通知长度（例如上限 ≤ 200 字符量级，具体以实现约定为准）。
   - 预期：单条通知长度稳定、与结果大小无关。

## 预期结果

- 通知是"指针"而非"搬运"：token 成本可控，且结果仍可获取。
- 通知中**不含**日志 tail / 结果正文（防止大结果污染上下文）。

## 验证方式

- 对比 A1 结果长度与通知长度：两者不相关。
- 单元测试补充：通知构造函数的输出不含 Result / LogTail 字段内容；含 id、run、状态关键字与查询提示。
