# FEATURE-566 运行时用例 UC-0008：非当前会话的子代理完成 → 不污染当前会话

## 目标

验证通知的会话隔离：完成事件只允许送达**它所属会话**的主 agent。若收到的完成事件属于**另一个会话**（异常/边界场景），不得注入当前会话的消息流或动态事件，也不得起新迭代；只记录日志。

## 前置条件

- `work/` 下已构建本分支可执行码（v0.80.0）；以 `--serve --port <port>` 启动，Web UI 已连接。
- 具备两个会话（`sess-A`、`sess-B`）。

## 步骤

1. 在 sess-A 启动 A1（`sleep 25`，timeout 3），回合结束后**尝试**切换会话：
   - 预期：被 FEATURE-565 守卫拒绝（A1 运行中不允许切换），或在无运行中时切换成功。
2. 通过调试手段构造"完成回调携带的 sessionID ≠ 当前会话"（例如单测中直接注入回调，或在后端把 `SetSessionID` 指向 sess-B 后触发 A1 的完成路径）。
   - 预期：`onSubAgentCompleted` 丢弃该事件并写日志；当前会话（sess-B）**没有**新通知、**没有**新迭代、**没有**动态事件残留。
3. 切回 sess-A 后查询 `sub_agent_status`。
   - 预期：A1 的终态与结果仍可在 sess-A 查到（进程表按「会话ID+子代理ID」编键）；只是"通知"未跨会话注入。

## 预期结果

- 通知不串会话：不会把 A 会话的子代理完成写进 B 会话的上下文。
- 数据不丢：结果仍归属原会话，可通过查询取得。

## 验证方式

- sess-B 的 LLM 输入中不含 A1 的完成条目；`AddDynamicEvent` 未被调用。
- 单元测试补充：sessionID 不匹配时回调提前返回（用桩断言"起新迭代"与"AddDynamicEvent"都未被调用）。
