# FIX-606 UC-0001：co-shell-hub 新增 `--no-api-key` 显式免密开关

> 分支：**FIX-606**　版本：**v0.95.3**　BUILD：**1218（已编译验证）**
> 判定口径：`co-shell-hub --no-api-key` 启动后，**本次进程内** TCP 网关鉴权关闭（`cfg.APIKey` 置空，客户端不携带 key 也能完成 auth 握手），且启动日志出现 `WARNING: TCP auth disabled (--no-api-key)`；同时 Web 侧的 `require_key`（设置页「强制校验」开关）在本进程内被视作关闭。所有效果**仅内存生效**，`hub-gateway.json` / `hub-settings.json` 均不被改写。
> 验证证据：`work/fix606-verify/verify-report.txt`（脚本 `verify.sh` + TCP 探针 `probe.go` + 各用例实例日志 `uc0*.log`），**25/25 全通过**。

## 背景（现状与目标）

- **现状**：`cmd/co-shell-hub/main.go:85` 的 `--api-key`（默认 `""`）只在非空时覆盖配置（`if *apiKey != ""`），空串被视作“未指定”。因此当 `hub-gateway.json` 已配置 `api_key` 时，**无法临时免密启动**（这正是用户 2026-10-04 21:51 提出的问题）。
- **网关侧已具备免密语义**：`hub/gateway/server.go:77` → `NewAuthenticator(cfg.APIKey)`；`hub/gateway/auth.go:24-26` 中 `key == ""` 时 `Authenticate` 恒返回 true。**缺的只是命令行入口**。
- **Web 侧**：`hub/gateway/webui.go:591-616` `needKey := s.RequireKey || (!allowed && s.AccessKey != "")`——白名单内主机（白名单为空时为 loopback）默认免 KEY，只有 `require_key=true` 会强制所有客户端校验。
- **目标**：新增显式开关 `--no-api-key`，作为“临时免密访问”的唯一入口；优先级最高（覆盖配置文件），与 `--api-key` 同时出现时按命令行顺序「后出现者生效」。

## 不在本次范围

- 不改 `--api-key` 现有语义（空串仍视为“未指定”，不用空串表示免密）——免密只认 `--no-api-key`。
- 不新增环境变量覆盖（方案 C 未采纳）、不做 CLI 互斥报错（方案 A 未采纳）。
- 不改 Web 访问控制的算法（白名单/`access_key`/`require_key` 判定逻辑保持原样，仅本进程忽略 `require_key`）。
- 不改 `hub-gateway.json` / `hub-settings.json` 的持久化格式，也不把命令行的临时状态写回文件。
