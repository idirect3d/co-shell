# FIX-311: OpenAI 工具调用模式 400 错误诊断增强

## 现象

openai 工具调用模式下，请求 Spark 网关（`http://localhost:11535/spark/v1/chat/completions`）间歇性报错：

```
LLM 调用出错: LLM call failed: OpenAI API error (status 400):
{"message":"Expecting value: line 1 column 493 (char 492)","type":"BadRequestError","param":null,"code":400}
```

随后 agent 进入「已移除有问题的上下文，正在重试...」流程，重试依然失败，用户侧无法定位根因。

## 排查结论（根因）

| 事实 | 证据 |
|---|---|
| 错误来自网关而非 co-shell | `Expecting value:` 是 Python `json.loads` 报错格式；co-shell Go 端只可能产生 `LLM call failed`/`OpenAI API error` 包装 |
| co-shell 发出的 JSON 合法 | `llm-interaction-*.log` 中所有 REQ 均能被 Python `json.loads` 成功解析（含失败请求） |
| jq 压缩的合法 JSON 也 400 | `jq -c . failing_req.json` 后再发网网关，3/3 复现相同错误 `char 492` |
| 与请求内容/字段无关 | 剪枝测试：messages 完全一致时，**无 stream 的请求全部 200**；带 `stream:true` 的完整请求稳定 400 |
| 非截断问题 | 11KB 纯 ASCII 流式请求 5/5 成功 |
| 非序列化转义问题 | 同逻辑请求用 UTF-8/`\uXXXX`/jq 三种序列化均稳定 400 |
| 间歇性表象 | 同请求重发偶尔 200（网关上游有状态/缓存），但错误列号恒定 493 |

**根因定论**：Spark 网关（Nginx → Python 上游）在 `stream=true` 请求路径上对请求体做了有损二次处理，导致对该网关自己收到的 JSON 做 `json.loads` 时失败。这是**网关侧缺陷**，co-shell 未产生非法 JSON；`tool_call_mode: openai` 只是恰好走了流式请求路径。

## 修复内容

co-shell 的排障缺陷：LLM API 返回 4xx 时错误信息仅含网关一句话，无任何请求上下文，排障只能靠反复实验。

### `llm/client.go`

1. **`Chat`（API error 分支）**：ERROR 日志附加实际发送请求的字节数 + 截断前 1000 字节；返回值错误消息附加字节数 + 紧凑摘要（`model`/`messages` 数/`tools` 数/`stream`/`extra_body`），**不回显消息内容**（避免污染回灌 LLM 的上下文）。
2. **`ChatStream`（HTTP error 分支）**：同上。
3. 新增辅助函数：
   - `truncateBody(body []byte) string`：截断请求体供日志使用。
   - `requestSummary(body []byte) string`：提取请求顶层概要，供回灌 LLM 的错误消息使用，绝不包含消息正文。

### `llm/client_test.go`（新增）

- `TestTruncateBody`：短体/恰好边界/超长截断（table-driven）。
- `TestRequestSummary`：完整请求/最小请求/无 stream/非法体/空体（table-driven），并断言不含换行（保证单行）。
- `TestRequestSummaryDoesNotEchoContent`：守卫测试，确保错误摘要不泄露 system prompt 内容。

## 修复效果

- 修复后若再遇 4xx：日志可立即看到实际发送字节数与请求体前 1000 字节，直接判定是 co-shell 还是网关问题；
- 回灌给 LLM 的错误压缩为一行概览（`model=..., messages=..., tools=..., stream=true`），不影响 agent 自我纠正。

## 复现档案

- `work/tmp/failing_req.json`：失败请求（从 `llm-interaction-2026-08-02.log` 22:07:53.831 REQ 提取，合法 JSON）。
- `work/tmp/failing_req_compact.json`：`jq -c` 压缩版，curl 直接发送必现 400（网关缺陷复现最小证据）。
