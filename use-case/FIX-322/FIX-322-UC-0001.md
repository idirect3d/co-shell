# FIX-322: 循环二次判定 exit_strategy 质量升级

## 背景

judgeLoop 二次判定时，判模仅凭 `{SUSPECT_CONTENT}` 判定，看不到 cwd/可用工具/文件线索，写出的 exit_strategy 常为空泛话术（"换个思路""重新评估"），无法指导主 LLM 落地下一步。且当 `is_loop=true` 但 `exit_strategy` 为空时，prompt 干预点会退化为泛模板。

## 修复方案

### A. 系统提示词加入 exit_strategy 编写六要求（zh/en 双语）
1. 动作性动词开头（调用/读取/修改/搜索/执行/询问）
2. 明确作用对象（工具名/文件名/命令/问题）
3. 可落地的下一步（具体小行动）
4. 信息不足时指明向用户提问内容
5. 禁止空泛话术（无作用对象表述）
6. 场景分类指导（搜索无果/命令重复/输出分析/无入口/信息不完整）

扩展 5 类样例、is_loop=true 时 exit_strategy 必须非空约束。

### B. user 模板新增 {CONTEXT} 环境上下文块
`buildJudgeContext()` 填充：cwd / workspace / 最近文件路径（启发式提取） / 可用工具列表（含 mcpMgr nil 保护、纯 Content 消息路径回退）。

### D. 服务端空值兜底
judgeLoop 解析后若 `is_loop=true` 且 exit_strategy 为空，回退 `KeyLoopJudgeFallback` 可操作指令。

## 用例列表

### UC-0001 buildJudgeContext 输出环境上下文（单测）
**前置条件**：构造含文件路径消息的 Agent。
**步骤**：调用 buildJudgeContext()。
**预期**：输出含 `cwd:`、`workspace:`、`recent_paths:` 及消息中的文件路径（如 `agent/loop.go`）。

### UC-0002 judge user 模板 {CONTEXT} 被填充（单测）
**前置条件**：i18n 已初始化。
**步骤**：调用 buildLoopJudgeUserPrompt()。
**预期**：无 `{CONTEXT}` 残留占位符；含 `cwd:` 环境块。

### UC-0003 兜底 key 存在非空（单测）
**前置条件**：i18n 已初始化。
**步骤**：读取 i18n.KeyLoopJudgeFallback 翻译。
**预期**：非空可操作指令。

### UC-0004 judgeLoop 空 exit_strategy 兜底（运行时，可选）
**前置条件**：loop-judge-enabled=on。
**步骤**：触发判模返回 `{"is_loop": true, "exit_strategy": ""}`。
**预期**：兜底指令被注入，prompt 干预不退化。
