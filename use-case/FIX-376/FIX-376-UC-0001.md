# FIX-376 测试用例 — 提问工具问题内容截断

> 版本 v0.7.8 | 分支 FIX-376
> 功能：修复 LLM 调用 ask_followup_question 提问时，显示的问题被截断（80 字符），用户看不到完整问题。

## 需求规格

1. `agent/tool_summary.go` 中 `ask_followup_question` 的 question 参数不再被 `truncate()` 截断，显示完整问题。
2. 该修复同时作用于 showTool 显示路径（`run_stream.go`）与确认提示路径（`tools.go`），两者均受益。
3. 其他工具的截断行为不变（write_to_file content、replace_in_file 数量等仍截断）。

## 测试用例

### UC-0001 长问题完整显示（Go 单测）
- 准备：构造超过 80 字符的 question（如"模型文件正在后台传输中（deepseek模型156G，预计2-3小时），下载完成后需要重启服务才能生效，请问是否现在重启？"）
- 操作：`buildToolSummary("ask_followup_question", {"question": longQuestion})`
- 断言：输出包含完整 question，且不含截断标记 `...（截断）`
- 通过标准：`TestBuildToolSummaryAskQuestionFull` 通过

### UC-0002 短问题正常显示（Go 单测）
- 准备：短 question（如"是否继续？"）
- 操作：`buildToolSummary("ask_followup_question", {"question": "是否继续？"})`
- 断言：输出包含完整短问题，无截断
- 通过标准：输出为"询问用户: 是否继续？"

### UC-0003 其他工具截断行为不变（Go 单测）
- 准备：write_to_file 长 content
- 操作：`buildToolSummary("write_to_file", ...)`
- 断言：长 content 仍被截断（不泄露原始长内容）
- 通过标准：`TestBuildToolSummaryTruncation` 通过（回归）

### UC-0004 回归：tool_summary 全量测试
- 操作：`go test ./agent/ -run 'TestBuildToolSummary'`
- 通过标准：全部通过，无回归

## 执行方式

- UC-0001~0004：`agent/tool_summary_test.go` 新增 `TestBuildToolSummaryAskQuestionFull`，运行 `go test ./agent/ -run 'TestBuildToolSummary'`
- 收尾：`go build ./... && go vet ./... && go build -o work/co-shell .`
