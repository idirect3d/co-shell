# FIX-584-UC-0001 SKILL.md front matter 的 YAML 块标量解析

## 需求

1. `agent/skill.go` 的 `parseSkillFrontmatter` 不再逐行取 `description:` 冒号后剩余内容，改为**缩进感知**解析 front matter：
   - 单行标量（含成对引号包裹）→ 剥离引号后作为值；
   - 块标量（`>` 折叠 / `|` 字面量，允许带 `-`/`+`/数字修饰符）→ 消费其后续更缩进的正文行，折叠/保留换行后作为值，且**不得吞掉后面的其他键**。
2. 技能卡片与系统提示词 `<skills>` 索引中显示**真实描述**，不再显示 `>-`。

## 运行时用例

### UC-0001-01 折叠块标量 `>-` 多行
- 前置：某 SKILL.md front matter 中 `description: >-` 后跟两行缩进正文（如 `agent-benchmark`）。
- 步骤：解析该 SKILL.md 并取 description。
- 预期：返回两行正文以空格拼接后的完整文本，**不含** `>-`、不含缩进、不含换行。

### UC-0001-02 折叠块标量 `>`（无修饰符）
- 前置：front matter 中 `description: >` 后跟多行正文。
- 步骤：解析并取 description。
- 预期：正文以空格拼接为一行完整文本（与 UC-0001-01 的折叠语义一致，chomping 差异不影响 TrimSpace 后的结果）。

### UC-0001-03 字面量块标量 `|`（保留换行）
- 前置：front matter 中 `description: |` 后跟多行正文。
- 步骤：解析并取 description。
- 预期：多行正文以 `\n` 连接（保留行结构），首尾无多余空白。

### UC-0001-04 块标量正文含空行
- 前置：`description: >-` 正文中存在空行分隔的段落。
- 步骤：解析并取 description。
- 预期：空行处产生段落换行（`\n`），非空行组内以空格折叠。

### UC-0001-05 块标量后接其他键（不得吞键）
- 前置：`description: >-` 正文之后仍有 `name: after` 等其它 front matter 键。
- 步骤：解析该 front matter。
- 预期：description 正确取值；`name` 正确解析为 `after`（块标量消费到缩进为 0 的行为止）。

### UC-0001-06 单行（含引号）标量
- 前置：`description: 单行描述` 或 `description: "带引号的描述"`。
- 步骤：解析并取 description。
- 预期：单行原样取值；成对引号被剥离。

### UC-0001-07 空块标量
- 前置：`description: >-` 之后无任何缩进正文（直接就是下一个键或 front matter 结束）。
- 步骤：解析并取 description。
- 预期：description 返回空字符串，不产生异常、不影响其它键解析。

### UC-0001-08 单元测试全绿
- 前置：仓库代码工作区。
- 步骤：执行 `go test ./agent/ -run 'TestParseSkillFrontmatter' -v`。
- 预期：`TestParseSkillFrontmatter` 与 `TestParseSkillFrontmatterBlockScalar` 全部 PASS。

### UC-0001-09 端到端：技能卡片与 `<skills>` 索引显示真实描述
- 前置：co-shell 以 `--serve` 启动且工作区含 `skills/`（`agent-benchmark`、`image-generate`）。
- 步骤：请求 `GET /api/skills`，并查看系统提示词 `<skills>` 索引。
- 预期：两个技能的 description 为真实文案（如 `>-` 修前的问题描述），**不再是 `>-`**；技能卡片同样展示真实描述。
