# FIX-289 单命令行模式下 Token 用量显示参数顺序错误

## 概述

单命令行模式（`co-shell "自然语言指令"`）在执行后显示 Token 用量时，fmt.Sprintf 参数顺序与格式串不匹配，导致显示乱码。

## 根因

`main.go` 中 `executeSingleCommand()` 的 `token_iter` 分支：
```go
// 错误：只传了 4 个参数，且顺序不对
fmt.Sprintf(i18n.T(i18n.KeyTokenUsageDisplay), prompt, completion, total, pct)
```

格式串 `KeyTokenUsageDisplay` 期望 7 个参数：
```
Token用量: 首字=%s | 输入=%d(%s t/s) | 输出=%d(%s t/s) | 总计=%d (%.1f%%)
            ft     prompt   inTPS  completion outTPS  total   pct
```

REPL 模式 `repl/repl.go` 中正确传递了全部 7 个参数：
```go
fmt.Sprintf(i18n.T(i18n.KeyTokenUsageDisplay), ft, prompt, inTPS, completion, outTPS, total, pct)
```

## 修复

将 `main.go` 第 1336 行的参数从：
```go
fmt.Sprintf(i18n.T(i18n.KeyTokenUsageDisplay), prompt, completion, total, pct)
```
改为：
```go
fmt.Sprintf(i18n.T(i18n.KeyTokenUsageDisplay), ft, prompt, inTPS, completion, outTPS, total, pct)
```

## 验证方法

1. `go build ./...` 编译通过
2. 运行类似 `co-shell "帮我执行ls"` 的自然语言指令，观察 Token 用量行显示应为：
   ```
   Token用量: 首字=1.7s | 输入=29408(22216 t/s) | 输出=56(36 t/s) | 总计=29464 (0.0%)
   ```
   而非 `%!s(int=37066)` 等乱码
