# FIX-590 UC-0003：输入框改 field-sizing（消除每键强制布局）

> 分支：**FIX-590**（追加项）　版本：**v0.91.6**
> 判定口径：支持 `field-sizing: content` 的引擎上，输入（含输入法逐键）**不再触发任何 JS 高度测量**（`scrollHeight` 读取 = 0）；输入框仍按内容增高、到 150px 后内部滚动；不支持该特性的引擎走回退路径且每帧最多测量一次。

## 目的

`autoGrow()` 原先挂在 `input` 事件上，每次内容变化都执行「`height:auto` → 读 `scrollHeight` → 写 `height`」，即**每键一次强制同步布局**（实测：15 个输入法按键 = 15 次 `scrollHeight` 读取）。本条把「测量次数」降为 0（现代引擎）或每帧 ≤1 次（回退）。

## 变更点

| 位置 | 变更 |
|---|---|
| `web/static/style.css` | 新增 `@supports (field-sizing: content) { #input { field-sizing: content; height: auto; max-height: 150px; overflow-y: auto; } }` |
| `web/static/app.js` | `autoGrow()`：`COMPOSER_FIELD_SIZING` 为真时**直接返回**；否则用 `requestAnimationFrame` 合并（每帧最多一次），测量逻辑移入 `growComposer()`（FEATURE-405 的 +6px 与 150px 上限不变） |

## 用例 A：输入法逐键零强制布局

- 在重 DOM 会话页（≥100 块）上插桩统计 `scrollHeight` getter 读取次数。
- 模拟输入法组合输入 15 键（compositionstart → 每键 keydown/compositionupdate/input → compositionend）。
- 断言：`scrollHeight` 读取次数 **= 0**（对照改前：15 次）。

## 用例 B：输入框按内容增高且到顶后内部滚动

- 输入单行 → 高度 ≈ 单行高（38px 量级）。
- 输入 3 行（含 Shift+Enter 换行）→ 高度 > 单行高且 = 内容高度。
- 继续输入到超 150px → 高度 **= 150px**（上限），`overflow-y` 为 `auto`（内部滚动）；`scrollHeight > clientHeight`。
- 删除回单行 → 高度回落到单行高（能缩回）。

## 用例 C：回退路径（不支持 field-sizing 的引擎）

- 断言：`autoGrow()` 不再同步测量，而是每帧最多一次（`composerGrowRaf` 合并）。
- 断言：高度行为与用例 B 一致（仅时机推迟到下一帧）。

## 用例 D：既有调用点语义不变

- 历史召回（↑/↓）、草稿恢复、发送后复位、初次加载等显式调用 `autoGrow()` 的位置行为不变（高度仍在下一帧正确）。
- 断言：依赖 `input.offsetHeight` 的弹层定位（app.js:6256）仍得到正确高度（field-sizing 下 `offsetHeight` 返回渲染高度）。
