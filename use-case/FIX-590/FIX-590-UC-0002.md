# FIX-590 UC-0002：屏外块跳过布局/绘制（A）+ 流窗口按文本量收敛与裁剪优化（B）

> 分支：**FIX-590**　版本：**v0.91.6**
> 判定口径：屏外消息块不再参与布局/绘制；流窗口在「块数/节点数」之外增加**文本字节上限**；裁剪不再产生两次强制布局与全量 `updateBlockNav`；跟随输出与用户上滚行为不变。

## 目的

实测：强制布局成本随流内文本量线性增长（1MB→66ms、5MB→316ms、10MB→628ms、20MB→**2.21s**）；`enforceStreamWindow`（app.js:1557-1595）每次 `makeBlock` 都执行，触发裁剪时做**两次 `scrollHeight`** 并调用全量 `updateBlockNav()`（10MB 场景 14.1ms/次）。本用例锁定 A、B 两项改造的行为与量化收益。

## 变更点

| 位置 | 变更 |
|---|---|
| `web/static/style.css` `.ev` | 新增 `content-visibility:auto; contain-intrinsic-size:auto <估高>`（屏外块跳过布局与绘制） |
| `scrollStream`（app.js:934-939） | `scrollTop=scrollHeight` 改为末块 `scrollIntoView({block:"end"})`（`scrollHeight` 在 content-visibility 下变估算值） |
| `updateFollowState` / `jumpToBottom` | 同步改为基于末块位置判定，保持「>100px 脱离底部不进跟随」 |
| `enforceStreamWindow`（app.js:1557-1595） | 新增**文本字节上限**（默认 2,000,000 字符）参与驱逐判定；裁剪时不读两次 `scrollHeight`（用锚点块 `offsetTop` 补偿）；裁剪后不跑全量 `updateBlockNav` |

## 用例 A1：屏外块跳过布局/绘制生效

- 断言：`.ev` 的 computed style `content-visibility == "auto"`；`contain-intrinsic-size` 已设置。
- 断言：滚动到流中部后，屏外块不产生布局（可用 `getBoundingClientRect().height` 与估算高度差异证明其为「跳过态」）。

## 用例 A2：跟随输出仍贴底

- 视图贴底时连发 chunk。
- 断言：末块底部始终在视口内（跟随不丢）；`followOutput === true`；下箭头按钮不出现。

## 用例 A3：用户上滚后不强制跳底

- 先上滚 500px，再连发 chunk。
- 断言：`followOutput === false`；视图位置不被改写（滚动位移 < 5px）；下箭头按钮出现；点击后跳到底部并恢复跟随。

## 用例 A4：滚动/布局成本下降（量化）

- 300 块 / ≈3MB 文本场景：对照注入 `content-visibility` 前后的
  - 一次强制布局（`document.body.offsetHeight`）与一次「追加 + 读 scrollHeight」耗时；
  - 逐块 `offsetTop` 扫描（`updateBlockNav` 循环）耗时。
- 断言：改后各指标 **下降 ≥ 50%**（记录实测值到交付说明）。

## 用例 B1：文本上限驱逐

- 构造单块超大文本（如 6 块 × 500KB）。
- 断言：流内文本字符数收敛到 ≤ 上限 + 一块（默认 2,000,000 + 最大单块）；最旧的整组被驱逐；至少保留 1 组。

## 用例 B2：裁剪不再双重强制布局

- 断言：一次裁剪过程中 `scrollHeight` 读取次数 ≤ 1（用 getter 计数插桩验证）；裁剪后不调用全量 `updateBlockNav`。
- 断言：20MB 场景下裁剪耗时 **< 100ms**（改前实测 2,210ms 的同一场景）。

## 用例 B3：裁剪后视图不跳

- 在流中部阅读时触发裁剪。
- 断言：视口内容位移 < 5px（锚点补偿生效）。

## 用例 B4：裁剪不破坏既有语义

- 断言：`token_iter` 尾块归属、`msgVizPending` 记账、`.ev-result` 标记与 silent 模式显示仍正确；`pendingInteraction` 期间的块不被驱逐。

## 用例 C：验收（含空闲态基线）

| 项 | 断言 |
|---|---|
| 空闲态长任务 | 重 DOM 页面静止 10s：`longtask` 条目数 = 0、阻塞总时长 < 100ms |
| 残留 streaming 动画 | turn 结束 / 连接断开后 `.ev-head.streaming` 数量 = 0（避免动画长期空转） |
| 按键延迟 | 模拟按键 dispatch→handler 完成 < 16ms（与 UC-0001 用例 D 一致） |
| 流式帧成本 | 200KB 块连续 60 帧：>16ms 的帧数 ≤ 3（UC-0001 用例 F） |
| 编译与测试 | `go build ./... && go vet ./...` 通过；`go test ./... -short` 失败集与 main 基线逐条一致 |
