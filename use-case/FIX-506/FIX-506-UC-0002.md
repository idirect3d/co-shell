> 分支：FIX-506

> 前置用例：FIX-506-UC-0001.md（首轮修复：msg_index 语义错位 + 页面刷新 + 图标）
> 本文档针对首轮修复后仍存在的缺陷补充运行时用例。

---

## 一、背景与根因

### 1.1 现象
用户在 Web UI 中依次发送 `hello 1`、`hello 2`、`hello 3`，点击第 2 个消息块（`hello 2`）标题栏的 ⏪（从此处重新执行），
预期"退至 hello 2"（保留 hello 1 + hello 2），实际 `:context` 只剩 hello 1。

### 1.2 根因
首轮修复把 `msg_index` 从"轮次计数器"改为 `len(a.Messages())-1`（**渲染时刻**的最后一条消息下标），方向正确但仍有缺陷：

1. **YOU 块拿到陈旧下标**：前端 `renderUserEcho(text)` 在用户回车时**立即**调用（`app.js` 发送输入处），
   此时后端尚未把该用户消息追加进 `a.messages`（追加发生在 `agent/run_stream.go` 的 `RunStream` 内）。
   它用的是 `lastMsgIndex`——**上一轮最后一个事件**的下标。
2. **同一轮内各块下标不一致**：第 2 轮中 user → assistant → tool 消息依次追加，
   每个事件渲染时 `len-1` 持续增长，导致 YOU / LLM / TOOL 块各携带不同下标。
3. **结果**：点 `hello 2` 实际回退到第 1 轮末尾，第 2 轮被整体截断，只剩 hello 1。

### 1.3 关键事实
- 一轮中**第一个**流事件到达时，`a.messages` 末尾正是该用户消息
  （assistant 消息要等流式结束才追加）。因此**该轮首个事件的 `msg_index` 就是该用户消息的真实下标**。
- `popTo(n)` 语义：`SetHistory(aMsg[:n+1])`，保留 `[0..n]`（含第 n 条）。

## 二、需求（用户确认）

| 编号 | 需求 | 说明 |
|------|------|------|
| R1 | 语义 | 点击 YOU 块 ⏪ = 保留到该消息为止（含），丢弃其后所有内容 |
| R2 | 移除其他块回退按钮 | LLM / THINK / TOOL / REPL / SYSTEM 等块不再显示 ⏪ |
| R3 | 参数口径一致 | 前端发送的下标 = 后端 `popTo` 使用的 `a.messages` 数组下标 |
