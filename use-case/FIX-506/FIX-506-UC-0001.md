# FIX-506 测试用例 — "从此处重新执行"回退语义错位 + 页面刷新 + 图标

> 分支：FIX-506
> 版本：v0.48.0
> 关联任务：FIX-506

## 背景

Web UI 的"从此处重新执行"（retry-from，块标题栏 `↻` 按钮）存在三个问题：

1. **回退数变成退至序号（严重）**：点击倒数第二个用户消息，上百条消息的上下文只剩 5 条。
   - 根因：前端 `app.js` 的 `↻` 按钮发送 `session_pop` 时传 `box.dataset.msgIndex`，该值来自后端 `WebRenderer.Render` 注入的 `msg_index`——它是 `WebSession.msgIndex`，**每次用户输入 +1 的轮次计数器**（1、2、3…），并非 `a.messages` 数组下标。后端 `cmd/session.go` 的 `popTo(n)` 却按 `a.Messages()` 的**数组下标**截断（`a.SetHistory(aMsg[:n+1])`）。两者语义错位导致截断位置错误。
2. **点击后整页刷新**：`app.js` 收到 `pop_result` 且 `ok` 时执行 `location.reload()`，整页重载（无必要）。
3. **图标**：`↻` 需改为两个向左的三角（古典倒带 ⏪）。

## 修复方案

- **后端**：`WebRenderer` 注入的 `msg_index` 改为真实消息数组下标（`len(a.Messages())-1`），使前端传值与 `popTo` 语义一致；轮次计数保留用于 token 统计显示（避免影响既有功能）。
- **前端**：`pop_result` 成功后不再 `location.reload()`，改为本地截断事件流（移除目标块之后的所有块）并刷新任务进展/文件树。
- **图标**：`↻` → `⏪`。

## 运行时用例

### UC-0001 点击倒数第二个用户消息，上下文按真实下标截断（核心回归）

**前置条件**
- 启动 `co-shell --serve --port <port>`，浏览器打开 Web UI。
- 当前会话已有 ≥ 10 轮用户输入（即 `a.messages` 长度 ≥ 20，含 system）。

**步骤**
1. 记录当前会话消息总数 N（可通过 `:session` 或状态栏查看）。
2. 找到倒数第二个 YOU 块（用户消息块），点击其标题栏的 `⏪` 按钮。
3. 观察后端截断结果与前端显示。

**预期结果**
- 后端截断到该 YOU 块对应的**真实消息数组下标**，保留 `[0..n]`，丢弃 `n+1..N-1`。
- 截断后消息数 ≈ 该用户消息在数组中的位置 + 1，**不是** 5 条（修复前 msgIndex≈5 导致只剩 5 条）。
- 前端事件流中，该 YOU 块之后的所有块被移除，该 YOU 块及其之前的内容保留。
- 页面**不整页刷新**（无白屏、无滚动位置重置、无 WebSocket 重连）。

**验证要点**
- 修复前：上百条消息 → 5 条（错误）。
- 修复后：上百条消息 → 保留到目标消息为止（正确）。

### UC-0002 点击第一个用户消息，上下文仅保留 system + 该消息

**前置条件**
- 同 UC-0001，会话已有 ≥ 3 轮用户输入。

**步骤**
1. 找到第一个 YOU 块，点击其 `⏪` 按钮。

**预期结果**
- 后端截断到该消息的真实下标（通常为 1，即 system 之后第一条）。
- 保留 `[system, user#1]` 共 2 条消息。
- 前端仅保留第一个 YOU 块，其后所有块被移除。
- 页面不整页刷新。

---

### UC-0003 点击最后一个用户消息，应被拒绝（无可回退内容）

**前置条件**
- 会话处于空闲状态（无正在运行的 LLM 输出）。

**步骤**
1. 找到最后一个 YOU 块，点击其 `⏪` 按钮。

**预期结果**
- 后端 `popTo` 检测到 `n >= len(aMsg)-1`，返回错误（"最后一条消息无需删除"类提示）。
- 前端收到 `pop_result` 且 `ok=false`，**不执行任何截断、不刷新页面**。
- 会话内容保持不变。

---

### UC-0004 点击后页面不整页刷新（回归）

**前置条件**
- 会话已有 ≥ 3 轮用户输入，页面滚动到中部（非顶部）。

**步骤**
1. 记录当前页面滚动位置、WebSocket 连接状态。
2. 点击任意非最后一个 YOU 块的 `⏪` 按钮。
3. 观察页面行为。

**预期结果**
- 页面**不发生** `location.reload()`（无整页白屏、无重新加载静态资源）。
- WebSocket 连接保持（不重连）。
- 仅事件流区域被本地截断，其余 UI（侧边栏、状态栏、输入框）保持原状。
- 任务进展面板与文件树被刷新（反映截断后的状态）。

### UC-0006 截断后继续对话，上下文正确衔接

**前置条件**
- 会话已有 ≥ 5 轮用户输入。

**步骤**
1. 点击倒数第三个 YOU 块的 `⏪` 按钮。
2. 在输入框输入一条新指令并发送。
3. 观察 LLM 收到的上下文。

**预期结果**
- 新指令追加在截断后的历史之后，上下文连续无断裂。
- LLM 能正确引用截断点之前的对话内容。
- 不出现"tool 消息成为孤儿"等 OpenAI 协议错误（截断点落在 user 消息上，天然安全）。

### UC-0007 轮次计数（token 统计）不受影响（回归）

**前置条件**
- 会话已有 ≥ 3 轮用户输入。

**步骤**
1. 发送一条新指令，等待 LLM 完成一次迭代。
2. 观察块底部的 token 统计行（迭代序号）。

**预期结果**
- token 统计行的迭代序号仍按轮次递增显示（`msgIndex` 轮次计数保留用于此用途）。
- 不出现序号错乱或缺失。

---

### UC-0008 多会话切换后回退仍正确

**前置条件**
- 存在 ≥ 2 个会话，当前会话 A 有 ≥ 5 轮输入。

**步骤**
1. 切换到会话 B，再切回会话 A。
2. 点击会话 A 中倒数第二个 YOU 块的 `⏪` 按钮。

**预期结果**
- 截断按会话 A 的真实消息下标执行，结果正确。
- 会话 B 不受影响。
