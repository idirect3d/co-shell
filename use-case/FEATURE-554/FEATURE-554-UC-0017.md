# FEATURE-554 验收测试用例：开发者页错误日志开关（tool-call-error-log / llm-call-error-log）

> 需求：在「系统设置 - 开发者页」新增两个开关，**默认均关闭**：
> 1. `tool-call-error-log`：开启后在 `log/` 下生成专用日志文件，记录工具调用报错信息，至少包含：
>    **调用时间、工具名称、原始工具调用报文（json/xml）、错误信息（与前端界面显示的红色文字一致）**；
> 2. `llm-call-error-log`：开启后在 `log/` 下生成专用日志文件，记录 LLM 调用错误与异常信息
>    （主要是调用远程 API 时返回的各类错误）。
>
> 设计口径（经 ask_user 与用户确认）：
> - 版本归属 **v0.74.0**，任务编号 **FEATURE-554**，分支 **FEATURE-554**；
> - 日志按日切分：`log/tool-call-error-YYYY-MM-DD.log`、`log/llm-call-error-YYYY-MM-DD.log`（与现有 `llm-interaction` 一致）；
> - 工具错误记录范围 = 工具执行返回错误（`formatToolError` 文案）、工具参数/XML 解析失败、未知/未注册工具、工具执行超时；
>   **不含**用户拒绝或取消工具执行；
> - LLM 错误记录范围 = HTTP 非 200（含远程 API 错误体）、网络/连接错误（DNS/TLS）、请求超时、
>   流式响应中断/SSE 异常终止、响应体解析失败；
> - 敏感信息（API Key、Authorization 等）**保持原样完整记录**，不脱敏（与现有 `llm-interaction` 日志一致，仅落本地）；
> - 开关关闭时**不得产生任何新增日志文件或写入**。

## 前置条件

- 已编译最新可执行码（`work/co-shell-0.74.0.darwin.arm64`），以 `--serve` 启动：
  `work/co-shell-0.74.0.darwin.arm64 --serve --port <port> --bind 127.0.0.1 -w <工作区> -c <工作区>/config.json --yolo`
- 清空基线：记录当前 `log/` 下已有文件名清单，便于比对新增文件。
- 可触发工具错误的测试工作区（例如对不存在的路径执行 `read_file`）。

### UC-001 两个配置项默认关闭

- 前置：工作区 `config.json` 中不存在 `tool_call_error_log` / `llm_call_error_log` 字段。
- 步骤：以该配置启动 `co-shell --serve`。
- 预期：
  1. 设置面板开发者页两项均显示为「关」；
  2. `.set tool-call-error-log` 与 `.set llm-call-error-log` 查询结果显示关闭；
  3. `log/` 下无新增日志文件。

### UC-002 开发者页显示两个开关且默认显示「关」

- 步骤：打开 Web UI → 系统设置 → 开发者页。
- 预期：
  1. 新增 `tool-call-error-log`、`llm-call-error-log` 两个 bool 开关，文案为多语言（中文/英文各一份）；
  2. 初值为「关」；
  3. 与既有 `log`、`llm-log` 项同组展示，顺序稳定、不破坏既有布局。

### UC-003 CLI 开启 tool-call-error-log 并持久化

- 步骤：`.set tool-call-error-log on`。
- 预期：
  1. 命令返回成功提示（多语言）；
  2. `config.json` 中 `tool_call_error_log` 变为 `true`；
  3. 无需重启即生效（随后触发一次工具报错会写日志）。

### UC-004 CLI 关闭后立即停止写入（运行期生效）

- 步骤：`.set tool-call-error-log off` → 再次触发工具报错。
- 预期：
  1. 提示关闭成功；
  2. 此后不再新增/追加任何工具错误日志行（已存在的历史文件内容不变）；
  3. 再次 `on` 后恢复写入。

### UC-005 关闭状态下工具报错不产生任何日志文件

- 前置：两个开关均为 `off`。
- 步骤：触发工具执行错误（如 `read_file` 读取不存在路径）。
- 预期：
  1. 前端正常显示红色错误信息；
  2. `log/` 下**不产生** `tool-call-error-*.log` 与 `llm-call-error-*.log`；
  3. 无该文件被创建（含空文件）。

### UC-006 开启后工具执行错误写入专用日志（四要素齐全）

- 前置：`.set tool-call-error-log on`。
- 步骤：触发工具执行错误 → 查看 `log/tool-call-error-<今天>.log`。
- 预期：新增一条记录，且**同一条记录**内包含：
  1. 调用时间（含日期，可定位到秒级或更细）；
  2. 工具名称（与调用一致）；
  3. 原始工具调用报文（JSON/XML 原文）；
  4. 错误信息（`formatToolError` 产生的文案）。

### UC-007 日志中的错误信息与前端红色文字完全一致

- 步骤：触发工具报错，对比前端红色文字与日志中错误信息字段。
- 预期：两者正文一致（若无前端附加包装，则字符串完全相等；若前端附加样式信息，则语义与正文一致且不含 HTML 标签）。

### UC-008 工具参数/XML 解析失败被记录

- 步骤：构造工具调用参数非法（缺少必填参数 / XML 格式错误）触发解析失败。
- 预期：写入日志；工具名称为目标工具或解析阶段标识，错误信息能定位到解析失败原因。

### UC-009 未知/未注册工具被记录

- 步骤：让模型调用一个不存在的工具（或直接触发未知工具分支）。
- 预期：写入日志，工具名称为该未知工具名，错误信息说明工具不可用。

### UC-010 工具执行超时被记录

- 步骤：配置一个短超时的 `execute_command`（如 `sleep 10` + 超时 1s）并触发。
- 预期：写入日志；错误信息包含超时语义。

### UC-011 用户拒绝/取消工具执行不记录

- 步骤：在需确认的工具调用上选择「拒绝」/取消执行。
- 预期：日志中**不出现**该条记录（该情形按用户决策不属于错误范围）。

### UC-012 原始调用报文按 JSON/XML 原文完整记录

- 步骤：触发一次含多行文本、中文、引号与转义字符的工具调用（如 `write_to_file` 写含中韩字符与 `\n` 的内容）。
- 预期：
  1. 日志记录的是**未经篡改**的原始报文（JSON 或 XML 原文）；
  2. 多行内容不被截断、不被二次转义破坏（可读或按原样转义，能还原原文）；
  3. 超长报文可按既有工具结果限制策略截断，但需在日志中标注截断。

### UC-013 LLM HTTP 非 200（含远程错误体）被记录

- 前置：`.set llm-call-error-log on`。
- 步骤：配置一个错误 API Key 或不可用模型名，发起一次会话请求，使远程返回非 200。
- 预期：`log/llm-call-error-<今天>.log` 新增记录，包含：时间、请求目标（模型/端点）、HTTP 状态码、远程返回的错误体原文。

### UC-014 LLM 网络/连接错误（DNS/TLS）被记录

- 步骤：把 base URL 指向不存在的主机（或使用错误证书域名），发起请求。
- 预期：写入日志，记录连接类错误（DNS 解析失败 / 连接被拒 / TLS 握手失败）的原始错误文本。

### UC-015 LLM 请求超时被记录

- 步骤：把超时设为极小值（如 1ms）并发起请求。
- 预期：写入日志，记录超时语义与耗时信息。

### UC-016 LLM 流式响应中断/SSE 异常终止被记录

- 步骤：在流式响应过程中断开网络（或使用会在中途截断响应的代理）。
- 预期：写入日志，记录流式中断位置与已接收内容的收尾状态（有区分于正常结束的标记）。

### UC-017 LLM 响应体解析失败被记录

- 步骤：用返回非 JSON 内容的代理（如返回 `not-json`）伪造响应。
- 预期：写入日志，记录解析错误原因与原始响应片段（足以定位问题）。

### UC-018 llm-call-error-log 关闭时 LLM 错误不写专用文件

- 前置：`llm-call-error-log` 为 `off`。
- 步骤：触发一次 LLM API 错误。
- 预期：
  1. `log/` 下**不产生** `llm-call-error-*.log`；
  2. 既有常规日志（`co-shell-YYYY-MM-DD.log`）行为不受影响；
  3. 前端仍正常提示错误。

### UC-019 日志文件按日切分

- 步骤：连续两天各触发一次同类错误（或修改系统日期模拟跨天）。
- 预期：生成两个独立文件（如 `tool-call-error-2026-09-25.log`、`tool-call-error-2026-09-26.log`），各自仅含当日记录。

### UC-020 Web 设置页保存后立即生效（无需重启）

- 步骤：在 Web 设置页把 `tool-call-error-log` 打开并保存 → 立即触发工具报错。
- 预期：
  1. 保存返回成功且页面刷新后开关显示为「开」；
  2. **无需重启**即开始写入日志；
  3. 关闭并保存后立即停止写入。

### UC-021 两个开关相互独立、互不影响

- 步骤：只开 `tool-call-error-log`（`llm-call-error-log` 关）→ 分别触发工具错误与 LLM 错误；再反向操作一次。
- 预期：
  1. 仅开通的那个产生对应日志文件；
  2. 另一个既不产生文件，也不影响对方写入。

### UC-022 并发多工具报错不丢行、不乱序

- 步骤：在同一轮中并行触发多个工具报错（≥5 条）。
- 预期：
  1. 日志中记录条数 = 实际报错条数（不丢行）；
  2. 每条记录自包含完整（不出现两条记录交错拼接）；
  3. 写入不阻塞主流程（不显著拖慢响应）。

### UC-023 敏感信息保持原样完整记录

- 步骤：在含 `Authorization` 头/API Key 的 LLM 错误场景下查看日志（或在记录结构里确认请求头字段）。
- 预期：按用户决策，敏感字段**保持原样**写入（与现有 `llm-interaction` 日志同一口径），不做脱敏处理；日志文件仅落本地 `log/` 目录。

### UC-024 配置持久化到 config.json（重启后仍生效）

- 步骤：`.set tool-call-error-log on`、`.set llm-call-error-log on` → 退出并重启 `co-shell`。
- 预期：
  1. `config.json` 中两字段均为 `true`；
  2. 重启后设置面板显示「开」，且错误发生时立即写入日志（无需再次设置）。

### UC-025 log 包写入器单测（开关/文件名/格式）

- 覆盖点：
  1. 开关关闭时写入函数为空操作（无文件创建、无字节写入）；
  2. 开关开启时创建 `log/tool-call-error-YYYY-MM-DD.log`、`log/llm-call-error-YYYY-MM-DD.log`（日期取自注入的时钟）；
  3. 工具错误记录包含时间、工具名、原始报文、错误信息四要素；
  4. 同一进程内多次写入按行追加，不覆盖历史内容。

### UC-026 config 默认值与序列化单测

- 覆盖点：
  1. 默认配置两字段均为 `false`；
  2. JSON 反序列化缺失字段时保持 `false`（向后兼容旧配置）；
  3. 序列化字段名为 `tool_call_error_log`、`llm_call_error_log`；
  4. 设置面板构建函数返回的两个设置项 Key/Type/Default 符合预期。
