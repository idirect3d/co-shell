# FIX-539 测试用例：状态条模型弹出列表「默认」项显示优先级最高的模型

## 背景

Web UI 状态条上有两个模型弹出列表（点击状态条的主模型项 / 视觉模型项弹出）：

- 主模型列表：`#modelMenu`（由 `renderModelMenu()` 渲染）
- 视觉模型列表：`#modelVisionMenu`（由 `renderModelVisionMenu()` 渲染）

两个列表底部都有一个「默认」行（DOM：`.model-menu-item.default`，由 `buildModelMenuDefault(target, menu, active)` 构建），点击它发送 `model_unbind` 清除当前模式对该槽位（text / vision）的模型绑定。

**问题（当前实现）**：`buildModelMenuDefault` 用 `modelInfo.textModel` / `modelInfo.visionModel`（状态条显示的「当前模式实际选中的模型名」）去 `modelList` 反查，反查到谁就显示谁；反查不到才退化为纯文字「默认」。

这带来两个不一致：

1. 当模式已绑定模型 A 时，「默认」行显示 A，但它实际代表的是「清除绑定 → 用全局优先级最高的模型」，语义与显示不符。
2. 未绑定时若反查失败（例如名字不匹配），「默认」行退化为纯文字，无法看出会使用哪个模型。

## 需求（用户确认）

1. 主模型列表的「默认」行**始终显示全局优先级最高的模型**（enabled 的模型中 `priority` 最大者），代表用户选择该项后会使用的模型。
2. 视觉模型列表的「默认」行**始终显示全局优先级最高的视觉模型**（`enabled && vision` 中 `priority` 最大者）。
3. 版本 `0.68.1`（FIX，patch+1）；任务号 `FIX-539`；分支 `FIX-539`。

## 实现契约（需确认）

| 项 | 约定 |
|---|---|
| 改动位置 | `web/static/app.js` 的 `buildModelMenuDefault()` 默认模型选取逻辑 |
| 改动内容 | 由「`modelInfo` 名字反查」改为「按 `target` 在 `modelList` 中取 `enabled`（vision 时再加 `vision`）且 `priority` 最大者」 |
| 不变项 | 菜单行 DOM 结构与类名（`.model-menu-item.default` / `.model-logo` / `.model-id` / `.model-default-hint` / `.model-ctx`）、菜单列表顺序、`model_bind` / `model_unbind` 消息、`active` 高亮判定规则（模式无绑定 → 默认行高亮） |
| 非目标 | 不改状态条主模型/视觉模型名称显示（`updateStatus`）、不改后端 `ModelWebJSON` 返回顺序、不改模型管理弹窗 |

## 通用查询片段（后续用例复用）

```js
function defRow(sel) {
  const row = document.querySelector(sel + ' .model-menu-item.default');
  if (!row) return null;
  const q = (s) => { const e = row.querySelector(s); return e ? e.textContent : ''; };
  const img = row.querySelector('.model-logo');
  return {
    id: q('.model-id'),
    hint: q('.model-default-hint'),
    ctx: q('.model-ctx'),
    active: row.classList.contains('active'),
    logo: img ? img.getAttribute('src') : ''
  };
}
```

## UC-0001 主模型默认行 = 优先级最高的已启用模型（核心用例）

**步骤（console）**：

```js
modelList = [
  {id:'m-high', provider:'deepseek', model:'deepseek-v4-flash', enabled:true,  vision:false, priority:100, max_model_len:128000},
  {id:'m-mid',  provider:'kimi',     model:'kimi-k3',           enabled:true,  vision:true,  priority:90,  max_model_len:262144},
  {id:'m-off',  provider:'qwen',     model:'qwen-plus',         enabled:false, vision:false, priority:200, max_model_len:131072}
];
modelInfo = {textModel:'kimi-k3', textMaxLen:262144, visionModel:'kimi-k3', visionMaxLen:262144, modeTextModelID:'', modeVisionModelID:''};
renderModelMenu();
JSON.stringify(defRow('#modelMenu'));
```

**期望**：`id = "m-high"`、`hint = "(默认)"`、`ctx = "125K"`、`logo` 含 `logos/deepseek.svg`、`active = true`。
**关键反例**：不得出现 `m-mid`（虽为当前模式实际使用的模型）或 `m-off`（disallowed：未启用且优先级更高）。

**步骤**：在 UC-0001 数据基础上，把模式绑定到次高优先级模型后重渲染：

```js

  boundActive: document.querySelector('#modelMenu .model-menu-item.active .model-id').textContent});
```
