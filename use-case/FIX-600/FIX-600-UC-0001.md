# FIX-600 UC-0001：向导打开时 agent 交互不再被降级吞掉

> 分支：**FIX-600**　版本：**v0.92.4**　BUILD：**1207**
> 判定口径：任何 `.modal`（尤其模型配置向导 `#modelWizard`、模型管理 `#models`）打开期间，agent 主流程发出的 `ask_user` / interaction 仍**正常渲染为底部交互表单、浮在弹窗之上、用户可见可回答**；向导自身功能不受影响。

## 背景（现象与根因）

- **现象**（用户 2026-10-04 11:31）：模型配置向导打开时，agent 的 `ask_user` 调用没有弹出问题框，用户看不到提问。
- **根因**：`web/static/app.js` 的 `showAsk()` 与 `showInteraction()` 开头都有：
  ```js
  if (wizardActive) { showWizardAsk({ id: msg.id, mode: "line" }); return; }
  ```
  把向导打开期间**所有** interaction 降级为向导弹窗内的**单行输入**并提前返回，跳过了 `kind === "questions" → renderQuestions(it)` 的多问题表单路径。该分支是 FEATURE-422 旧文本流向导的兼容桩（原注释自述 FEATURE-429 结构化向导已不再发出这类消息），却误伤 agent 主流程的真实交互。
- **证据**：日志 `11:29:59.398` 执行 ask_user → `11:30:02.208` 用户在模型向导中提交模型（`wizardActive=true`）→ `11:31:22.743` web-interrupt 中断并丢弃该轮 assistant 消息。
- **附带问题（本次一并处理）**：`.modal` 为 `position:fixed; inset:0; z-index:70` 的全屏遮罩，而 `#askArea`（在 `#bottom` 内）无 z-index → 即使移除降级分支，交互渲染到底部后仍**会被弹窗遮住**。因此同时提升 ask 区层级。

## 变更点

| 位置 | 变更 |
|---|---|
| `web/static/app.js` `showAsk()` | 删除 `if (wizardActive) { showWizardAsk(...); return; }` 降级分支 |
| `web/static/app.js` `showInteraction()` | 同上，删除降级分支（保留 `kind=questions` 正常渲染） |
| `web/static/app.js` `answerAsk()` | 删除 `if (wizardActive) { appendWizardText(...); ... }` 回声分支，统一走正常回声 |
| `web/static/app.js` `renderEvent()`（ui_text repl） | 删除 `if (... && wizardActive) { appendWizardText(...); return; }` 分支 |
| `web/static/app.js` `showWizardAsk()` / `appendWizardText()` | 删除（降级分支移除后已无引用；`wizardActive` 变量仍被 `showModelResult()` 使用，保留） |
| `web/static/style.css` `.ask-area` | 增加 `position: relative; z-index: 90;`，浮在 `.modal`（70）之上 |
