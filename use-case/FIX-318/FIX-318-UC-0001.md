# FIX-318: reorganize_context 触发 OpenAI 400（孤儿 tool 消息）

## 现象
调用 `reorganize_context` 工具成功后，下一次 LLM 调用报错：
`Messages with role 'tool' must be a response to a preceding message with 'tool_calls'`（OpenAI API status 400）。
会话直接中断，无法继续。

co-flow 日志佐证（04:07:04）：reorganizeContextTool 成功后 `messages=3` 的请求立即 400。

## 根因
`reorganizeContextTool`（agent/reorganize_context.go）在**工具执行阶段**清空 `a.messages`（只保留 system），
把当前迭代刚追加的 `assistant(tool_calls)` 消息也删掉了。随后 run_stream.go 才追加 `role:"tool"` 结果消息，
导致消息序列 `[system, tool, user]` 中 tool 消息没有前置 assistant(tool_calls)，违反 OpenAI API 工具消息配对约束。
`run.go`（非流式）同样受影响。

## 修复（agent/reorganize_context.go + agent/run_stream.go + agent/run.go）
1. `reorganizeContextTool` 不再清空 `a.messages`，仅设置 `a.reorganizeContextUsed = true`（+保留 loop detector 重置、summary 写入）
2. `run_stream.go` 工具循环结束后（所有 tool 结果 + summary flush + env 注入完成）检测标志：
   折叠消息为 `[system, user(summary)]`，置 messagePointer=1，重置标志
3. `run.go`（非流式路径）工具循环结束后同样折叠为 `[system, user(summary)]`
4. 折叠后只保留一个 user message（含 summary_prompt），tool/assistant 全部清除

## 用例
1. OpenAI 模式：reorganize 后下次发送 = `[system, user]`，无孤儿 tool
2. XML 模式：同样折叠为 `[system, user]`，行为一致
3. 非流式（Run）：同样折叠为 `[system, user]`
4. 折叠后 messagePointer=1，reorganizeContextUsed 重置
5. 多次 tool 调用 + reorganize：所有 tool 结果先追加完成再折叠
6. 回归：未调用 reorganize 的普通工具调用不受影响（消息正常累积）
