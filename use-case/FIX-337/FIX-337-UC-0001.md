# FIX-337: 修复 search_files 结果匹配数错误显示 0 处

## 背景

LLM 调用 search_files 搜索 coflow.json 时，工具返回 header 显示"找到 0 处匹配"，但下方却正常输出了 3 处匹配内容。该矛盾输出让 LLM 无法信任匹配数。

## 根因

`agent/file_tools.go` 的 `searchFilesTool` 中 `matchCount` 累加时机晚于 `writeHeader()`：

```go
// 在 filepath.Walk 回调中：
writeHeader()                          // ← header 写入时 matchCount 尚未累加本文件
...
writeLine("")                          // 文件内容已写入
matchCount += len(fileMatches)         // ← 累加发生在 header 之后
```

`writeHeader` 闭包捕获 `matchCount` 并立即格式化输出。因此遇到第一个（或唯一）匹配文件时，header 写入时计数仍为 0，而文件内容随后正常显示——形成"0 处匹配 + 有内容"的矛盾。

## 修复方案

将 `matchCount += len(fileMatches)` 从文件内容写入之后**提前到** `writeHeader()` 调用之前；删除原位置（文件末尾）的累加语句。header 因此显示当前已扫描完成的真实匹配总数。

```go
// 修改后（在 walk 回调中）：
matchCount += len(fileMatches)         // ← 提前累加
writeHeader()                          // ← header 显示真实计数
...
writeLine("")
return nil                             // 删除原 matchCount += len(fileMatches)
```

## 用例

| 编号 | 场景 | 输入 | 预期结果（修复后） | 修复前行为 |
|------|------|------|-------------------|-----------|
| UC-0001 | 单文件多匹配 | path=临时目录, regex=`"users"\|"username"\|"name"\|"role"`, file_pattern=coflow.json | header 显示 **找到 4 处**（users/name/role/name 共 4 个匹配行），内容完整显示 | header 显示 0 处 |
| UC-0002 | 多文件匹配总数 | path=临时目录, regex=hello | header 显示 **找到 3 处**（file1.go 2 处 + file3.txt 1 处） | header 显示 0 处 |
| UC-0003 | 单文件精准多匹配 | path=临时目录, regex=`fmt\|package`, file_pattern=file1.go | header 显示 **找到 2 处** | header 显示 0 处 |
| UC-0004 | 单文件单匹配 | path=临时目录, regex="world", file_pattern=file2.go | header 显示 **找到 1 处** | header 显示 0 处 |
| UC-0005 | 无匹配 | path=临时目录, regex="nonexistent_pattern" | 返回"未找到匹配"消息，不出现 header | 无变化（本用例不受影响） |
| UC-0006 | 多文件各多匹配累计 | path=临时目录, regex="fmt"（file1.go/file2.go 各 1 处） | header 显示 **找到 2 处** | header 显示 0 处 |

## 验证方式

1. **单元测试**（`agent/file_tools_test.go`）：
   - 在 `TestSearchFilesTool` 开头调用 `i18n.SetLang("zh")` 固定语言（避免依赖测试机 LANG 环境变量）
   - 现有用例 `"search all files for hello"` 增加断言 `"找到 3 处"`
   - 新增用例 `"search single file with multiple matches"`（regex=`fmt|package`，file_pattern=file1.go）断言 `"找到 2 处"` 与 `"file1.go:1-4:"`
   - 新增用例 `"search specific file for name"` 断言 header 计数非零
   - 新增用例 `"no matches"` 断言返回"未找到"消息（无 header）

2. **运行命令**：`go test ./agent/ -run TestSearchFilesTool -v`

3. **回归**：`go build ./...`、`go test ./agent/`、`go vet ./agent/` 全绿
