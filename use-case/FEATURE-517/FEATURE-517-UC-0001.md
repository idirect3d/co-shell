# FEATURE-517 测试用例 — ask_user 多问题表单焦点切换动效

> 分支：FEATURE-517
> 版本：v0.56.0
> 关联任务：FEATURE-517
> 关联特性：FEATURE-512（ask_user 多问题表单 `qs-card`：Qn 徽标 / 选项键帽 / 提示行 / 键盘导航）、FEATURE-388（交互卡片上下布局）

## 背景

Web UI 的 `ask_user` 多问题表单（`web/static/app.js` → `renderQuestions()` / `setActive()`）在**题目间切换焦点**时，目前表现为「瞬时跳变」：

| 元素 | 现有实现 | 问题 |
|------|----------|------|
| 滚动定位 | `card.scrollIntoView({ block: "start" })` | 无 `behavior:"smooth"`，画面瞬间跳转，容易眩晕 |
| Qn 徽标（`.qs-index`） | 直接 `classList.toggle("hot")` | CSS 无 `transition`，新旧徽标同时瞬间切换 |
| 选项键帽（`.qs-hotkey`） | 直接 `classList.toggle("hidden")` | `display:none` 切换，无淡出淡入 |
| 提示行（`.qs-hint`） | 直接 `classList.toggle("hidden")` | 同上 |
| 焦点卡片（`.qs-card.active`） | JS 已 toggle `.active` | CSS 中**无任何 `.qs-card.active` 样式**，焦点卡片无视觉强调 |

用户（需求方）确认的验收诉求：

1. 完成一道题的选择、焦点移动到下一道题，或按 `+` 焦点回到上一道题时，要有**动态移动的效果**，让用户明显看到焦点移动了（包括 Q1 焦点转移到 Q2 标签这种）。
2. 焦点**消失和显现**要有**淡出 / 淡入**效果。
3. 页面**不要一下就转过去**，要有**动态的滚动效果**。

用户确认的范围与参数：

- 动效强度：**轻量**——仅「淡入淡出 + 平滑滚动」，不额外加滑动指示条、脉冲等强提示。
- 动效时长：**标准，约 280–350ms**（首版 300ms，经用户实测反馈“太快、来不及看清”，同会话内延长 50% 至 **450ms**）。
- 鼠标点击选项行：**保持现状**（仅勾选，不自动前进；仅数字键 / 键帽选择后前进）。
- 版本归属：**v0.56.0**（FEATURE 分支，minor +1）。

## 验收标准

- 焦点在题目间切换时（Enter / 键帽前进、`+` 返回），旧题目的 Qn 徽标、选项键帽、提示行**淡出**，新题目的对应元素**淡入**，肉眼可辨，不是瞬间切换。
- 焦点题目的滚动为**平滑滚动动画**，不是瞬时跳转；目标题目停在可视区顶部（沿用既有 `block:"start"` 定位语义）。
- 动效时长约 **450ms**（包含淡入淡出与滚动，两者同节奏）；动画不改变布局，不产生抖动、横向位移或徽标宽度跳变。
- 原有键盘交互**不回归**：Enter 前进 / 末题提交、`+` 返回、数字键 1-9 选择、单选题选择后自动前进、长按数字键打开该选项备注、空格打开本题备注、`-` 取消表单。
- 鼠标点击选项行**保持不前进**（仅勾选）。
- 表单初次渲染（`setActive(0)`）时不应出现突兀的整片动画。
- 快速连续切换（连按 Enter）不出现动画堆积、卡顿或状态错乱。
- `node --check web/static/app.js` 通过；`go build ./... && go vet ./...` 通过。

## 运行时用例

### UC-0001 焦点前进 Q1 → Q2：徽标焦点转移肉眼可辨（核心）

**前置条件**
- `co-shell --serve --port <port>` 启动，浏览器打开 Web UI。
- 触发一次包含 **≥2 个带选项的问题** 的 `ask_user` 调用，表单已渲染（Q1 为焦点题）。

**步骤**
1. 记录切换前状态：Q1 徽标为实心高亮（`.qs-index.hot`）、Q2 徽标为描边样式。
2. 按 `Enter` 前进（或在 Q1 用数字键键帽选择单选选项触发前进）。
3. 观察 Q1、Q2 两个 Qn 徽标在切换瞬间的变化过程（可放慢 / 逐帧截图）。

**预期**
- Q1 徽标由「实心高亮」**渐变**回「描边」样式，Q2 徽标由「描边」**渐变**为「实心高亮」，两者在过渡期间**同时处于中间态**（不会同一帧完成切换）。
- 过渡可被肉眼捕捉（约 300ms 量级的渐变），不是瞬时跳变。
- 过渡结束后终态与旧实现的静态样式完全一致（不改变配色与尺寸）。

### UC-0002 焦点前进：滚动为平滑动画而非瞬移（核心）

**步骤**
1. 构造一个总高度超出消息区可视范围的表单（如 6 题，每题含 3–4 个选项）。
2. 保持 Q1 为焦点，记录消息区（`streamB`）的 `scrollTop`。
3. 按 `Enter` 前进到 Q2。
4. 在切换后立即（0ms）、约 150ms、约 400ms 分别采样 `scrollTop`。

**预期**
- `scrollTop` 在 ~150ms 时处于「起点与终点之间」的中间值，到 ~400ms 时稳定在终点值 —— 证明存在**过渡过程**，而非 0ms 直接跳到终点。
- Q1 → Q2 的位移方向与题目顺序一致（向下）。
- 滚动结束后 Q2 卡片停在消息区可视区顶部附近（沿用 `block:"start"` 定位）。

### UC-0003 按 `+` 返回上一题：焦点回移动效与平滑滚动（核心）

**步骤**
1. 先前进到 Q3（或表单中较靠后的题目）。
2. 按 `+` 返回 Q2。
3. 观察徽标焦点转移与 `scrollTop` 变化。

**预期**
- Q3 徽标淡出高亮、Q2 徽标淡入高亮，方向与 UC-0001 相反但同样可辨。
- 滚动为**向上**的平滑动画（不是瞬移），同样经过中间值。
- Q2 卡片停在可视区顶部附近。

### UC-0004 选项键帽 1-9 随焦点淡出 / 淡入

**步骤**
1. 在 Q1（有 3 个以上选项）观察选项行左侧的数字键帽（`.qs-hotkey`）。
2. 按 `Enter` 前进到 Q2。

**预期**
- Q1 的键帽**淡出**（不是 `display:none` 一帧消失），Q2 的键帽**淡入**。
- 淡入完毕后，只有焦点题目显示键帽，非焦点题目完全不可见（终态与旧实现一致）。
- 淡出过程中键帽仍占据原有位置至完全隐去，不引起选项行文字的横向抖动。

### UC-0005 提示行随焦点淡出 / 淡入

**步骤**
1. 在 Q1 观察其提示行（`.qs-hint`，含「Enter 下一题 · + 上一题 · 空格 备注 · - 取消」）。
2. 按 `Enter` 前进到 Q2。

**预期**
- Q1 提示行**淡出**、Q2 提示行**淡入**，过程中两者可同时可见（交叉过渡）。
- 淡入完成后仅焦点题目显示提示行，终态与旧实现一致。
- 提示行的淡出 / 淡入不引起下方内容位移（占位稳定）。

### UC-0006 动效时长落在标准区间（约 450ms）

**前置条件**
- 浏览器开发者工具可用（可读取 `getComputedStyle`）。

**步骤**
1. 在 DOM 中检查 `.qs-index`、`.qs-hotkey`、`.qs-hint` 的 `transition-duration`。
2. 实际按 `Enter` 切换一次，用 Performance/动画面板或逐帧截图测量过渡时长。

**预期**
- `transition-duration` 解析值落在 **0.43s–0.47s** 区间内（约 450ms）。
- 实测过渡时长与声明值一致，误差在 ±50ms 内；滚动走完所需时间与淡入淡出相当（同节奏）。
- 三个元素的时长一致（同一节奏），不出现「徽标快、键帽慢」的割裂感。

### UC-0007 单选题数字键选择后自动前进的动效链路（核心）

**步骤**
1. 焦点在 Q1（单选题，`.qs-tag` 显示「单选」）。
2. 按 `1`（或点击 Q1 的键帽「1」）选择第一个选项 —— 会触发「选择 + 自动前进」。

**预期**
- 选项被勾选的状态变化与焦点移动**依次**发生：先看到 Q1 选项变为选中态，随后 Q1 → Q2 的焦点过渡动画开始。
- 不出现「选择与跳题同一帧完成、用户来不及看清选中了什么」的情况。
- 平滑滚动与 UC-0002 一致。

### UC-0008 多选题（multi）不自动前进：焦点保持、无多余动效

**步骤**
1. 焦点在 Q1（多选题，`.qs-tag` 显示「多选」）。
2. 按 `1`、`2` 选择两个选项。

**预期**
- 焦点**保持在 Q1**，不发生题目切换动画与滚动。
- 选项勾选状态正常切换（无明显延迟或阻塞）。
- 不出现「预先滚动到下一题又回弹」的异常动效。

### UC-0009 首题按 `+` 不越界（边界）

**步骤**
1. 焦点在 Q1，按 `+`。

**预期**
- 焦点仍停留在 Q1（`Math.max(0, …)` 夹紧），不出现任何跳题动画。
- 不出现滚动抖动、徽标闪烁。

### UC-0010 末题回车 = 提交，不触发题目切换动效（边界）

**步骤**
1. 焦点在最后一题，按 `Enter`（或点击「确定」按钮）。

**预期**
- 触发提交（答案回显为一条 `YOU · 回答` 消息），**不**出现题目切换动画。
- 若存在必填题未答，则焦点跳到第一个未答题目（`setActive(missing[0])`）并**带平滑滚动与淡入动效**，同时该题卡片高亮（`.qs-missing`）。

### UC-0011 表单初次渲染不出现突兀动画（边界）

**步骤**
1. 触发 `ask_user` 多问题表单渲染（表单从无到有出现）。
2. 观察 Q1 获得焦点、其键帽 / 提示行显示的过程。

**预期**
- 表单首屏渲染时，Q1 的键帽与提示行**直接以终态呈现**或为极短淡入，不出现「先显示 Q2 再跳回 Q1」的动画。
- 不出现整片卡片依次淡入的连环动画（避免页面嘈杂）。

### UC-0012 键盘交互回归：Enter / `+` / 数字 / 空格 / `-` / 长按（回归）

**步骤**
1. 依次执行下列按键操作（每次操作后确认状态）：
   - `Enter`：前进一题；在末题提交。
   - `+`：返回上一题。
   - 数字 `1`–`9`：选择对应选项（单选后前进）。
   - **长按**数字键 ≥450ms：打开该选项的备注输入框（`input.qs-note-input`）并获得焦点。
   - `空格`：打开当前题目的备注输入框（`.qs-free-note` 或 `.qs-free`）并获得焦点。
   - `-`：取消整个表单（等同底部「再想想，先退出」按钮）。
2. 在备注输入框内输入文字后按 `Enter`。

**预期**
- 所有按键行为与 FEATURE-512 现状**完全一致**，无功能丢失或错位。
- 备注输入框内输入时，题目导航按键被正确抑制（`e.stopPropagation()` 生效），不会误触前进 / 取消。
- 备注输入框按 `Enter` 只失焦（`blur`），不触发跳题。

### UC-0013 鼠标点击选项行仍仅勾选、不前进（回归）

**步骤**
1. 焦点在 Q1（单选），用鼠标点击某选项**行**（`.qs-option`，非左侧数字键帽）。
2. 再用鼠标点击 Q1 左侧的数字**键帽**（`.qs-hotkey`）。

**预期**
- 点击选项行：仅切换选中态（`.on`），焦点**仍停留在 Q1**，不产生跳题动画与滚动。
- 点击数字键帽：选中该选项并**自动前进到 Q2**（带本次实现的动效）。
- 两者行为差异符合用户确认的「鼠标点选保持现状」要求。

### UC-0014 备注输入框开启与焦点切换共存（回归）

**步骤**
1. 在 Q1 长按数字键打开某选项的备注框，输入备注。
2. 按 `Enter` 使备注框失焦，再按 `Enter` 前进到 Q2。

**预期**
- 备注框打开时布局正常展开（`.qs-note-input` 由 `hidden` 变可见），不因动效引入而闪烁。
- 前进到 Q2 后备注内容仍保存在对应选项上（提交后答案中带 note）。
- 焦点切换动画不影响输入框内容与状态。

### UC-0015 快速连续切换焦点无动画堆积（边界）

**步骤**
1. 表单含 ≥5 题。
2. 连续快速按 `Enter` 5 次（间隔 ≈50ms），从 Q1 一路前进到 Q5。

**预期**
- 最终焦点稳定在 Q5，徽标 / 键帽 / 提示行终态正确（无多个题目同时高亮）。
- 不出现动画堆积、闪烁、卡顿或滚动「来回拉扯」。
- 若中途发生滚动打断，最终仍会平滑停在 Q5 的可视位置。

### UC-0016 长表单（≥6 题）中平滑滚动全程可见（核心）

**步骤**
1. 构造 6 题以上的表单，逐题前进，观察 Q1 → Q6 的滚动过程（可录屏）。

**预期**
- 每一次前进都有肉眼可见的平滑滚动过程（不是瞬移），且相邻两题的滚动时长一致。
- 滚动结束后目标题目停在消息区顶部附近，题目标题（含 Qn 徽标）完整可见。
- 到达最后一题后提交按钮可见（`.qs-submit` 不再隐藏）。

### UC-0017 切换过程中动画不引起布局抖动 / 徽标宽度跳变（回归）

**步骤**
1. 在焦点切换的整个过渡期间（约 300ms），观察卡片内各元素的几何位置。
2. 用 `getBoundingClientRect()` 在过渡前后对比 `.qs-head`、`.qs-option` 的位置。

**预期**
- 过渡期间无横向位移、无文字重排、无滚动条横向出现。
- Qn 徽标切换前后宽度与位置不变（`.qs-index` 有 `min-width`，不因 `hot` 状态改变尺寸）。
- 页面上其它消息块的位置不受影响（滚动仅发生在消息区容器内）。

### UC-0018 `prefers-reduced-motion: reduce` 下动效降级（可访问性，待用户确认是否纳入）
**步骤**
1. 在操作系统 / 浏览器中开启「减少动态效果」（Chrome DevTools → Rendering → Emulate CSS `prefers-reduced-motion: reduce`）。
2. 切换题目焦点。

**预期**
- 焦点切换的显隐与滚动以**极短或瞬时**方式完成，不产生长时动画（避免对动效敏感用户造成不适）。
- 功能不受影响：焦点、选中态、滚动定位终态与正常模式一致。

> 说明：本用例为可访问性增强项。**用户已在需求确认阶段裁定：不纳入本次范围**（严格按需求，仅做淡入淡出 + 平滑滚动）。本用例保留作后续可选增强的参考，本次不作为验收项。

## 验证方式说明

- 运行时用例以 **DOM 量测 + 逐帧截图 + 录屏** 三种手段交叉验证：DOM 量测用于断言 `transition-duration`、`scrollTop` 中间值、类名终态；截图 / 录屏用于确认「肉眼可辨」的动效存在。
- 参考 FEATURE-516 经验：调试浏览器 CDP 截图可能超时，故**关键结论优先以 DOM 量化测量为准**（如在不同时刻采样 `scrollTop`、读取 `getComputedStyle(...).transitionDuration`）。
- 验证实例使用独立端口与 `workdir`，不干扰 28256 主实例。
